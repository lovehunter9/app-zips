# Radicale 简易使用文档

> 适用版本: Radicale v3.7.3 / Olares chart 1.0.8 及以上

Radicale 是一个轻量级、自托管的 **CalDAV / CardDAV 服务器**——也就是你自己的"日历 + 通讯录"中枢，可以让 iPhone、Mac、Android、Outlook、Thunderbird 等几乎所有支持 CalDAV/CardDAV 标准的应用，连到同一份日历和通讯录上做多端同步。

本文介绍 Radicale 在 Olares 上的初次配置、客户端接入方式，以及在导入历史数据时常遇到的一个浏览器超时提示的真实含义与处理建议。

## 一、本次升级要点

Radicale 从 v3.1.8 一次性跳到 v3.7.3，跨越了 v3.2 ~ v3.6 多个中间版本。对终端用户来说，**最直观的变化是 Web 界面**。其他偏内部的安全与性能更新对你是透明的，照常使用即可。

### 1.1 全新 Web 界面

整个 `/.web` 控制台被重写：

- 列表、按钮、表单的视觉重新设计，**移动端可用性明显改善**
- 创建 / 重命名 collection（日历或通讯录）时的字段校验更友好
- 顶部新增"下载完整 collection"按钮（一键导出 `.ics`）

### 1.2 协议与兼容性

- 支持 CalDAV 调度（Scheduling，RFC 6638）——发送和接收会议邀请
- 修复了若干与 iOS / macOS / Outlook 客户端的边角兼容问题
- 部分客户端在 PROPFIND 大量 collection 时的响应速度有所提升

### 1.3 安全

- 修复了多个 v3.1.x 时期的安全公告（CVE）
- 改进了对认证错误和异常请求的处理

## 二、快速开始

### 2.1 打开 Radicale Web 界面

在 Olares 桌面或应用列表里点开 Radicale，浏览器会进入它的 Web 控制台。地址形如：

```
https://<你的-radicale-入口域名>/.web
```

> Olares 已经在外部入口处为你做了访问控制——只有用你自己的 Olares 账号登录后，才能访问到这个页面。

### 2.2 关于"用户名"

打开 Web 界面会看到一个登录框，让你填"用户名"和"密码"。这里**不是 Olares 账号**，也不是另一套独立账户——它只是用来给你的 collection 起一个"命名空间前缀"。

- **用户名**：任意填一段你自己记得住的字符串即可，例如 `me`、`personal`、`family`。后面所有日历都会建在这个名字下面（路径形如 `/me/work-calendar/`）。
- **密码**：可以随便填，**不会被校验**（外部访问的鉴权已由 Olares 完成）。

建议：第一次使用时简单地填一个固定的用户名（例如自己名字的拼音首字母），之后所有客户端、所有设备都用同一个名字，数据就会聚合在一起。

### 2.3 创建你的第一个日历

登录后页面中央会显示一个"New collection"按钮，点击并填写：

| 字段 | 说明 | 示例 |
|---|---|---|
| Title | 日历/通讯录显示名称 | `Work` |
| Type | 集合类型 | Calendar / Address book / Task list / Webcal |
| Color | 显示颜色 | 任选 |
| Description | 备注（可选） | |

点 Create 即建立完成。可以多次点击创建多个 collection（比如 `Work` / `Personal` / `Family`）。

### 2.4 创建通讯录

操作完全相同，只是 Type 选 **Address book** 即可。通讯录与日历可以在同一个用户名下共存。

## 三、客户端接入（多设备同步）

CalDAV / CardDAV 是一套标准协议，几乎所有日历应用都直接支持。下面列出最常见的几类客户端的配置入口。

### 3.1 iOS / iPadOS / macOS（系统原生）

iPhone 与 Mac 自带的"日历"和"通讯录"应用原生支持 CalDAV / CardDAV，不需要装任何插件。

**添加 CalDAV 账户**：

1. iOS: 设置 → 日历 → 账户 → 添加账户 → 其他 → **添加 CalDAV 账户**
   macOS: 系统设置 → 互联网账户 → 添加其他账户 → **CalDAV 账户**
2. 选择 Manual / 手动，并填写：

| 字段 | 内容 |
|---|---|
| 服务器 | `<你的-radicale-入口域名>`（仅域名，不要带 `https://` 前缀，也不带路径） |
| 用户名 | 你在 2.2 选定的那个用户名 |
| 密码 | 随便填一段非空字符串 |
| 描述 | 自定义，例如 `Radicale` |

3. 点完成，系统会自动发现该用户名下的所有日历。
4. 通讯录的添加流程相同：账户 → 添加 → 其他 → **添加 CardDAV 账户**，字段一样。

### 3.2 Android（DAVx⁵）

Android 系统不自带 CalDAV/CardDAV 支持，需要装 **DAVx⁵**（F-Droid 或 Play Store 均可）。

1. 打开 DAVx⁵ → 右下角 `+` → **使用 URL 和用户名登录**
2. 填写：
   - Base URL: `https://<你的-radicale-入口域名>/<用户名>/`
   - 用户名: 同 2.2
   - 密码: 随便填非空
3. 完成后 DAVx⁵ 会自动发现并列出该用户名下的所有日历与通讯录，按需勾选要同步的项即可。
4. Android 系统的日历 / 通讯录会立即接管这些数据，使用方式与本地账户完全一样。

### 3.3 Thunderbird

Thunderbird 内置 CalDAV / CardDAV 支持，无需插件。

- 添加日历：日历视图 → 文件 → 新建日历 → **网络** → CalDAV，Location 填 `https://<你的-radicale-入口域名>/<用户名>/<日历名>/`
- 添加通讯录：通讯录窗口 → 文件 → 新建 → **CardDAV 通讯录**

Thunderbird 会要求填用户名/密码，规则同 2.2。

### 3.4 其他客户端通用配置

任何标准 CalDAV / CardDAV 客户端都能接入。通用字段：

| 字段 | 取值 |
|---|---|
| 服务器 / Base URL | `https://<你的-radicale-入口域名>/<用户名>/` |
| 用户名 | 你在 2.2 选定的字符串 |
| 密码 | 任意非空字符串 |

## 四、导入与导出

### 4.1 导入已有日历或通讯录

如果你之前在别处（Google Calendar / iCloud / Outlook / Nextcloud / ...）已有数据，几乎所有平台都支持导出为 `.ics`（日历）或 `.vcf`（通讯录）文件。把这些文件导入 Radicale 的方式：

1. 在 Radicale Web 界面打开目标 collection
2. 点 **Upload** 按钮，选择本地的 `.ics` 或 `.vcf` 文件
3. 等待页面提示"上传成功"

> **如果文件较大（几千条以上日程 / 几 MB 起），浏览器可能会显示超时——这是预期内的，请阅读 5.1**。

### 4.2 导出整个 collection

打开 collection → 点 **Download** 按钮，浏览器会下载一份完整的 `.ics` / `.vcf`，可作为备份或迁移到其他平台。

### 4.3 增量同步无需"导入"

一旦客户端（手机 / Thunderbird / DAVx⁵）连接成功，日常的新增 / 修改 / 删除日程会自动同步，不需要任何手动导入操作。**4.1 的批量导入只适用于"首次迁移历史数据"或"从其他平台一次性搬家"的场景**。

## 五、常见问题与解决建议

### 5.1 ⚠️ 一次性导入大文件时，浏览器显示 504 / Gateway Timeout / 上传失败

**这是本文档需要重点说明的一个现象**——上传规模较大的 `.ics` 文件时，**浏览器在大约 5 分钟时会显示 504 Gateway Timeout 或上传失败**的红色提示。

**真实情况**：

> Radicale 在处理批量导入时，需要把每一条日程作为单独文件写入磁盘。这个过程的耗时大致与日程条数成正比，**一旦超出浏览器连接的有效时长，页面就会显示 504**——但 **Radicale 后台仍在继续写盘**，并不会因为浏览器收到 504 就中断。

**推荐做法**：

1. **不要立刻点重试**——重试会触发重复处理，反而拖慢实际写盘速度。
2. **等 3 ~ 10 分钟后刷新页面**（具体时长取决于文件大小）：
   - 多数情况下你会看到 collection 已经成功创建、日程已全部导入。
   - 此时一切就绪，可以继续添加客户端或正常使用。
3. **如果等够时长后刷新仍未看到数据**，再判断是否需要重试。重试前**先在 Web UI 删除"上次没传完"的 collection**，避免数据残留。

**单次导入规模的实用建议**（基于实测）：

| 单次规模 | 文件大小约 | 大致耗时 | 体验 |
|---|---|---|---|
| ≤ 5,000 条日程 | ≤ 2 MB | ~1 分钟 | 顺畅完成 |
| 5,000 ~ 15,000 条 | 2 ~ 6 MB | 1 ~ 3 分钟 | 顺畅完成 |
| 15,000 ~ 20,000 条 | 6 ~ 8 MB | 3 ~ 5 分钟 | 通常仍可完成，临近浏览器超时阈值 |
| 20,000 ~ 25,000 条 | 8 ~ 10 MB | 4 ~ 6 分钟 | **边缘区**——浏览器可能显示 504，但**后台多半已成功**，等几分钟后刷新查看即可 |
| > 25,000 条 | > 10 MB | 6 分钟以上 | 大概率显示 504。请把源文件拆成多个再分批上传，避免重复处理浪费时间 |

> 上面这张表只对应"Web UI 一次性大批量导入"这一特殊场景。**通过 iOS / Android / Thunderbird / Outlook 等客户端做日常增量同步不受此限制**——它们每次只新增 / 修改少量日程，永远在毫秒级完成。如果你愿意，把数据先在客户端里加好、让客户端自己同步上来，是更稳妥的方式。

### 5.2 Web 界面顶栏的 `list` / `info` 链接显示 404

这两个链接属于 Radicale 的可选"共享功能"模块，当前部署默认未启用，因此点击会显示 404。不影响 CalDAV / CardDAV 的任何核心功能，可以忽略。

### 5.3 客户端能登录但同步缓慢、或某条日程未同步

最常见的原因是 **客户端缓存**。可以尝试：

1. 在客户端的账户设置里手动点一次 "刷新" / "立即同步"
2. iOS / macOS：设置 → 日历 → 账户 → 选中 Radicale → 关闭日历开关 → 等几秒 → 重新打开
3. DAVx⁵：进入账户 → 右上角菜单 → "完全重新同步"
4. Thunderbird：右键日历 → 同步

如果某条日程在 Web 界面看得到、但客户端始终看不到，可能是该条日程的格式被客户端额外做了筛选（如时区、循环规则）；可以在 Web 界面打开该日程的 `.ics` 文本检查后再做相应调整。

### 5.4 想区分多个"账户"或"家庭成员"怎么办

Radicale 的"用户名"就是天然的命名空间。你可以：

- **个人多空间**：自己用 `personal` / `work` / `study` 三个用户名各登录一次，分别建对应的 collection
- **家庭共用**：每位家庭成员在 Radicale Web 界面用不同的用户名登录、建自己的 collection；想共享某本日历时，把日历的 URL（`https://<域名>/<用户名>/<日历名>/`）发给对方，对方在自己的客户端里以"只读"或"读写"方式添加即可

> 当前部署没有为不同用户名做严格隔离——任何登录到 Radicale Web 界面的人，理论上都能访问到其他用户名下的 collection。所以**家庭共用 / 团队共享场景下请预先约定彼此的用户名**，不要把同一台 Olares 当作多租户隔离使用。

### 5.5 备份建议

Radicale 的全部数据都存放在 Olares 应用数据目录里，整机 Olares 备份就会自动覆盖到。如果需要"导出一份纯 `.ics` / `.vcf`"作为额外保险，最简单的办法是：

1. 在 Web 界面打开每一本 collection
2. 点顶部 **Download** 把 `.ics` / `.vcf` 下载到本地
3. 定期重复以上步骤即可（也可以做成脚本调 CalDAV `GET` 接口批量拉取）

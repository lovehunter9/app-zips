## 一、问题根因（为什么之前 `bifrost` 每次都重新下载 11MB）
`@maximhq/bifrost-cli` 这个 npm 包**只是个 bootstrapper**：运行 `bifrost` 时它把真正的
二进制下载到 `$HOME/.bifrost/bin/bifrost`。而运行时 **`HOME` 指向 appData 卷**
（chart 里 `cli` sidecar 设了 `HOME=/app/data/.cli-home`），卷会**遮蔽镜像里的同名目录**，
所以即便我们在镜像构建期把东西放进 root 的 home，运行时也看不到 → 每次都重新下载。

## 二、本次改动（文件级）
### 2.1 `bifrost-cli-docker/Dockerfile`
- **构建期触发一次下载，再把真二进制烤到系统 PATH**：
  ```
  RUN npm install -g @maximhq/bifrost-cli@${BIFROST_CLI_VERSION}
  RUN bifrost --version >/dev/null 2>&1 || true; \
      test -f "$HOME/.bifrost/bin/bifrost" \
        && install -m 0755 "$HOME/.bifrost/bin/bifrost" /usr/local/bin/bifrost \
        && echo "baked real bifrost binary -> $(command -v bifrost)"
  ```
  - 构建期 `HOME=/root`，下载落到 `/root/.bifrost/bin/bifrost`，`install` 覆盖掉
    `/usr/local/bin/bifrost` 那个 npm shim → 运行时 PATH 命中的就是**真二进制**，
    不再触发 bootstrapper，**零下载**，且不被 appData 卷遮蔽。
  - **故意做成「失败即让构建失败」**：若下载/拷贝没成（`test -f` 不成立），整条
    `&&` 链失败、CI 红。宁可构建期红，也不发一个运行时还会下载的「假 test2」。
- **新增 qwen**（binary: `qwen`，包 `@qwen-code/qwen-code`），**单独一层 + `|| echo`
  非致命**，避免它改名/挂掉时连累已知良好的那 4 个 agent。
- 4 个核心 agent（claude/codex/gemini/opencode）仍是已验证可用的那一层，未动。

## 二、根因 + 修复（/opt/venv，不是 /pydeps）

- `beclab/nvidia-nemo:26.02` 把 `nemo_toolkit` 装在**自带的 uv venv `/opt/venv`**（python 3.12），
  与基础镜像的**系统 python**（`/usr/local/.../dist-packages`，torch 在这）是两套。共享
  `$pydepsPrelude` 用系统 python + `--system-site-packages` 建 `/pydeps/venv` → 看得见 torch，
  **永远看不见 nemo**（不同 venv，不在系统 site-packages）。参考 NeMo 26.02 Dockerfile
  (`UV_PROJECT_ENVIRONMENT=/opt/venv`) 确认。
- 修复（`engine.yaml` diar_stream cmd）：直接跑 `/opt/venv/bin/python`；
  `export PYTHONPATH=/pydeps/diarstream-site`（**覆盖**掉 prelude 的 3.12 路径）；
  fastapi/uvicorn/websockets 用 pip/uv `--target` 装到该持久目录、且仅在 import 探测缺失时装
  （实际 /opt/venv 已自带 → 没装）；sentinel `/pydeps/.diar_stream.ok` → 重启不重装。
- `helm template` 渲染正常、既有 8 模式零回归；重打 `audiolabxv3-1.0.0.tgz`。

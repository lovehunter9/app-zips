## 一、改动思路（先读代码再动手）

梳理 gateway 现有 audio 数据面后确认：
- `audioPassthroughHandler`（multipart）已用 `c.Data(status, ct, body)` 回写，**保留任意响应 Content-Type** → `embed`（音频入/JSON 出）和 `enhance`（音频入/`audio/wav` 出）**直接复用**，只差 handler+route+mode+spend 常量。
- `translate` 是 **JSON 入/JSON 出**，且上游路径 `/v1/translate` 不在 `/audio/` 下 → 需新增一个 JSON 透传 adapter 方法 + 专用 handler。

**无需新迁移**：`provider_models.mode` 的 CHECK 在 000019 已含 `translate/embed/enhance`；`spend_logs.mode` 只有"非空"约束、无 enum。

## 二、代码改动（repo `~/beclab/llm-gateway`，分支 `feat/market-real-llm-gateway-supported`，commit `cb6c51a`，未 push）

- **adapter 接口**：`ChatAdapter` 新增 `TextPassthrough(ctx, op, rawBody)`。openai_compatible 实现为把 JSON POST 到 `<base_url>/<op>`（复用已有私有 `do`）；anthropic / azure_openai / gemini 返回 `ErrAudioUnsupported`；两个测试桩（registry_test 的 fakeAdapter、v1 的 recordingAdapter/stubAdapter）补桩。
- **embed / enhance handler**（`audio.go`）：`AudioEmbeddingsHandler`（op=embeddings, mode=embed）、`AudioEnhanceHandler`（op=enhance, mode=enhance），均复用 `audioPassthroughHandler`。
- **translate handler**（新增 `translate.go`）：`TranslateHandler` 仿 `EmbeddingsHandler` 的 dispatch 流程（从 JSON body 取 `model` → `DispatchForMode(mode=translate)` → mode 校验 → quota → `TextPassthrough(op="translate")` → `c.Data` 回写 → spend）。新增错误码 `CodeTranslateModeMismatch`。
- **spend 常量**：`ModeTranslate/ModeEmbed/ModeEnhance`。
- **路由**（`router.go`）：`POST /v1/audio/embeddings`、`POST /v1/audio/enhance`、`POST /v1/translate`。

`go build` / `go vet` / `go test`（api/v1、dataplane/*、spend、defaults）全绿。改动 13 文件 +233 行。

## 五、经验

- gateway 的"audio passthrough"对**音频出**（enhance→audio/wav）天然支持，因为 `doRaw` 保留上游 Content-Type、handler 用 `c.Data` 原样回写——无需为二进制响应做特殊处理。
- 给接口加方法要同步所有实现者（4 个正式 adapter + 3 个测试桩），`go build ./...` 会一次性逼出来。
- 切 live 镜像号这种小事交给用户手动（ControlHub），比纠结 olares-cli 怎么 set-image 更快。
- 沙箱外目录（`~/beclab/llm-gateway` 不在 workspace）的 `git commit` 偶发 `index.lock: Operation not permitted`，重试即可。

## 一、audiolabxv3 依赖持久化（/pydeps venv）——已完成并实测

### 背景
用户提出：初装下模型可接受，但那个只有 `latest` 的基座镜像不放心；**至少保证「重启不重装」**
（卸载重装重下可接受，重启不能重装）。原先所有 wrapper/cmd 的 pip 装到**临时容器 FS**，重启即丢 →
重装 + 联网（网络差的用户会卡死，qwen-asr 模式每次重启 ~2.5min）。

### 方案（`audiolabxv3/templates/engine.yaml`，覆盖全部模式，不换镜像、不改 llm-init）
- 新增 hostPath 卷 `pydeps` → `{{ .Values.userspace.appData }}/pydeps`，挂载 `/pydeps`（per-instance，重启持久）。
- 新增 `$pydepsPrelude`（prepend 到**每个** engine cmd）：首启 `python3 -m venv --system-site-packages /pydeps/venv`
  （继承镜像自带 torch/vLLM/CUDA，只补装缺的包，不重下几个 G），把 venv 的 bin 放进 PATH。
  这样**原有 cmd 一字不改就透明用上 venv**：`python3`/`pip`→venv（安装落盘持久；wrapper 的 `try import`
  重启后命中 venv、不再 pip）；`vllm`（系统 console script，venv bin 里没有）仍跑镜像那份，音频扩展经 PYTHONPATH 可见。
  venv 建不出来时**回退**临时安装（不比现状差）。
- 5 个在 cmd 里直接 pip 的模式（stt / stt_stream / align / qwen3-asr / faster-whisper）加 `/pydeps/.<mode>.ok`
  **sentinel**：重启直接跳过 pip，**连 PyPI 都不碰**。
- 重打 `audiolabxv3-1.0.0.tgz`（30.4KB）。helm template 对 stt_stream/whisper-stt/qwen3-asr/vad/align 全渲染通过。

### 实测（RULE 1 全流程）
- `market uninstall audiolabxv30f9f88` → `market delete audiolabxv3` → `market upload` 新 tgz →
  `market clone ... stt_stream`（**复用同一 hash `audiolabxv30f9f88`，公网 URL 不变**，用户已确认
  `https://d123f7e6.olarestest003.olares.com/`）。
- 首装：pip 正常装进 `/pydeps` venv（下模型 + 装包）。
- `cluster pod restart` 后新 pod 1/1，**日志零 pip 活动**（无 Collecting/Downloading/Successfully installed，
  无 "creating persistent venv"）；重启后首条 `[stream]` 直接是 `constructing ...LLM` → sentinel 命中、venv 复用。

## 三、⚠️ BUG（今天卡在这）：前端 nginx `/v1/` 缺 WS upgrade 头

### 现象
经网关 WS 握手 **HTTP 400 "Bad Request"**（`server: envoy`，`x-envoy-upstream-service-time: 9` 即已到网关 app）。

### 根因
网关**前端 nginx** 的 `location /v1/`（`deploy/frontend.nginx.conf.template`）**没有**
`proxy_set_header Upgrade $http_upgrade;` / `Connection "upgrade";`（而 `/console/api/` 有，所以那边 SSE/WS 正常）。
nginx 吞掉 upgrade 头 → 后端 gorilla 握手失败回 400。**不是后端逻辑问题，后端 test7 路由是对的。**

### 已做的修复
- 已在 `deploy/frontend.nginx.conf.template` 的 `/v1/` 块补上 `Upgrade`/`Connection` 两行（照 `/console/api/` 的写法；对非 WS 请求无害，`$http_upgrade` 为空即不升级）。
- 这配置**烤在前端镜像里**（envsubst 模板 → `/etc/nginx/conf.d/default.conf`），所以**必须重建前端镜像**才生效。
- chart `llmgatewayv3/templates/llmgateway.yaml` 前端镜像已改为
  `docker.io/lovehunter9/llm-gateway-frontend:v2.0.6-test1`（与后端同 registry `lovehunter9`，便于推送；tag 用户指定 `v2.0.6-test1`）。

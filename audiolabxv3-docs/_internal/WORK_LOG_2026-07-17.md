# WORK LOG 2026-07-17 — llm-init audio-aware endpoint catalog (test3) + RULE-1 rebuild

## Problem (user-spotted from the dashboard)
The STT Stream instance's llm-init console ("服务状态 → 支持的端点 / API 格式") listed the
**generic LLM surface** — `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`,
`/v1/responses`, plus OpenAI-Compatible / Anthropic-Compatible format toggles — for an
**audio** (`stt_stream`, Qwen3-ASR) instance. Wrong: the audio proxy never serves those.
User: "界面上这显示对吗？我怎么觉得这是 llm-init 改得不到位。" Correct diagnosis.

## Root cause
The original ENGINE_KIND=audio work covered the DATA plane (proxy/adapter.go: reverse-proxy
`/v1/*`, synthesize `/v1/models`, health probes) but NOT the CONTROL plane. `controlplane/
endpoints.go` was a static OpenAI/LLM catalog with no `EngineAudio` branch; since the data
plane is "on" for audio, the chat/embeddings/responses/messages rows were all flagged
`available` and rendered. dashboard.js buckets rows by `category` into ollama/openai/anthropic,
so the OpenAI+Anthropic toggles showed. Purely a control-plane/display bug — audio requests
always worked (WS e2e verified previously).

## Fix (llm-init, branch feat/stt-relative)
- `internal/controlplane/endpoints.go`: added `categoryAudio="data-plane-audio"`, `mWS="WS"`,
  `groupAudio`. Split the data-plane rows out of the catalog literal into `llmDataPlaneRows`
  (OpenAI+Anthropic, unchanged) and new `audioDataPlaneRows` keyed on `cfg.Spec.Mode`.
  `buildEndpointCatalog` appends one or the other by `kind`. Per-mode audio paths mirror the
  chart's wrappers.yaml FastAPI routes; every mode always keeps GET `/v1/models`.
- `internal/controlplane/static/dashboard.js`: added an `audio` format bucket
  (label `Audio`, category `data-plane-audio`) to FORMAT_META + `svc.formats/endpoints` +
  `fetchEndpoints` re-init + `defaultFormat` order.
- `internal/controlplane/static/dashboard.css`: `.ep-method.ws` badge style.
- Tests: `TestEndpoints_AudioKind` (stt: audio rows present, no LLM rows) +
  `TestEndpoints_AudioModeRoutes` (per-mode route table for the other 8 modes). Fixture got an
  `EngineAudio` case. `go build ./...` OK; `go vet ./...` clean; controlplane/dataplane/config/
  proxy packages all pass. (Only pre-existing sandbox-only failure: hfwrap temp-file test —
  "Operation not permitted", unrelated.)
- model-spec NOT touched: its `mode` already passes MODEL_MODE through verbatim (correct for
  the gateway); no audio-specific change needed there.

## 五、长流式加固（滚动重置 = 实现B）+ 服务端保活修复

- **问题**：Qwen3-ASR 流式 state 持续累积音频上下文 → vLLM 编码器缓存（启动日志确认 budget
  **8192 tokens**）在约 10 分钟连续流后溢出 → 会话中断。会议/演讲/有声书都动辄 >10min，必须解决。
- **修复（`audiolabxv3/templates/wrappers.yaml` → `stream.py`）**：
  1. **主动滚动重置**：每 `STREAM_ROLL_SEC`（默认 240s）`finish_streaming_transcribe` 当前段，
     把其文本折进 committed `prefix`（`_join` 保证跨接缝单调、仅英文词间补空格），再
     `init_streaming_state` 开新 state → 编码器缓存占用归零 → 时长事实上无限。
  2. **兜底**：捕获 `encoder cache/exceeds/pre-allocated` 异常 → 强制 roll → 重试该 chunk 一次。
  3. 推理已用 `asyncio.to_thread` + 全局 `_infer_lock` 卸到线程池（循环不被推理堵死）。
- **顺带修 1011**：`uvicorn.run(..., ws_ping_interval=None, ws_ping_timeout=None)`。猛灌帧压测下
  默认 20s 保活 ping 会把健康会话误杀（`CLOSE 1011 keepalive ping timeout`）；字幕是客户端驱动，
  改用 WebSocketDisconnect/TCP reset。
- **重装**（RULE 1 全流程）：uninstall→delete→重打 tgz→clone；hash/URL 复用不变
  （`audiolabxv30f9f88` / `https://d123f7e6…`，env 未变）。
- **实测（经网关，合成长音频，`/tmp/ws_gw_client.py` 需 `proxy=None` 绕沙箱 SOCKS）**：
  - 300s（跨 1 次 roll）：601 partial → FINAL，零报错，文本跨 roll 单调累积。
  - 720s 旧代码：~560s 处被 1011 切断，但**无 encoder-cache 报错**（证明 roll 生效）。
  - 720s 加固后：**1443 partial → FINAL，零报错**，干净越过旧 ~10min/600s 崩溃点。
  - 用户随后用 1h05m 真实英文有声书线上实测，滚动字幕正常（2:09 已定 59 句）。

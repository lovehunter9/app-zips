## 一、根因:faster-whisper 在 Blackwell 上静默退回 CPU

- 现象:Whisper STT 极慢(~realtime),4 分钟音频要好几分钟;经 Gateway 频繁 504。
- 排查:
  1. 病态测试数据(`long.wav` 重复句)触发 faster-whisper 的反幻觉 **temperature 重试风暴**,成倍放大耗时——但这只是放大器。
  2. 真正根因:`faster-whisper-server:0.6.0-rc.3-cuda` 基于 **CUDA 12.6.3 + ctranslate2**,在 **Blackwell sm_120** 上 cuBLAS 没有对应 kernel → 即便 `inference_device=cuda`,float16 也**静默退回 CPU**(推理时 `GPU Utilization = 0%` 实测佐证)。上游 faster-whisper/speaches 暂无面向 Blackwell 的镜像。
- 结论:这个镜像不可救,弃用。

## 二、决策:镜像收敛到 2 个(老板「镜像尽量少」)

| 能力 | 旧镜像 | 新镜像 |
|---|---|---|
| STT(Whisper) | fedirz-faster-whisper-server | **vllm-vllm-openai:v0.23.0-cu129**(`vllm serve openai/whisper-large-v3`) |
| STT(Qwen3-ASR) | vllm-vllm-openai(已是) | 不变 |
| VAD | fedirz-faster-whisper-server | **maximsachs-pyannote_fastapi:4.0.4** + wrapper |
| Translate | fedirz-faster-whisper-server | **maximsachs-pyannote_fastapi:4.0.4** + wrapper |
| Diar / Embed / Enhance | pyannote_fastapi(已是) | 不变 |

最终全座基座只剩 **vLLM cu129** 与 **pyannote_fastapi 4.0.4** 两个镜像。两者都已确认 Blackwell 兼容(vLLM cu129 跑 Qwen3-ASR;pyannote 的 torch 跑 diar `device:cuda` 亚实时)。

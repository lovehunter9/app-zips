## 二、Phase 1：dual + 持久化 servers.json + 两个变量留空

### 2.1 改 MODE 默认值 + 两个变量模板成空串

`templates/configmap.yaml`：

```yaml
MODE: "dual"
PASSWORD: "{{ (.Values.olaresEnv | default dict).PASSWORD | default "" }}"
GDPR_EMAIL: "{{ (.Values.olaresEnv | default dict).GDPR_EMAIL | default "" }}"
```

用 `(.Values.olaresEnv | default dict)` 防御性写法，避免 helm template 测试时 `nil pointer` 报错（第一次没加 default 就被 helm lint 卡住了一次）。

### 2.2 servers.json 持久化 + 首次种子

新增三件套：

- `librespeed-defaults` ConfigMap：存放 chart 默认 `servers.json`（最初 1 条 Local + 1 条 placeholder remote）
- `librespeed-data` hostPath volume：**最初挂在 `userspace.appCache`** ← 这里 5 分钟后被用户指出错误，改 `userspace.appData`
- `init-servers-json` init container（最初用 `docker.io/beclab/aboveos-busybox:1.37.0`）：检查 `/data/servers.json` 是否存在，没就从 `/defaults` 拷一份；存在就跳过——保证 **user edit never overwritten**

主容器以 `subPath: servers.json` 把 hostPath 里的那个文件挂到 `/servers.json`（read-only，主机侧可写），LibreSpeed entrypoint 在 startup 时 `cp /servers.json /var/www/html/server-list.json`。

### 2.3 OlaresManifest 暂时移除 envs

整个 `envs:` 块删除，安装时不再要求填任何字段——用户能直接看到 `TELEMETRY=true + PASSWORD="" + GDPR_EMAIL=""` 的实际 UI 表现。

→ 打包测试：`librespeed-1.0.0.tgz` v1。

### 2.4 用户校正 #1：appCache → appData

用户原话：「放在 appCache 下不能真正持久化，得放在 appData 下，你可以扫描一下其它应用。」

→ 扫 radicale / testapp5 / karakeep / agentzero 等用到 `userspace.appData` 的 chart，确认这就是真持久化点。`appCache` 是 best-effort cache，Olares 可能清理。

改动：

- `hostPath.path` 从 `{{ .Values.userspace.appCache }}` 改成 `{{ .Values.userspace.appData }}`
- `permission` 去掉 `appCache: true`（不再需要）
- 所有 i18n 描述里的路径 `appCache/librespeed/...` → `appData/librespeed/...`
- init container 日志文案同步

→ 重打包 v2。

## 三、用户互动：servers.json 改完要不要重启？远程节点能填啥？

### 3.1 「改完需要重启吗」

如实回答：**需要**。原因是 LibreSpeed entrypoint 只在 startup 时 `cp /servers.json /var/www/html/server-list.json`，Apache 之后服务的是「拷贝出去那份」，跟我们挂的 `/servers.json` 已脱钩。

讨论了 3 个热重载方案：

| 方案 | 评估 |
|---|---|
| A. 同一 hostPath 文件双挂 (/servers.json + /var/www/html/server-list.json) | entrypoint 的 `cp` 检测到同 inode 会报 `are the same file` 退出，**否决** |
| B. 自定义 wrapper 覆盖 entrypoint，用符号链接替换 | 能做到真热重载，但维护成本高（LibreSpeed 升级若改 entrypoint 我们要跟），**未上** |
| C. sidecar inotify 监听文件 + cp | 需要共享 PID/mount，对镜像有侵入，**未上** |

最终决定：**保持「改完手动重启」的现状**。servers.json 是低频操作，Olares 自带停止/启动按钮，UX 可接受。

### 3.2 「能填 baidu.com 吗」

不能。LibreSpeed 不是通用 HTTP 测速——远程节点必须实现它自定义的 `garbage.php` / `empty.php` / `getIP.php` 端点协议，**且必须返回 `Access-Control-Allow-Origin: *`**（浏览器跨域 XHR 必备），普通网站都不会满足这两条。

### 3.3 把示例 placeholder 换成实际可用的公共节点

用户：「把 servers.json 的 example 换成实际的公共测速点，我不喜欢一进页面就跳错说连不上。」

→ 拉 LibreSpeed 官方维护的 `https://librespeed.org/backend-servers/servers.php`（社区节点列表），用 curl 探活 + 检查 CORS：

| 节点 | HTTP | `ACAO` | 评级 |
|---|--:|---|---|
| Sharktech LA | 200 | `*` | **✓ 选** |
| Sharktech Amsterdam | 200 | `*` | **✓ 选** |
| Sharktech Chicago / Las Vegas | 200 | `*` | ✓ 备选 |
| Clouvider FRA/LON/NYC/LA/ATL | 200 | **空** | ✗ 浏览器会被 CORS 挡 |
| A573 Tokyo | 403 | — | ✗ 拒访问 |
| DSGroupMedia Singapore | DNS 失效 | — | ✗ |
| `in1.backend.librespeed.org` | SSL 证书名不匹配 | — | ✗ |
| `de1.backend.librespeed.org` | DNS 失效 | — | ✗ |

Sharktech 是这批节点里唯一**三个端点都齐 ACAO=\* 的**，挑了地理上跨太平洋（LA）和跨欧亚（Amsterdam）两个，跟 Local 凑 3 条默认下拉。

→ 重打包 v3。

## 四、Phase 2：5 个变量 envs 化

`OlaresManifest.yaml` 新增 `envs:` 块（5 条，全部 `required: false + editable: true + applyOnChange: true`）：

```yaml
envs:
  - envName: MODE
    type: string
    default: "dual"
    options:
      - title: "Dual — ..."
        value: "dual"
      - title: "Standalone — ..."
        value: "standalone"
      - title: "Frontend — ..."
        value: "frontend"
      - title: "Backend — ..."
        value: "backend"
  - envName: TELEMETRY        # bool, default "true"
  - envName: PASSWORD         # password, default "", regex 允许空或 ≥6 位
  - envName: GDPR_EMAIL       # email, default ""
  - envName: IPINFO_APIKEY    # password, default ""
```

**MODE 下拉用 `options:` 块**（karakeep 的 `INFERENCE_OUTPUT_SCHEMA` 用同样模式确认 Olares 原生支持）。本来想只暴露 dual/standalone 两个，最终决定 4 个都暴露（用户后来明确要保留），副作用在第六节处理。

`templates/configmap.yaml`：从 `librespeed-env` 里删除上面 5 项。
`templates/librespeed.yaml`：主容器同时用 `envFrom: configMapRef`（静态项）和 `env:` 列表（5 个用户可调项），后者从 `(.Values.olaresEnv | default dict).X | default "xxx"` 注入——`env:` 在 Kubernetes 里优先于 `envFrom`。

→ 重打包 v4。

## 五、Bug 修复：Local 在下拉里消失 & sponsor 双括号

用户截图：MODE=dual + 我们的默认 servers.json，**下拉里只有 "LOS ANGELES, USA (SHARKTECH)" 和 "AMSTERDAM, NETHERLANDS (SHARKTECH)"，Local 整个不见了**。

### 5.1 Local 失踪 — v6.1.0 UI 的过滤逻辑

从 `https://librespeed.org/javascript/index.js` 抓代码：

```js
const aliveServers = testState.servers.filter((s) => {
  if (s.pingT !== -1) return true;
  return typeof s.server === "string" && s.server.startsWith("//");
});
```

我们 Local 的 `"server": ""` 空串两条都不满足 → 被 `aliveServers` 过滤剔除 → 不进 dropdown。

**修复**：让 Local 的 `server` 字段使用协议无关的 `//<librespeedDomain>/`。需要在 helm template 里读 `.Values.domain.librespeed`（Olares 自动注入），套用 karakeep 同款写法：

```yaml
{{- $domainDict := .Values.domain | default dict -}}
{{- $librespeedDomain := index (split "," ($domainDict.librespeed | default "")) "_0" -}}
```

`servers.json` 里：

```json
{
  "name":   "Local (this Olares)",
  "server": "//{{ $librespeedDomain }}/",
  ...
}
```

这样既满足 `startsWith("//")` 兜底，又是真实可达的 URL（ping race 一般也能赢）。

### 5.2 sponsor 双括号 — 同样从 JS 源码定位

```js
link.innerHTML = `${server.name}${
  server.sponsorName ? ` <span>(${server.sponsorName})</span>` : ""
}`;
```

我们 name 里写了 `"Los Angeles, USA (Sharktech)"` + 又给了 `sponsorName: "Sharktech"` → 渲染成 `LOS ANGELES, USA (SHARKTECH) (SHARKTECH)`。

修复：name 去掉 `(Sharktech)` 后缀，只保留 `sponsorName` 字段给 UI 自己追加。

→ 重打包 v5。新版升级时需要用户手动删 `/Data/librespeed/servers.json` 让 init container 重新种子（init 不会覆盖已存在文件）。

## 六、识别但保留的限制：`backend` 模式与 Olares 鉴权

用户洞察：「我们是不是 backend mode 现在完全支持不了，因为有 Olares 鉴权的问题。。。别人想访问也访问不了。」

**确认是真的**：

- Olares 给每个 entrance 套 SSO 鉴权（默认 `authLevel: internal`）
- backend 模式的全部意义就是「让别人能 XHR 到你的 PHP 端点」
- 别人浏览器一发请求 → Olares 拦下扔到登录页 → 节点立即被判死

考虑了 3 个方案：

| 方案 | 评估 |
|---|---|
| A. 从 MODE 下拉删除 backend | 最干净，但牺牲了模式探索性 |
| B. 默认 entrance 改 `authLevel: public` | UI 也变公开，任何人能进来跑测速 / 看历史，**致命** |
| C. 双 entrance（UI internal + backend public），拆 service | chart 复杂度翻倍，用户心智成本大 |

用户拍板：**「不删选项，但在文档里说明 backend 要想能够使用，最简单的方式是如何修改」**。中庸方案，文档 5.4 处理。

文档 5.4 v1 我写成了「改 OlaresManifest.yaml + helm package + 卸载重装」——用户**当晚立刻指出这脱离实际**（end user 拿不到 chart 文件），并拍 Olares Settings UI 的截图过来：路径是 **Settings → Applications → librespeed → Access policies → Authentication level → Public**。

→ 文档 5.4 v2 改成纯 UI 操作 + 加「用完想撤回，改回 Internal 立即生效」给一个可逆退路。

## 七、Bug：切换 MODE 但 UI 不变（standalone 仍显示 3 条下拉）

用户截图：环境变量已经 `MODE=standalone`、Pod 已重启，**但 UI 下拉依然 3 条**。第一反应可能是「重启没生效」——但其实根因更深。

### 7.1 根因（来自 fetch 上游 entrypoint.sh）

```bash
if [[ "$MODE" == "frontend" || "$MODE" == "dual" || "$MODE" == "standalone" ]]; then
  ...
  if [ -f /servers.json ]; then
    cp /servers.json /var/www/html/server-list.json
  fi
fi
```

**LibreSpeed entrypoint 对 standalone / dual / frontend 完全一样处理 `server-list.json`**——只要 `/servers.json` 挂了就用它。MODE 之间的区别只在「是否往 /var/www/html/backend/ 拷 PHP 文件」「是否设置 /var/www/html/results/」上，对 UI 下拉行为零影响。

我之前文档里写的「standalone = 不显示下拉」是**基于"MODE 应该改变 UI"的天真假设**，跟 LibreSpeed 实际实现不符。

### 7.2 修复：chart 侧做 MODE-aware 渲染

引入第三个 volume `librespeed-effective`（emptyDir），让 init container 根据 MODE 现写：

| MODE | effective servers.json |
|---|---|
| `standalone` | heredoc 写入「Local 单条」——LibreSpeed UI 看到 `servers.length === 1` 自动折叠 dropdown |
| `frontend` | jq 过滤掉 server == 本机域名 / 空串 / `/` 的条目（见下节） |
| `dual` / `backend` | `cp /data/servers.json /effective/servers.json` |

主容器把 `librespeed-effective` 卷的 `servers.json` 挂到 `/servers.json`，**持久化文件 `/data/servers.json` 完全只读**——切换 MODE 永远不会丢用户编辑，切回 dual 立刻恢复全量视图。

init container 加注入两个 env：`MODE` 和 `LIBRESPEED_DOMAIN`。

→ 重打包 v6，文档第 1、5.1 节同步说明。

## 八、Phase 2 加料：frontend 模式自动过滤 Local

用户提议：「frontend 是不是也可以友好化？比如自动过滤掉 servers.json 里的 LOCAL？（当然，对于 DUAL 和 FRONTEND，如果用户删掉了 servers.json 里的 LOCAL，那么尊重用户的选择，frontend 和 dual 都保持没有 LOCAL 的状态）」

很合理——frontend 模式无本地 PHP backend，Local 条目必失败。

### 8.1 镜像换成自带 jq

busybox 没 jq、没 python；用 sed/awk 解析 JSON 太脆。扫到 mattermost 用 `docker.io/beclab/harveyff-utils-jq:v0.0.1` 处理 config.json，自带 jq，**这个镜像已经在 beclab 镜像仓**。

init-servers-json 镜像换掉。

### 8.2 jq 过滤逻辑

```bash
LOCAL_URL="//${LIBRESPEED_DOMAIN}/"
jq --arg local "$LOCAL_URL" \
   '[ .[] | select((.server // "") != $local and (.server // "") != "" and (.server // "") != "/") ]' \
   /data/servers.json > /effective/servers.json
```

**识别依据是 `server` 字段，name 字段无关**——好处是：

| 场景 | 行为 | 是否符合用户预期 |
|---|---|---|
| 默认 Local（`server: "//本机/"`）| 过滤 | ✓ |
| 用户重命名 Local 但 server 不变 | 过滤 | ✓ |
| 用户把 Local 改指向另一台 Olares（`//bob.olares.cn/`）| 保留 | ✓（用户故意） |
| 用户已主动删除 Local | 什么都没动到 | ✓（尊重删除） |
| 旧格式 `server: ""` 残留 | 过滤 | ✓（在 frontend 下也必然失败） |

→ 重打包 v7。文档第 1 节 frontend 行说明改成「chart 自动过滤掉指向本机的 Local 条目」，删掉切换提醒里「切 frontend 前要手动删 Local」那条。

# 候选移植路径设计

> 把"移植难度评估"的结论落到 5 条具体的可执行路径。每条路径给出：定位、与既有应用关系、技术栈、关键设计点、工作量量级、风险点。**只到设计层**，不写 Helm chart 也不写代码骨架。

---

## 一、路径全景表

| 路径 | 形态 | 定位 | 优先级 | 工作量 | 与既有应用关系 |
|---|---|---|---|---|---|
| **甲** 扩展 `whisperwebuiv2` | 升级现有应用 | 给已上架的 `whisperwebuiv2` 补"任务队列、对象存储、字幕编辑器、AI 摘要联动" | ★★★★★ 最优先 | 0.5-1.5 人月 | 直接修上游 fork |
| **乙** 上架 `whisperX-FastAPI` | 新增 headless API 应用 | 高精度长音频 + 词级时间戳 + 说话人分离的独立 endpoint | ★★★★ | 0.5-1 人月 | 与 `speaches` 并存（重型版） |

## 二、路径甲：扩展 `whisperwebuiv2`（最低成本）

### 2.1 定位

不新增应用，直接给已上架的 `whisperwebuiv2`（v1.0.19，fork 自 `jhj0517/Whisper-WebUI`）做下列增量。

### 2.2 现状缺口

| 缺口 | 现状 | 用户痛点 |
|---|---|---|
| 长任务 | Gradio 内部队列，HTTP 超时不可控 | 1 小时以上音频可能中断 |
| 对象存储 | hostPath PVC | 多用户共用一个大盘容易满 |
| 字幕编辑器 | 无（导出 SRT 后用户在外部编辑） | 用户体验不闭环 |
| AI 摘要 | 仅有翻译 | 没有"章节 / 摘要 / 行动项" |
| 多用户 | Gradio 单用户语义 | 多人共用会任务串扰 |

### 2.3 技术栈增量

| 模块 | 选型 | 理由 |
|---|---|---|
| 任务队列 | RQ + Redis（轻量） | 避免引入 Celery 复杂度 |
| 字幕编辑器 | 内嵌 web-based editor（如 `subtitle-edit` 的 web fork 或自写 Svelte 组件） | 不出 Gradio UI |
| AI 摘要 | 调 `ollamav2` 的 `/v1/chat/completions`（OpenAI 兼容） | 不带模型权重 |
| 对象存储 | 仍 hostPath PVC（短期）→ 后期可选接 MinIO（中期） | 渐进式 |

### 2.4 关键设计点

- **fork 策略**：基于上游 `jhj0517/Whisper-WebUI`，在 Olares 团队的 fork 上加 patch；定期 rebase 上游。
- **任务队列**：用 RQ + Redis 把"上传文件 → 转录"做异步；前端用 SSE 显示进度。
- **AI 摘要 endpoint**：调 `ollamav2` 时，sharedEntrance 已存在；OlaresManifest 加 `dependencies.ollamav2`。
- **字幕编辑器**：内嵌一个轻量 SRT 编辑器；保存时把修订写回 hostPath。
- **多用户隔离**：用户上传文件 + 转录结果按 `bfl.username` 子目录隔离。

### 2.5 工作量与风险

- **工作量**：0.5-1.5 人月（看是否做字幕编辑器 + AI 摘要全栈）
- **主要风险**：
  - 上游 `jhj0517/Whisper-WebUI` 迭代速度慢（v1.0.19 → 1.0.20 等增量缓慢），Olares fork 维护成本上升
  - Gradio 框架对"多用户 + 队列"支持不优雅；可能需重写部分前端

## 三、路径乙：上架 `whisperX-FastAPI`（高精度长音频 endpoint）

### 3.1 定位

`speaches` 用的是 faster-whisper-small；对长音频 + 说话人分离 + 词级时间戳支持有限。**`whisperX-FastAPI`** 把 WhisperX（large-v3 + pyannote + wav2vec2 对齐）做成独立 FastAPI endpoint，**与 `speaches` 并存**——`speaches` 负责"短音频实时"，`whisperX-FastAPI` 负责"长音频高精度"。

### 3.2 技术栈

| 模块 | 选型 |
|---|---|
| 上游 | `pavelzbornik/whisperX-FastAPI`（或 `Nyralei/whisperx-api-server`） |
| ASR | WhisperX = faster-whisper large-v3 + wav2vec2 + pyannote 3.1 |
| HTTP API | FastAPI + uvicorn |
| OpenAI 兼容 | 部分（需要包一层 `/v1/audio/transcriptions` 转换） |
| 任务模型 | 同步阻塞（短）+ 异步任务（长）| 

### 3.3 OlaresManifest 关键字段

- `entrances`: REST API + 文档（FastAPI 自带 `/docs`）
- `sharedEntrances`: 内部，供其它应用调用
- `requiredGpu: 8Gi` / `limitedGpu: 16Gi`
- `dependencies`: 无外部依赖，自带模型缓存
- `appData`: 存模型缓存（10 GiB+）

### 3.4 工作量与风险

- **工作量**：0.5-1 人月
- **主要风险**：
  - `whisperX-FastAPI` 这类社区项目维护频率不一致；需挑社区活跃的 fork
  - 需要在 OlaresManifest 文档化"HF token 接受 pyannote license"步骤

## 四、路径丙：上架 `WhisperLiveKit`（流式 WebSocket endpoint）

### 4.1 定位

`speaches` 不做流式 WebSocket；**`WhisperLiveKit`** 提供 `/asr` WebSocket + `/v1/audio/transcriptions` REST，**填补流式短板**。

### 4.2 应用场景

- 上游"语音输入法"项目的 WebSocket 后端
- 实时字幕（如 OBS 直播叠加 / 个人讲话实时显示）
- "录音中边显示"的 AI 笔记本（路径丁会用到）

### 4.3 技术栈

| 模块 | 选型 |
|---|---|
| 上游 | `QuentinFuxa/WhisperLiveKit` |
| ASR | faster-whisper（多档可选） |
| HTTP/WS | FastAPI + WebSocket |
| OpenAI 兼容 | 完全（`/v1/audio/transcriptions`） |

### 4.4 工作量与风险

- **工作量**：0.3-0.8 人月（最轻）
- **主要风险**：上游项目相对新，社区生态薄；建议先验证与 `speaches` 是否真的有差异化

## 五、路径丁：自研"AI 语音笔记本" Olares 应用（旗舰方向）

### 5.1 定位

**本课题最值得自研的方向**。复用 Olares 既有 `whisperwebuiv2` / `speaches`（转录）和 `ollamav2`（LLM），做一个**端到端 AI 语音笔记本**——用户对着浏览器或手机说话，自动转录 + AI 摘要 + 标签 + 跨笔记问答。

类比：NotebookLM + AudioPen + Voicenotes 的"个人云"版本。

### 5.2 与 Olares 定位的契合点

| Olares 定位 | AI 语音笔记本契合点 |
|---|---|
| "我的数据在我家" | 个人脑暴 + 私密会议 100% 在家 |
| LarePass 移动端 | 手机录音 → 上传家用 Olares |
| sharedEntrance 共享后端 | 转录 + LLM 都复用现有应用 |
| hostPath 持久化 | 笔记可永久保存 |
| 多 sub-chart | 数据后端 + 前端独立 |

### 5.3 架构设计

```
[Web UI / 手机 PWA / LarePass 内嵌]
            ↓ HTTP/WebSocket
[新增应用：audionotes-server]
    ├── 录音上传（支持 chunk upload，避免 1GB 文件一次发）
    ├── 调 `whisperwebuiv2` 或 `speaches` 转录（sharedEntrance 内部调用）
    ├── 调 `ollamav2` 做摘要、章节、行动项、标签（OpenAI 兼容）
    ├── SQLite + 文件存储（hostPath PVC）
    ├── 跨笔记搜索（向量 + 关键词）
    └── 跨笔记问答（RAG over notes）
```

### 5.4 技术栈

| 模块 | 选型 | 理由 |
|---|---|---|
| 后端 | FastAPI（Python）| 与 ASR 生态一致 |
| 前端 | SvelteKit 或 Vue 3 | 体积小 + Capacitor 友好（未来上移动端）|
| 数据库 | SQLite + sqlite-vss 或 sqlite-vec | 无需独立 DB 容器 |
| 转录调用 | 调 `whisperwebuiv2` 的 sharedEntrance（内部） | 复用 |
| 流式录音 | 调 `WhisperLiveKit`（如已上） | "边说边显示" |
| LLM 调用 | 调 `ollamav2` 的 sharedEntrance（OpenAI 兼容） | 复用 |
| 嵌入模型 | bge-small-zh / e5-small | 走 `ollamav2` 或自带 |
| 容器化 | 单容器（不必微服务） | 简洁 |

### 5.5 OlaresManifest 关键字段

- `dependencies`: `whisperwebuiv2`（或 `speaches`）+ `ollamav2`
- `entrances`: 主 Web UI + 可选 API endpoint
- `sharedEntrances`: 可选（供 LarePass / 其它应用调用）
- `permission.userData`: Home（用户笔记 + 录音永久存）
- `permission.appData / appCache`: 模型缓存
- `requiredMemory`: 1 GiB / `requiredCpu: 200m`（轻量后端）
- 不需要 GPU（GPU 由依赖应用提供）

### 5.6 功能阶段（建议三阶段交付）

**第一阶段（MVP, 1.5 人月）**：
- 录音上传 → 转录 → AI 摘要 → 笔记保存
- 单一笔记视图 + 列表 + 搜索
- 调依赖应用，不带模型

**第二阶段（增强, 1 人月）**：
- 跨笔记 RAG 问答
- 标签自动生成 + 手动整理
- 笔记导出（Markdown / DOCX / PDF）
- 实时录音（调流式 endpoint）

**第三阶段（移动端 + 集成, 1 人月）**：
- LarePass 内嵌 / PWA
- 手机录音 → 上传家用 Olares
- 与其它笔记应用集成（Joplin、Memos、AppFlowy 等已在 Olares Market）

### 5.7 工作量与风险

- **工作量**：2-4 人月（三阶段累积）
- **主要风险**：
  - 与 `whisperwebuiv2` 的"WebUI 转录界面"用户场景区分要明确（避免被认为冗余）
  - 移动端录音上传带宽 + 长任务体验是关键 UX 难点
  - RAG 搜索需要嵌入模型 + 向量库；Olares 上 `sqlite-vec` 是否能跑得动需要验证

## 六、路径戊：上架 `Anysub`（whishper v4）

### 6.1 定位

`whisperwebuiv2` 是 Gradio 单用户 UI；`Anysub`/`whishper v4` 是 Svelte 全栈多用户 + 字幕编辑器 + 分布式 worker。**与路径甲是替代关系，不是并存关系**——选其一。

### 6.2 与路径甲的取舍

| 维度 | 路径甲（扩展 whisperwebuiv2） | 路径戊（新上 Anysub） |
|---|---|---|
| 工作量 | 0.5-1.5 人月（fork 维护） | 1-2 人月（新打包） |
| 用户体验 | Gradio 风格（功能丰富但 UX 一般） | 现代 Web UI + 字幕编辑器 |
| 多用户 | 需补 | 原生 |
| 分布式 | 需补 | 原生 |
| 上游活跃度 | 中（jhj0517 维护稳定） | 中（pluja v4 在 alpha） |
| 用户迁移 | 无 | 旧 `whisperwebuiv2` 用户需迁移 |

**推荐**：先做路径甲（增量低风险）；如果用户反馈"UI 太丑 + 长任务不稳"，再做路径戊作为升级版替代。

### 6.3 工作量与风险

- **工作量**：1-2 人月
- **主要风险**：
  - `whishper v4 / Anysub` 在 2026 中仍属于 alpha 阶段
  - 旧 `whisperwebuiv2` 用户的迁移路径（数据格式不同）

## 七、推荐三阶段路线（综合）

### 第一阶段：补全集群侧底座（1-2 个月）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1.a | 上架 `whisperX-FastAPI`（路径乙） | 0.5-1 人月 |
| 1.b | （可选）上架 `WhisperLiveKit`（路径丙） | 0.3-0.8 人月 |
| 1.c | 给 `whisperwebuiv2` 补 AI 摘要 + 字幕编辑器（路径甲最小集） | 0.5 人月 |

**完成后状态**：
- `speaches`：短音频实时（已存在）
- `whisperX-FastAPI`：长音频高精度 + diarization
- `WhisperLiveKit`：流式 WebSocket（可选）
- `whisperwebuiv2`：通用 GUI + AI 摘要 + 字幕编辑

### 第二阶段：自研旗舰应用（2-3 个月）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 2.a | "AI 语音笔记本"应用 MVP（路径丁第一阶段） | 1.5 人月 |
| 2.b | 增强：RAG + 标签 + 导出（路径丁第二阶段） | 1 人月 |

### 第三阶段：移动端 + LarePass 集成（1-2 个月）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 3.a | AI 语音笔记本 PWA / LarePass 内嵌 | 1 人月 |
| 3.b | （可选）路径戊：考察 `Anysub` 是否升级替代 `whisperwebuiv2` | 1-2 人月 |

### 总计

- **集群侧**：约 1-2 人月
- **自研旗舰**：约 2-3 人月
- **移动端**：约 1-2 人月
- **合计**：4-7 人月（取决于是否做路径戊与移动端）

## 八、不在本路线上的项目

| 项目 | 不纳入原因 |
|---|---|
| Otter / Fireflies / Read.ai 等会议机器人 | 闭源 SaaS，无移植路径 |
| Nuance DAX / Suki / Abridge 等医疗 | 闭源 + 行业合规壁垒，移植无意义 |
| Verbit / Rev / Beey 等法律 | 同上 |
| OpusClip / Submagic 等视频创作者 | 闭源 + 重云端视频处理 |
| MacWhisper / Vibe / Buzz 桌面 App | 流派 A 本质不该上服务端；正确做法是它们改接 `speaches` |
| 国内大厂转录（通义听悟 / 飞书妙记 / 讯飞听见）| 闭源 SaaS；私有化版需联系商务而非"移植" |

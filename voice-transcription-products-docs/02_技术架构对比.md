# 技术架构对比

> 把 120+ 个样本按 7 个维度做横向技术架构对比，识别出 6 大架构流派；为后续"Olares 移植难度评估"提供基础。

---

## 一、对比维度

| 维度 | 关注什么 |
|---|---|
| **形态** | 桌面 App / 浏览器扩展 / Web SaaS / 会议机器人 / CLI / 自托管 WebUI / 视频编辑插件 / 行业 SDK / 录音笔 + App |
| **音频输入源** | 本地文件 / URL / YouTube / Zoom-Teams-Meet 直接拉 / 浏览器扩展抓 / 麦克风录制 / 实时流 / 硬件录音笔 |
| **进程模型 / 部署模型** | 单进程客户端 / 客户端 + 本地后端 / 客户端 + 云后端 / 全云 / 全本地 / 分布式 worker |
| **任务模型** | 同步阻塞 / 异步 polling / 任务队列（Celery/RQ）/ 流式 SSE / WebSocket / 分布式 worker pool |
| **持久化** | 仅模型缓存 / + 上传文件 / + 转录结果 DB / + 多用户 + 协作版本 / + 对象存储 |
| **后处理 AI** | 无 / 标点恢复 / 章节切分 / AI 摘要 / 关键点 / Action Items / Q&A / 翻译 / Repurposing |
| **字幕 / 输出** | 仅纯文本 / + SRT-VTT / + 词级 JSON / + 视频编辑同步 / + DOCX-PDF / + 多语种字幕 / + clip 视频 |

---

## 二、六大架构流派

> 把 120+ 样本归纳为 6 大架构流派。每一派的代表、共性、和"移植到 Olares 的视角"。

### 2.1 流派 A：单进程桌面 App + 本地引擎

**代表**：Vibe、Buzz、MacWhisper、Aiko、Spect、AutoSubs、Petal、Whisper Transcription

**架构**：
```
[GUI shell] ── [whisper.cpp / WhisperKit / faster-whisper] ── [本地模型缓存]
                                  ↓
                          [本地 SRT/VTT/JSON 输出]
```

**共性**：
- 单一二进制 / 单 dmg 安装；无服务端依赖
- 引擎跑在用户机器上（CPU 或 GPU）
- 模型按需下载（首启耗时 5-30 s 取决于 size）
- 隐私第一：音频从不出本机
- 任务模型：同步阻塞（短文件）或本地后台进程（长文件）
- 字幕格式齐全：SRT/VTT/JSON/TSV

**移植到 Olares 的视角**：**这一派不适合直接移植**——它的产品形态本身是"桌面应用"，移植成 Olares 应用反而失去"完全本地 / 一键启动"的本质优势。**正确做法**：让流派 A 的桌面客户端**接 Olares 的 STT endpoint**（即 `speaches`），等于把流派 A 的"用户视角"保留，但底层引擎由用户家的 Olares 集群提供。

### 2.2 流派 B：自托管 Web 全栈（GUI + 后端 + 队列 + DB）

**代表**：Whisper-WebUI（**Olares `whisperwebuiv2` 上游**）、Whishper、Anysub、Project W

**架构**：
```
[浏览器 Web UI] ── HTTP/WS ── [API/Backend]
                                    ↓ 任务派发
                              [Transcription Worker pool]
                                    ↓
                              [faster-whisper / WhisperX + pyannote]
                                    ↓
                              [文件存储 + DB（MongoDB/MariaDB）]
                                    ↓
                              [翻译子服务（LibreTranslate/NLLB/DeepL）]
```

**共性**：
- 完整全栈：UI + 后端 + 任务队列 + 数据库 + 翻译子服务（多容器）
- 多用户支持（虽然多数项目是个人单用户）
- 长任务：异步上传 + 后台 worker + 完成后通知
- 字幕编辑器：典型功能（可在网页上编辑 SRT 行）
- 翻译：通过 LibreTranslate / NLLB / DeepL
- 说话人分离：pyannote（需 HF token）

**移植到 Olares 的视角**：**这一派是 Olares 移植的天然候选**——`whisperwebuiv2` 已经证明了路径。其它候选（如 Whishper、Anysub）可以作为 `whisperwebuiv2` 的替代或补强（如果 jhj0517 上游停滞）。

### 2.3 流派 C：OpenAI 兼容 API 服务端（headless）

**代表**：`speaches`（**Olares 已上架**）、`whisper-asr-webservice`、`whisperX-FastAPI`、`whisperx-api-server`、`WhisperLiveKit`、Deepgram On-prem、AssemblyAI On-prem、Speechmatics Container

**架构**：
```
[任意客户端] ── HTTP/WS（/v1/audio/transcriptions、/v1/audio/translations）
                            ↓
                      [headless server]
                            ↓
                      [Whisper / faster-whisper / WhisperX / 商业自研]
```

**共性**：
- 无 GUI，纯 API
- OpenAI 兼容（多数）→ 客户端切 baseURL 即可
- 任务模型：短文件同步、长文件可异步（取决于实现）
- 单服务多客户端共享（多租户）

**移植到 Olares 的视角**：**这一派是 Olares "共享后端"模式的完美匹配**——`speaches` 已经证明了路径。差异化方向：
- 加任务队列与对象存储 → 适合长任务（`whisperx-api-server` Kafka/S3 模式可借鉴）
- 加中文模型 → 接 sherpa-onnx + SenseVoice / Paraformer（上一课题已规划）
- 加说话人分离 endpoint → 比 `speaches` 多一层

### 2.4 流派 D：会议机器人 / 实时云端

**代表**：Otter、Fireflies、Read.ai、Granola、Fathom、tl;dv、Jamie、Spinach、Avoma、Grain、Gong、Chorus

**架构**：
```
[Zoom/Teams/Meet/Webex] ←─ bot 加入 OR 桌面捕获
                ↓
        [实时音频流（PCM/Opus）]
                ↓
        [流式 ASR（Deepgram-class / 自研）]
                ↓
        [实时增量字幕 + 说话人分离 + 摘要]
                ↓
        [LLM 后处理（GPT-4 / Claude）]
                ↓
        [CRM / Slack / Notion / Email 出口]
```

**共性**：
- 触发方式：bot 加入会议 OR 桌面 audio capture（无 bot）
- 实时流式 ASR：sub-second latency
- 说话人分离 + 实时增量：核心难点
- LLM 摘要：通常 GPT-4o / Claude / 自家 fine-tuned
- 集成出口：CRM / 项目工具 / 邮件
- 隐私：bot 加入时被参会者看见；桌面捕获不可见（**这是 2026 年的关键差异化**）

**移植到 Olares 的视角**：**这一派对 Olares 极不友好**——bot 加入要求公网可达 Zoom/Teams 服务器、商业账户、webhook 注册等；桌面捕获要求用户安装桌面端。Olares 作为"用户家自托管"在这一派上没有任何优势。**正确做法**：不做这类移植；如果非要做，只做"桌面捕获 + 上传到家用 Olares ASR"的轻量级形态（流派 A 的变种）。

### 2.5 流派 E：视频字幕 / 创作者重型工具

**代表**：OpusClip、Submagic、CapCut、Captions、Vugola、Klap、Vizard、Vidyo、Riverside、Descript、Premiere、DaVinci Resolve、Kapwing、Veed

**架构**：
```
[长视频上传] → [转录（自家 / Whisper / 商业 API）] → [LLM 找爆点 / 章节 / 标题]
                          ↓
              [视频处理 pipeline（FFmpeg + AI reframe / 字幕烧录 / B-roll）]
                          ↓
              [短视频导出 + 字幕样式 + 一键发布到 TikTok/YouTube Shorts/Reels]
```

**共性**：
- 重点不在"转录精度"，在"转录后的视频处理"
- 多模态：转录 + 视觉分析（人脸框 / 场景切换 / 情感）
- LLM 找"爆点"是核心（OpusClip 的 ClipAnything）
- 字幕样式 + 动效是用户体验差异化（Submagic 的"字幕样式"领先）
- 通常云端 SaaS（视频处理算力大）

**移植到 Olares 的视角**：**这一派部分可行**——
- "转录 + AI 找爆点"的算法可以本地化（用 Whisper + Ollama LLM）
- 视频处理（FFmpeg + reframe）可以在 Olares 上跑
- 但视频处理算力 + GPU 内存峰值很高，Olares 单机难以匹敌云端
- 用户分发不是 Olares 的强项（用户要把短视频发回 TikTok 自己的账号）

可考虑的方向：做一个"长视频 → 转录 + 章节 + 字幕 SRT" 的本地工具，**省去"自动找爆点"和"reframe"**这种重度视频处理；用户拿到字幕和章节后，自己用 CapCut 等本地剪。

### 2.6 流派 F：AI 笔记本 / 个人长音频整理

**代表**：NotebookLM、AudioPen、Voicenotes、AudioNotes、Cleft、TalkNotes、Letterly、Plaud Note、Mem、Limitless、Rewind

**架构**：
```
[麦克风录音 / 文件上传 / 全天捕获（硬件）]
            ↓
    [转录（Whisper-class）]
            ↓
    [LLM 整理（GPT/Claude/Ollama）：摘要 / 标题 / 行动项 / 标签]
            ↓
    [个人知识库（本地 SQLite / 云数据库）]
            ↓
    [搜索 / 跨笔记 Q&A / 导出]
```

**共性**：
- 个人级，不是团队
- 单次音频通常短（5-30 分钟）
- 重点在"AI 整理"而非"逐字稿"
- 模型组合：Whisper + GPT/Claude/Ollama
- 数据所有权：用户极度敏感（个人脑暴 + 私密会议）

**移植到 Olares 的视角**：**这一派最契合 Olares 定位**——
- "个人云"+"我的笔记不出家门"= 完美匹配
- 转录引擎可复用 `speaches` 或 `whisperwebuiv2`
- LLM 后处理可复用 `ollamav2`
- 持久化用 hostPath PVC
- 这是 Olares 在转录场景**最值得自建一个新应用**的方向

## 三、技术架构维度横向矩阵（重点流派）

| 维度 | 流派 A 单进程桌面 | 流派 B 自托管 Web 全栈 | 流派 C OpenAI 兼容 API | 流派 D 会议机器人云 | 流派 E 视频创作者 | 流派 F AI 笔记本 |
|---|---|---|---|---|---|---|
| 部署方 | 用户机器 | 用户机器 / VPS / Olares | 用户机器 / VPS / Olares / 云 | SaaS 云 | SaaS 云 / 桌面 | 云 + 移动端 / 可本地化 |
| 多用户 | ❌（单人） | ✅（多账户） | ✅（多客户端共享） | ✅（团队 + 企业） | ✅（团队） | ❌-✅（个人 → 团队） |
| 多容器 | ❌ | ✅（4-8 个容器） | ❌（单容器） | ✅（云端微服务） | ✅（云端流水线） | ✅（云端，本地化时变 ✅） |
| 长任务 | 本地后台进程 | 异步 worker | 通常同步（长任务可异步） | 实时流式 | 异步 batch | 通常短任务，长可异步 |
| 对象存储 | 本机磁盘 | 本机磁盘 / hostPath | 流式不存 | S3 / R2 | S3 / CDN | hostPath / 云盘 |
| 说话人分离 | 部分有（pyannote / WhisperX） | ✅（pyannote/UVR） | 部分（取决于引擎） | ✅（自研） | 通常不做 | 可选 |
| 字幕编辑器 | 部分有 | ✅（流派 B 招牌） | ❌（纯 API） | 部分 | ✅ | ❌ |
| AI 摘要 | 通常无 | 可选（Anysub 加了） | ❌ | ✅（核心） | ✅（找爆点） | ✅（核心） |
| 翻译 | 部分有 | ✅（NLLB/DeepL） | ❌ | 部分 | ✅ | 部分 |
| 实时流式 | ❌ | ❌ | 可选（WebSocket） | ✅（核心） | ❌ | ✅（录音中实时显示） |
| 视频处理 | ❌ | ❌ | ❌ | ❌ | ✅（核心） | ❌ |
| GPU 需求 | 可选（CPU 可跑小模型） | 强烈推荐 | 可选 | 云端不可见 | 高 | 可选 |

## 四、Olares 移植场景下的"流派契合度"速查

| 流派 | Olares 契合度 | 已有锚点 | 自研增量价值 |
|---|---|---|---|
| **A 单进程桌面** | ★（不该移植） | — | 让桌面客户端接 `speaches` 即可 |
| **B 自托管 Web 全栈** | ★★★★★ | `whisperwebuiv2` 已上 | 可加任务队列、对象存储、字幕编辑器；或换 fork 上游 Whishper v4 |
| **C OpenAI 兼容 API** | ★★★★★ | `speaches` 已上 | 加中文引擎（sherpa-onnx + SenseVoice）；加说话人分离 endpoint；加长任务异步队列 |
| **D 会议机器人云** | ★（强烈不建议） | — | 网络穿透 + 商业账户门槛太高 |
| **E 视频创作者重型** | ★★★（部分） | — | 可做"轻量字幕导出 + 章节"；省 reframe / B-roll；不与云端竞争 |
| **F AI 笔记本** | ★★★★★ | 可复用 `speaches` + `ollamav2` | **本课题最值得自研的方向**：私人脑暴 + AI 摘要 + 跨笔记搜索 |

---

## 五、本章结论

1. **120+ 样本可归为 6 大流派**：单进程桌面、自托管 Web 全栈、OpenAI 兼容 API、会议机器人云、视频创作者重型、AI 笔记本。
2. **Olares 应只在 3 个流派上发力**：B（已有 `whisperwebuiv2`，可扩展）、C（已有 `speaches`，可扩展）、F（最值得自研新应用）。
3. **明确**：流派 A 桌面端不该被移植；流派 D 会议机器人不适合自托管；流派 E 视频创作者只可做"轻量字幕导出"。
4. **本课题最有价值的自研方向 = 流派 F（AI 笔记本 / 长音频整理）**——Olares "个人云"定位与这个流派完美对齐，且现有 `whisperwebuiv2`（流派 B）和 `speaches`（流派 C）都不覆盖。

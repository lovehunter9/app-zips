# Olares 语音转录产品综合调研 · 最终报告（初稿）

> **重要：本报告已锚定到统一语音 AI 平台愿景。** 完整产品形态、架构、落地路线请优先看 [`../voice-ai-platform-docs/README.md`](../voice-ai-platform-docs/README.md)。本报告聚焦"语音转录"这一用例集在统一平台下的角色，以及该用例独有的市场全景（120+ 样本）、技术架构、长音频与会议场景细节。

## 一、产品愿景下的本课题角色

**统一平台一句话**：做一个新 Olares 应用（暂名 `voice-ai-hub`），提供一套统一 API（OpenAI 兼容 + 扩展），让用户跑转录 / 实时听写 / 会议 / 翻译 / TTS / 播客等 26 个用例；底层模型全部可配置（本地"独立模型应用" + 远程 BYOK）。

**"语音转录"在该平台下不是独立产品，而是 5+ 个 API 用例的实现路径**：

| 用例 | API 端点 | 任务模式 | 主要场景 |
|---|---|---|---|
| **A-1 文件转录** | `/v1/audio/transcriptions` | 异步长任务 | 上传音频 / 视频 → 出文稿 |
| **A-2 音频翻译** | `/v1/audio/translations` | 异步长任务 | 非英语 → 英语 / 跨语种 |
| **A-5 URL 转录** | `/v1/audio/url-transcribe` | 异步长任务 | YouTube / 直链 → 文稿 |
| **B-4 字幕生成** | `/v1/subtitles/generate` | 异步长任务 | 视频 → SRT/VTT 多语种 |
| **B-5 AI 摘要 / 章节 / Action Items** | `/v1/analyze/summary` | 异步 | 文稿 → 摘要 / 章节 / 关键点 |
| **C-1 会议记录会话** | `/v1/meeting/sessions` | 流式 + 持久化 | 实时增量字幕 + 结束后摘要 |
| **C-2 长音频整理** | `/v1/notes/ingest` | 异步长任务 | 个人脑暴 / 日记 / 课堂 |
| **C-3 跨笔记 RAG 问答** | `/v1/notes/qa` | 同步 | 用户问句 → 引用片段回答 |
| **D-2 说话人分离** | `/v1/audio/diarize` | 异步 | 多人音频 → 标 speaker |
| **D-5 强制对齐** | `/v1/audio/align` | 异步 | 已知文本对齐到时间戳 |

**之前推荐的"自研 AI 语音笔记本 / 重型独立转录 App / 上架第二个 WebUI 应用"现在的定位**：

- ✅ **能力上仍然有意义**——但**实现层面被统一平台核心应用 + 本地模型应用 + LLM 后处理（`ollamav2`）覆盖**
- 🔄 **"自研 AI 笔记本"形态从"独立 Olares 应用"变成"核心应用 Web UI 的笔记面板"或独立移动 PWA**（第三阶段 3.3）
- ⏬ 原"路径甲扩展 whisperwebuiv2"路径**降级为可选维护任务**（不在第一阶段核心目标里）

### 2.4 集群侧硬约束（长任务场景特有）

| 约束 | 数量级 | 缓解 |
|---|---|---|
| GPU 内存峰值 | Whisper large + pyannote + 翻译 + LLM 摘要可超 **22 GiB** | 任务串行；档位化；分流应用 |
| 长任务 HTTP 超时 | Olares Nginx 3-5 min；1h 音频跑不完 | 异步任务 + polling / SSE / Webhook（统一平台已内置）|
| 上传带宽 | 1h MP4 ~1 GB；家用上传 10-50 Mbps | 客户端 FFmpeg.wasm 抽音轨；chunk upload |
| 模型缓存膨胀 | Whisper-large + distil + pyannote + NLLB ~20 GiB | hostPath PVC ≥ 50 GiB |
| 多用户 GPU 竞争 | 同 GPU 多任务排队 | 任务队列 + 优先级 + 配额 |

## 五、本课题独有风险（不重复统一平台风险）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **GPU 内存峰值（22 GiB）超出家用集群** | 长音频 + diarization + 翻译 + LLM 并发跑不动 | 档位化任务（入门 / 主流 / 专业）；任务串行 |
| **长任务 HTTP 超时** | 1h 音频跑不完 | 统一平台已内置异步任务 + polling/SSE/Webhook |
| **上传带宽（1h MP4 ~1 GB）** | 移动端体验差 | 客户端 FFmpeg.wasm 抽音轨 + chunk upload |
| **`whisperwebuiv2` 与统一平台核心应用边界不清** | 用户分不清"用核心应用还是直接用 whisperwebuiv2" | 文档明确：whisperwebuiv2 是"一次性文件转录 GUI 体验"；核心应用是"统一 API + 多用例联动" |
| **pyannote 3.1 HF token gated license** | 用户需手动接受 | OlaresManifest 文档化；首次启动引导 |
| **NLLB-200 商用受限（CC-BY-NC-4）** | 翻译子服务商用受限 | 长期换 Qwen3 LLM 翻译 |
| **AI 语音笔记本"国内市场认知度低"** | C-2 / C-3 用户量短期难起 | LarePass / 移动端集成放大用户量 |
| **会议机器人形态在 Olares 不可行** | 公网账号门槛 + SaaS 闭源 | 统一平台 C-1 用例只走"用户主动开 session"路径，不做"bot 加入" |
| **长音频跨语种翻译质量** | NLLB-200 在专业术语场景质量一般 | 默认推荐 LLM 翻译；NLLB 仅作 fallback |

完整 30+ 条风险见 `06_风险与开放问题.md`；统一平台 41 条风险见 [`../voice-ai-platform-docs/04_风险与开放问题.md`](../voice-ai-platform-docs/04_风险与开放问题.md)。

## 六、关键事实（已查证）

- **`whisperwebuiv2` 当前 v1.0.19**（cluster-scoped），sharedEntrance `sharedentrances-whisperwebui`，admin 模式 8 GiB GPU + 6.5 GiB 内存；后端 = faster-whisper（默认） / openai-whisper / insanely-fast-whisper + pyannote + UVR + NLLB / DeepL；统一平台第一阶段直接复用，零工程。
- **`speaches` 当前 v1.0.12**（cluster-scoped），OpenAI 兼容 STT（faster-whisper-small）+ TTS（Kokoro-82M）；同上。
- **`ollamav2` 当前 v1.0.18**（cluster-scoped），OpenAI 兼容 LLM endpoint；统一平台所有 B-5 摘要 / B-3 播客文本生成 / C-3 RAG 直接调用。
- **WhisperX 在 RTX 4090 上的 RTF**（large-v3 + FP16，2026 实测数据）：
  - 仅转录：**72×**
  - + 词级对齐：**60×**
  - + diarization（pyannote）：**30×**（即 1h 音频 ~2 分钟处理完）
  - 注：之前文档写"70× 实时（large-v3-turbo）"是 WhisperX 官方 README 对应 **large-v2** 的数字；large-v3 + 完整流水线实际 30×。
- **pyannote 3.1 DER**（2025-09 官方 benchmark，已按数据集分项；之前文档写 "~12-15%" 过于乐观）：
  - AISHELL-4：12.2%；**AMI (IHM)：18.8%**；AMI (SDM)：22.7%；DIHARD 3 (full)：21.4%；VoxConverse v0.3：11.2%；CALLHOME：28.5%
  - **新版本**：`community-1`（开源，~3-9% 绝对降幅）和 `precision-2`（**premium**，AMI IHM 12.9% / DIHARD 3 14.7%，约 30-40% 相对降幅）已发布；本平台 P1 的 `voice-diarization` 应**优先用 community-1**（开源 + 更准），保留 3.1 作为兼容档。
- **国内 ASR 首选**：SenseVoice-Small（234 M，Apache-2，ModelScope 直拉，含情感标签）；Paraformer-Large。
- **Vibe（5.8k★ MIT，最新 v3.0.19 2026-03）+ Buzz（19k★ MIT，最新 v1.4.4 2026-03）** = 桌面端开源转录的双标杆，但都**不该被移植**——它们应该改接统一平台核心应用的 `/v1/audio/transcriptions` API。Vibe = Tauri 2 + TypeScript + Rust + Python；Buzz = Python + PyQt。

## 七、与 Olares Team 应对齐的事项

1. **`whisperwebuiv2` 与统一平台核心应用的对外定位说明** —— 避免用户认知冲突
2. **`whisperwebuiv2` 是否继续维护** —— 决定是否要新建 `voice-stt-pro` 重型替代品
3. **`ollamav2` 的 sharedEntrance 是否对其它应用开放调用** —— 影响统一平台核心应用调 LLM 的实现成本
4. **集群侧 GPU 资源池现状** —— 决定 `voice-stt-pro` / `voice-diarization` 等高 GPU 应用是否能跑
5. **LarePass Service Provider SDK 时间表** —— 影响第三阶段 LarePass 内嵌的实现

## 八、一行结论

> **"语音转录"不再是一个独立产品，而是统一语音 AI 平台的 8 个 API 用例**（文件转录 / 翻译 / URL / 字幕 / 摘要 / 会议 / 长音频 / 跨笔记 RAG / 说话人分离 / 强制对齐）。原"自研 AI 语音笔记本"形态变为"核心应用 Web UI 笔记面板 + 移动 PWA"，第二 + 第三阶段交付。**第一阶段（2 个月内）就能让用户上传文件出文稿 + 摘要**，整体 4–6.5 个月跑通核心场景；移动端 + 跨笔记 RAG 是长期路线。

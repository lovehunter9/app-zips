# 风险与开放问题

> 把本课题在"落地为 Olares 应用"过程中可能踩的坑、需要决策但暂未决策的事项整理在此。按 6 类组织。

> **⚠️ 已锚定到统一平台**：本文 30+ 条风险是"语音转录用例"层面的；与统一平台 41 条风险（[`../voice-ai-platform-docs/04_风险与开放问题.md`](../voice-ai-platform-docs/04_风险与开放问题.md)）并行。如两文档结论冲突，**以统一平台文档为准**——特别是 whisperwebuiv2 处置、Qwen 优先、声音克隆决策等四条已锁定决策。

## 一、技术风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 1 | **GPU 内存峰值** | Whisper-large + pyannote + 翻译 NLLB + LLM 摘要并发可超 22 GiB | 任务串行化；分流到不同应用；档位化（入门/主流/专业） |
| 2 | **长任务 HTTP 超时** | Olares Nginx Ingress 3-5 min 超时；1 h 音频转录跑不完 | 强制异步任务 + polling/SSE/WebSocket |
| 3 | **上传带宽** | 1 h MP4 视频可达 1 GB；家用上传带宽通常 10-50 Mbps | 客户端 FFmpeg.wasm 抽音轨；chunk upload |
| 4 | **pyannote HF token license** | 必须用户手动接受 `pyannote/speaker-diarization-3.1` license | OlaresManifest 文档化；首次启动引导 |
| 5 | **模型缓存膨胀** | Whisper-large + distil + pyannote + NLLB 等可达 20+ GiB | hostPath PVC ≥ 50 GiB；按需下载 |
| 6 | **流式 WebSocket 跨 Ingress 稳定性** | 家用网络中长 WS 连接易断 | 心跳 + 重连协议；优先 HTTP polling |
| 7 | **多用户并发 GPU 竞争** | 同一 GPU 多任务排队 | 任务队列 + 优先级 + 限流；按 user 配额 |
| 8 | **音视频格式兼容性** | 部分 MP4/MOV 编码 Whisper 解不开 | 容器内自带 FFmpeg；前端格式校验 |
| 9 | **中文 + 中英混合识别质量** | Whisper 在纯中文 / 中英混合 / 方言场景明显弱于 SenseVoice/Paraformer | 支持引擎切换；中文场景默认 SenseVoice |
| 10 | **说话人分离质量** | pyannote 3.1 在嘈杂会议 + 4+ 说话人场景仍有 15-25% DER | 提供"手动校正"UI；不要营销"100% 自动准确" |

## 二、产品 / 定位风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 11 | **`whisperwebuiv2` 与新增应用重叠** | 用户分不清"通用转录 GUI vs AI 笔记本" | **已被统一平台决策覆盖**：whisperwebuiv2 不扩展，定位"独立 GUI 转录工具"；本平台用例由 `voice-ai-hub` 核心应用 + 自家 ASR 矩阵承担，两者职责清晰互不冲突；详 [`../voice-ai-platform-docs/04_风险与开放问题.md`](../voice-ai-platform-docs/04_风险与开放问题.md) §三 Risk 14 |
| 12 | **不与 SaaS 直接竞争** | Otter/Fireflies/Read.ai 的核心优势是会议机器人；Olares 不该跟 | 明确定位"个人 / 私密 / 不上云"，不做会议机器人 |
| 13 | **国内场景与海外样本差异** | 国内用户更在乎中文准确率 + 行业术语；通义听悟/讯飞听见的体验难以本地化复制 | 在中文 ASR 引擎（SenseVoice）+ 中文 LLM 摘要（Qwen3）上重点投入 |
| 14 | **个人 AI 笔记本"小众"风险** | 这一形态在西方流行（AudioPen 用户数 5w+），国内市场认知度低 | 在 LarePass / 移动端集成后才能放大用户量 |
| 15 | **与 Olares 现有"通用笔记应用"（Joplin、Memos、AppFlowy）边界不清** | 用户已经有笔记，再装"语音笔记本"会问"为什么不直接在原笔记里加录音" | 设计成"语音→AI 整理→可导出到 Joplin/Memos"，做"AI 入口"而非"另一个笔记仓库" |

## 三、合规 / 许可证风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 16 | **pyannote 3.1 license** | 实际为 MIT，但要求 HF token 接受 gated terms | 文档化；自动化引导 |
| 17 | **NLLB-200 商用限制** | CC-BY-NC-4 严格商用受限 | 长期换 Qwen3 LLM 翻译 |
| 18 | **Cohere Transcribe license** | 部分受限 | 仅用作"实验性引擎"，不做默认 |
| 19 | **Whisper 模型 license** | MIT（自由）；但 distil 衍生品 license 需确认 | 选 MIT 衍生 |
| 20 | **GDPR / HIPAA 等数据合规** | 自托管转录医疗 / 法律敏感数据需文档化合规边界 | OlaresManifest 中明示"非医疗设备 / 非法律证据级" |
| 21 | **录音法律** | 中国大陆: 单方录音合规；某些国家需双方同意 | 应用启动提示 + 文档化用户责任 |

## 四、运营 / 维护风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 22 | **上游 `jhj0517/Whisper-WebUI` 维护节奏不一致** | 上游半年内迭代 6-8 次，但每次小幅；fork 维护成本上升 | 自动化 rebase；定期同步上游 |
| 23 | **WhisperX 上游不再维护风险** | `m-bain/whisperX` 2024 末较活跃但 commit 频率下降 | 关注社区 fork（如 `jianfch/stable-ts` 等）作为备份 |
| 24 | **国内模型权重不稳定** | SenseVoice / Paraformer 在 ModelScope 上，海外用户下载慢 | OlaresManifest 中支持多镜像源 |
| 25 | **GPU 驱动兼容性** | CUDA / Vulkan / Metal 在不同 Olares 节点上行为差异 | 推荐 NVIDIA + faster-whisper（最成熟） |

## 七、本章结论

1. **技术上的硬约束 4 件事**：GPU 内存峰值、长任务超时、上传带宽、模型缓存膨胀。
2. **产品上的硬约束 2 件事**：与 `whisperwebuiv2` 重叠 / 与 SaaS 不竞争。
3. **合规 2 件事**：pyannote token、NLLB CC-BY-NC 商用受限。
4. **10 个开放问题** 大多可在每个阶段开始前决策，不必在路线起点都定。
5. **建议**：先按推荐路线第一阶段（补集群侧底座）落地，半年内根据数据 + 用户反馈再回到本章重新评估。

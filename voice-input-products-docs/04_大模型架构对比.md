# 大模型架构横向对比

> 本文件把 §00 §2.4 服务端选项 列出的 10 个端侧推理引擎 + 17+ 个核心 ASR 模型 + 7 个 OpenAI 兼容服务端封装 + 12+ 家云 ASR + 9 个 LLM 后处理供应商按统一维度做横向对比，落脚到"Olares 集群可部署性"与"候选方案选型"。

## 一、方法与置信度

### 1.1 维度（8 维）

| # | 维度 | 含义 |
|---|---|---|
| M1 | **参数规模 / 模型体积** | params（M / B）+ 落盘大小（不同量化的 ONNX/GGML/CoreML） |
| M2 | **推理硬件** | CPU x86 / CPU ARM / NVIDIA CUDA / AMD ROCm / Intel/AMD Vulkan / Apple Metal / MLX / CoreML / NPU |
| M3 | **语种数** | 训练 + 推理实际可用语种 |
| M4 | **流式能力** | 完整 chunked / streaming / 仅 offline file |
| M5 | **许可证** | 模型权重 + 推理代码两份许可 |
| M6 | **量化形态** | FP32 / FP16 / INT8 / INT4 / GGML Q4/Q5/Q8 / CoreML Q4/Q8 |
| M7 | **国内可获得性** | 模型权重 / 推理代码 / 配套云服务在国内能不能拿到、要不要梯子、是否被备案 |
| M8 | **Olares 集群可部署性** | 0=无法 / 1=改造可 / 2=直接装 / 3=已有 Helm chart |

### 1.2 限定与约定

- 模型版本以 **2025‑11 至 2026‑05 公开材料**为准；若有歧义优先取该项目在 重点 / 横向对比项目 中实际使用的版本（如 FluidVoice 用的 Cohere CoreML 1.4 GB 版）。
- 体积一律按 **该项目实际下载的格式**（FluidVoice 用 CoreML、CapsWriter 用 ONNX、Whisperboard 用 WhisperKit 等），不强行换算。
- "Olares 集群可部署性"评分基于：是否有现成 Docker 镜像、模型许可证是否允许集群多用户、单实例 VRAM 是否在常见消费 GPU（8/12/24 GB）可承受范围、Helm chart 是否已有人写过。
- **不评估**主观使用体验、不打分（避免误导）。

## 二、端侧推理引擎横向对比（10 个）

> 引擎是"模型的运行时"。任何一个模型在不同引擎里跑，性能、量化、平台覆盖会差很多。

| `whisper-rs` / `transcribe-rs` / `vad-rs` | Rust binding | 同 whisper.cpp + ONNX | 同 whisper.cpp + 自家 ONNX 路径 | streaming + VAD | Handy Handy（`transcribe-rs` 0.3.8 + `vad-rs`）、横向对比项目 Murmur、Voquill 的 `packages/rust_transcription` | MIT | Rust/Tauri 圈事实标准；`transcribe-rs` 在自己上面屏蔽了 whisper-cpp / onnx 后端差异；feature flag：whisper-cpp / onnx / whisper-metal / whisper-vulkan / whisper-cuda / ort-directml `[高]` |
| Vosk（alphacephei） | Kaldi-based, C/C++ + Python/Java | 自家 Kaldi nnet3 `.zip` 模型包 | Linux / macOS / Windows / Android / iOS | **天然流式**（Kaldi-style chunk） | 对比项 #11 Vocalinux（VOSK 三引擎之一）、提名项目 Sayboard | Apache-2 | 老牌 Kaldi 系；中小模型 ~50 MB；Android IME 早期主力（Sayboard）`[高]` |
| `onnx-asr` | Python + ONNX Runtime | ONNX | CPU 高度优化（无 GPU 也快） | offline / chunk | hyprwhspr hyprwhspr（用来跑 Parakeet ONNX） | — | 小众但 hyprwhspr 选它说明在 Linux + 无 GPU 场景比 sherpa-onnx 还轻 `[中]` |

**引擎层关键观察**：

1. **三足鼎立**：服务端 = faster-whisper；中文 + 跨平台 = sherpa-onnx；Apple Silicon = WhisperKit + FluidAudio + MLX 三件套并存。
2. **唯一"全平台 + 全模型"的引擎不存在**。任何一家想做"覆盖 macOS + Windows + Linux + Android + iOS + 服务端"，都得用 2‑3 个引擎拼接（如 transcribe-rs 用 whisper-cpp 走桌面 + 用 ONNX 走轻量；Type4Me 用 sherpa-onnx 走 SenseVoice + MLX 走 Qwen3-ASR）。
3. **方案四 Olares 集群侧最干净的选择**是 **faster-whisper（服务端通用）+ sherpa-onnx（中文 / 多模型）** 二选或并列，因为它们都有现成 Docker 镜像、都开源 Apache-2/MIT、都可以多用户并发；CoreML / MLX 因为只跑 Apple Silicon，不适合 Olares 集群（除非 Olares 节点本身就是 Mac mini 集群——少数发烧友会这么搞但非主流）。`[高]`

## 三、模型横向对比（按家族）

### 3.1 OpenAI Whisper 家族

| 变体 | 参数 | 体积（GGML Q5） | 体积（CTranslate2 INT8） | 语种 | 流式 | 许可 | 备注 |
|---|---|---|---|---|---|---|---|
| `tiny` | 39 M | ~75 MB | ~78 MB | 99 | offline / chunk | MIT | 入门基线；移动端首选 |
| `base` | 74 M | ~140 MB | ~145 MB | 99 | 同上 | MIT | — |
| `small` | 244 M | ~480 MB | ~500 MB | 99 | 同上 | MIT | 桌面端首选默认 |
| `medium` | 769 M | ~1.5 GB | ~1.5 GB | 99 | 同上 | MIT | — |
| `large-v3` | 1550 M | ~3.0 GB | ~3.0 GB | 99 | 同上 | MIT | 准确率最强档 |
| `large-v3-turbo` | 809 M | ~1.6 GB | ~1.6 GB | 99 | 同上 | MIT | **2024‑10 发布**；large-v3 的 decoder 砍到 4 层；准确率近 large-v3 但快 8× `[高]` |
| `distil-large-v3` | 756 M | ~1.5 GB | ~1.5 GB | 99 | 同上 | MIT | 蒸馏自 large-v3；HuggingFace 上 `distil-whisper/distil-large-v3` `[高]` |
| `distil-medium.en` / `distil-small.en` | 394 M / 166 M | ~0.7 GB / ~0.3 GB | — | 仅英文 | 同上 | MIT | 英文场景 first pick |

**Whisper 家族特性**：

- **架构**：encoder-decoder Transformer，30 s 输入窗口的硬约束（这也是 WhisperIME 30 s 录音上限的根本原因）。`[高]`
- **流式**：原生不流式，所有"流式"靠 chunk + sliding window + 拼接策略（`ufal/whisper_streaming` 是 SOTA 策略，被 WhisperLive 等沿用）。
- **量化**：GGML 圈普遍 Q4/Q5/Q8 三档，Q5 是质量/体积平衡点；CoreML 圈通常只发 fp16 和 Q4。
- **国内**：模型权重在 Hugging Face，国内需镜像（如 `hf-mirror.com`）或挂梯子；模型本身权重 ≤ 3GB，CDN 加速即可。

### 3.2 NVIDIA Parakeet 家族

| 变体 | 参数 | 体积 | 语种 | 流式 | 许可 | 备注 |
|---|---|---|---|---|---|---|
| `parakeet-tdt-1.1b-v2` | 1.1 B（更早 0.6B 也有） | ~600 MB（CoreML） / ~1.5 GB（NeMo fp16） | 英文 only | **TDT 天然流式**（Token-and-Duration Transducer，2024 出） | CC-BY-4.0（**关键差异**） | 速度比 Whisper 快 50×（NVIDIA 自报）`[中]` |
| `parakeet-tdt-0.6b-v3` | 0.6 B | ~500 MB（CoreML） | 25 欧洲语种 | TDT 流式 | CC-BY-4.0 | 2025‑08 发布；多语种扩展；FluidVoice 默认 Apple Silicon 多语种 |
| `parakeet_realtime_eou_120m-v1`（**Parakeet Flash**） | 120 M | ~250 MB（CoreML） | 英文 only | streaming + EOU 检测（端点） | CC-BY-4.0 `[中]` | 2025‑10 发布；专为 dictation/realtime 设计；FluidVoice 的"最低延迟"档 |

**Parakeet 家族特性**：

- **架构**：**RNN-T 类（TDT 是其改进版）**——与 Whisper 的 encoder-decoder 不同，天然流式、低延迟，但训练数据完全是 NVIDIA 内部。
- **许可证陷阱**：CC-BY-4.0 要求**保留 NVIDIA Attribution**——商业部署到 Olares Market 时需在 manifest / UI 显式说明。`[中]`
- **国内**：模型权重在 HuggingFace（`nvidia/parakeet-*`），下载 ~500 MB，但国内需镜像；推理代码（NeMo / NVIDIA 自家 Python 栈）依赖 CUDA + PyTorch，Olares 集群部署需 NVIDIA GPU + CUDA 12+。
- **CoreML 版本**通过 FluidAudio 间接获得，但只能用于 Apple Silicon 桌面。

**FunAudioLLM 家族特性**：

- **架构**：SenseVoice 是 Non-Autoregressive（NAR）Encoder + CTC，因此推理只需要一次前向传播，**比 Whisper 快 15‑50×**（官方 paper 数字 `[中]`）。
- **许可证**：清一色 Apache-2，**对商业部署最友好**。
- **国内可得性**：**最佳**——HuggingFace + ModelScope 双仓托管，模型在国内 ModelScope CDN 上拉无需梯子；推理代码也都开源。
- **缺陷**：英文准确率不如 Whisper-large-v3-turbo；多语种覆盖不如 Parakeet TDT v3；体积也比 distil-whisper 大。

> **方案四 Olares 集群最佳默认引擎**：SenseVoice-Small（~228MB，中文 + 5 语种 + 情感 + 事件，Apache-2，国内可直拉）。这是 CapsWriter 已经验证的事实选择。`[高]`

|---|---|---|---|---|---|---|
| `SFSpeechRecognizer`（老 API） | 系统内 | 0（系统自带） | 系统语言列表 | streaming（但需联网，除特定语言离线包） | Apple SDK | macOS 10.15+ / iOS 10+；多年来主力 |
| **`SpeechAnalyzer` / `SpeechTranscriber`（macOS 26+）** | 系统内 | 0 | 系统语言列表 + 新增多语种 | **streaming + 完整离线** | Apple SDK | **2025 WWDC 发布**；macOS 26（Tahoe）+ iOS 26 起；接到 Apple Intelligence 本地 LLM 做上下文感知 ASR；FluidVoice / 横向对比项目 多家可挂 `[高]` |

**Apple Speech 家族特性**：

- **架构**：闭源，但根据 WWDC 公开材料是"端侧 Transformer + Apple Intelligence Foundation Model 后端"；估算与 distil-whisper-medium 同级。
- **国内可得性**：在国行 macOS 上**可用但语种受限**——Apple Intelligence 在中国大陆暂未上线（截至 2026‑05），SpeechAnalyzer 的部分高级特性（如上下文修正）在中国账号下可能不可用。`[中]`
- **Olares 部署**：N/A（只能在 Apple 设备客户端用）。
- **意义**：对桌面端 方案五 路径有重大影响——Mac 用户的"无需下载、零配置、原生体验"备选基线就是 SpeechAnalyzer，第三方 ASR 必须证明"比 Apple 系统的快/准/隐私更好"才有用户黏性。

- **意义**：Cohere 是少数"多语种精度对标 large-v3 但速度快 5‑10×"的选项——但其许可证不友好让它**不适合 方案四 默认选型**。

### 8.2 Olares 集群部署的关键约束

1. **GPU 节点假设**：Olares 是个人云 OS，**默认假设 0‑1 张消费 GPU**。设计时不应假设 A100/H100。
2. **模型分发**：Olares Market 应用包大小 ≤ 10 GB 是软上限（超过要在 first-run 时下载，类似 ollamav2 的做法）。
3. **多用户并发**：家用场景同时 1‑3 个用户上限，无需自建复杂调度。
4. **CPU fallback**：对 SenseVoice / Whisper-tiny / Moonshine 这类小模型，纯 CPU 也能跑（特别适合 Olares 在 Raspberry Pi 5 / NUC 等无 GPU 节点上跑）。

### 8.3 给 方案四 的部署建议

- **第一版**：直接复用现有 **`speaches`** 应用（Whisper-large-v3-turbo），sharedEntrances 暴露 OpenAI 兼容 endpoint；让 方案五 的桌面客户端把 baseURL 改过来即可工作。
- **第二版**：新增 **`olares-funasr`** 应用（基于 sherpa-onnx + SenseVoice-Small，CapsWriter Server 端做参考），中文场景默认走这家；OpenAI 兼容 endpoint 与 speaches 二选一。
- **第三版（可选）**：加 **`olares-parakeet`**（NVIDIA NeMo + Parakeet TDT v3）—— 多语种 + 流式 + GPU；可选安装。
- **LLM 后处理**：独立挂在 Olares 已有的 **`ollamav2`** 上，Qwen2.5-7B-Instruct-AWQ 作为默认；不要绑死在 ASR 服务里。

## 十一、一句话结论

> **方案四 Olares 集群 ASR 后端的最佳默认组合 = `speaches`（Whisper-large-v3-turbo）+ 一个新增的 `olares-funasr`（SenseVoice-Small）双部署，搭配已有的 `ollamav2` 跑 Qwen2.5-7B 做 LLM 后处理**——三个组件加起来 ≤ 6 GB 模型 + ≤ 8 GB VRAM，能覆盖 80% 的中英 + 多语种 + LLM 润色场景；剩下 20% 的细分场景（流式低延迟、高精度多语种、繁体中文等）通过 方案五 第三方桌面客户端走云 API（火山 / Groq / Parakeet 私有部署）兜底。

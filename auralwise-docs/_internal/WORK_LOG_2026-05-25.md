|---|---|---|

v2 做了什么：

### 3.1 主动 HTTP 探测（最大杀手锏）

```
$ curl -sSI https://api.auralwise.cn/
Server: Tengine
X-WAF: true
Via: cache23.l2cn3163[...], kunlun6.cn6489[...]
Ali-Swift-Global-Savetime: ...
EagleId: ...
Set-Cookie: sl-session=...
Access-Control-Allow-Headers: Authorization, Content-Type, X-API-Key, X-Node-Token

$ curl https://api.auralwise.cn/v1/nonexistent
404 page not found

$ curl https://api.auralwise.cn/v1/tasks
{"error":"authentication required: provide Authorization: Bearer \u003ctoken\u003e or X-API-Key"}
```

**三个独立指纹一次拿齐**：

| 指纹 | 唯一锁定 | 凭什么是"指纹级" |
|---|---|---|
| `404 page not found` 纯文本 | Go 标准库 `http.NotFound` | 这是 Go `net/http` 的字面输出，其它语言/框架默认不会写成这样 |
| 错误 JSON 里 `<` 被转义成 `\u003c` | Go `encoding/json` 默认 `HTMLEscape(true)` | Python `json.dumps` 默认不转义、Node `JSON.stringify` 默认不转义，**只有 Go 默认这么干** |
| `Server: Tengine` + `EagleId` + `kunlun*.cn6489` + `X-WAF` + `sl-session` cookie | 阿里云 CDN + 阿里云 WAF | Tengine 是阿里云专属 Nginx fork，EagleId/kunlun 是阿里云节点编号；sl-session 是 WAF 注入（不是应用 session） |

### 3.2 SSL cert 给了惊喜

```
$ openssl s_client ... | openssl x509 -noout -subject -issuer
subject=CN=auralwise.com    ← .com 也是他们的！
issuer=Let's Encrypt R13    ← 90 天周期，acme.sh / Caddy 风格自动续签
```

→ 之前不知道有 `.com` 域，这下知道了。`.com` 域被阿里云 WAF challenge（HTTP 468）拦着，可能是出海/品牌占位。

### 3.3 端点枚举

```
GET /v1/audio-event-classes  -> 401  (存在但需要 key，反爬)
GET /v1/billing/transactions -> 401
GET /v1/{login,me,users,api-keys,health,healthz,metrics,version,register}
                              -> 404  (账户管理 API 完全不在 api.auralwise.cn)
```

→ 公开 API tier **只暴露 task + audio-event-classes + billing 三组**。账户管理走 SPA 同源的另一组路由（很可能同一个 Go 二进制按 vhost 分流），与开发者 API 物理分离。

CORS `Allow-Headers` 里的 `X-Node-Token` → **worker → API 回写结果的内部共享密钥**，证实"Go 薄 API + Python 厚 ML worker"分层。

### 9.4 续场的小复盘

1. **"删 v1/v2"是个迟到的认知**：我在 v2 出炉的时候应该就意识到 v1 的叙述已经没有保留价值——读者关心的是"现在你怎么判断"，不是"你怎么走到这里的"。下次写阶段性深化文档时，**v(n+1) 出炉就应该直接把 v(n) 的过程性叙述压成附录或者删掉**，不要保留两层叠加。

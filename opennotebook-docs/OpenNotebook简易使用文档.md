# OpenNotebook 简易使用文档

本文档以实际 UI 为准，指导在 Olares 平台上部署的 OpenNotebook 如何从零开始配置和使用。涵盖模型配置、核心概念、来源与笔记管理、Chat、询问与搜索、播客、转换等完整功能，以及推荐工作流程。

## 二、核心概念：三层结构

Open Notebook 按三层结构组织内容：

```
┌──────────────────────────────────────────────────┐
│  笔记本 Notebook（容器/项目）                    │
│  例："量子计算入门研究"                          │
├──────────────────────────────────────────────────┤
│  来源 Sources（原始素材，不可修改）              │
│  ├─ 论文.pdf                                     │
│  ├─ YouTube 视频链接                             │
│  └─ 网页文章链接                                 │
│                                                  │
│  笔记 Notes（加工后的知识，可编辑）              │
│  ├─ AI 摘要（自动生成）                          │
│  └─ 我的研究心得（手写）                         │
└──────────────────────────────────────────────────┘
```

- **笔记本**：一个研究项目的容器，各笔记本完全隔离
- **来源**：添加进来的原始材料，一旦添加不可修改
- **笔记**：从来源中提炼出的知识，可以编辑和完善

## 三、创建笔记本（实操）

步骤：

1. 打开 Open Notebook 首页
2. 点击 **"New Notebook"**（"创建笔记本"）
3. 填写信息：
   - 名称：例如 `量子计算入门研究`
   - 描述：例如 `收集量子计算基础概念、最新进展和应用前景的资料`
4. 点击 **Create New Notebook**

**描述很重要**——它为 AI 提供上下文，当你在笔记本中对话时，AI 会知道你在研究什么。

## 四、添加来源 Sources（实操）

进入你的笔记本后，你可以通过多种方式添加来源——支持直接为笔记本"添加来源"，也可以先在来源处添加来源后，在笔记本处"添加现有来源"。

[图片]

[图片]

### 4.1 上传文件（PDF/Word/PPT/音频）

示例：上传一篇名为 `A Minimal Introduction to Quantum Computing.pdf` 的论文，关联到"量子计算入门研究"笔记本，选择 Dense Summary 转换，开启向量嵌入。完成后系统会自动提取文本、切分段落、生成向量嵌入并存入数据库。

**步骤一：添加来源（上传文件）**

1. 在笔记本界面点击 **"+ 添加来源"**
2. 选择 **"上传文件"** 标签页
3. 从电脑选择文件（支持格式见下表）
4. 标题可留空，系统会根据内容自动生成
5. 点击 **"下一步"**

**支持的文件格式**：

| 类型 | 格式 |
|---|---|
| 文档 | PDF、DOCX、TXT、MD、PPT/PPTX |
| 音频 | MP3、WAV、M4A |
| 视频 | MP4 |
| 其它 | 以实际 UI 支持为准 |

[图片]

**步骤二：选择笔记本（可选）**

选择要将此来源关联到哪个笔记本。可勾选一个或多个已有笔记本，也可跳过此步稍后再关联。选好后点击 **"下一步"**。

[图片]

**步骤三：处理设置**

- **转换（可选）**：选择 AI 对内容的处理方式，可多选：

| 转换名 | 用途 |
|---|---|
| Dense Summary | 生成深度摘要（标"默认"） |
| Key Insights | 提取关键见解和可执行要点 |
| Analyze Paper | 学术/技术论文分析 |
| Reflections | 生成思考性问题 |
| （可自建） | 见第九节 |

**特别说明**：虽然可以多选，但是对于单卡本地模型处理而言，同时处理几个来源和多个处理方式可能会带来资源压力，导致时间过慢、重复生成、卡死甚至报错。本文档中勾选多个处理方式（包括批量处理多个 URL）仅为功能演示示意，**建议一次只处理一个来源的一个处理方式**，后续可以进入来源的"见解"标签页，通过"**生成新见解**"功能使用其它处理方式。

[图片]

- **设置**：
  - **启用搜索向量嵌入** — 勾选后可在向量搜索和 AI 对话中检索该来源（建议保持开启）

[图片]

[图片]

**实操示例**：

假设你的笔记本里有 3 个来源：

- `量子计算综述.pdf`（主要研究对象）→ 设为 **Full Content**
- `量子力学基础.pdf`（背景知识）→ 设为 **Summary Only**
- `某公司内部文件.pdf`（敏感）→ 设为 **Excluded**

**你的问题**：

> 根据量子计算综述论文的方法论部分，量子纠错的三种主要方法分别是什么？请引用论文中的具体页码。

AI 会基于论文全文给出回答，并附上引用。

### 6.3 对话策略

**逐步深入**：

```
第 1 轮：这篇论文的核心论点是什么？
第 2 轮：方法论部分有什么创新之处？
第 3 轮：与传统方法相比，这种方法的优劣势是什么？
第 4 轮：作者承认了哪些局限性？
```

**跨来源对比**：

> 论文 A 和论文 B 在量子纠错方面的方法有何不同？哪种方法在实际应用中更可行？

### 6.4 验证引用

AI 回答中会标注引用来源。你可以：

1. 点击引用链接
2. 查看原文中的相关段落
3. 确认 AI 的陈述是否准确

如果 AI 没有给引用，可以追问：

> 请为这个说法提供来源中的具体引用。

## 七、询问与搜索（实操）

### 7.1 先认路

左侧边栏 → **处理** → **询问与搜索**。进去后顶部有两个 tab：

- **提问 (beta)** — 问一句话，LLM 自动检索你的知识库、给出带引用的完整答案
- **搜索** — 关键字或向量查询，返回匹配片段列表

两个 tab 是**并列**关系，根据你要的是"现成答案"还是"自己扒资料"选一边。

[图片]

### 7.2 提问 (beta) —— 让 LLM 替你搜 + 答

面板上能看到的东西：

| UI 元素 | 作用 |
|---|---|
| **问题**（大 textarea） | 用自然语言写你的完整问题 |
| **按 Cmd/Ctrl+Enter 提交** | 快捷键 |
| **正在使用默认模型** | 当前这轮用的三个模型 |
| **策略: xxx / 回答: xxx / 最终: xxx** | 三个模型标签，分别对应不同阶段 |
| **高级**（右上齿轮按钮） | 临时覆盖这三个模型，不想碰全局默认就在这里改 |
| **提问**（蓝色大按钮） | 跑起来 |

**三个模型各干啥**（这是 OpenNotebook 的设计，比普通 RAG 复杂）：

| 模型槽位 | 作用 | 选模型原则 |
|---|---|---|
| **策略 Strategy** | 看你的问题，拆出要搜什么（生成若干子查询 + 决定搜哪些 source） | 用**便宜快**的中等模型就够，拆问题不需要很强 |
| **回答 Answer** | 拿到检索到的每段内容，对每段出一个局部答案 | 中等即可；多段并行调用，节省成本比智商重要 |
| **最终 Final** | 把所有局部答案综合成一个带引用的完整回答 | 用你**最强**的那个模型，这步决定输出质量 |

**操作流程**：

1. 输入问题，例：`对比我笔记里超导、离子阱、光子三种量子计算硬件路线的优劣`
2. 默认模型能应付就直接点"提问"
3. 想换模型就点右上角**高级**，覆盖策略/回答/最终的模型选择
4. 等 10-30 秒
5. 页面给出：策略 + 独立回答 + 最终回答 + 保存到笔记本按钮

**注意**：提问 mode 是 **beta**，界面上明确标了。行为偶尔抽风很正常，卡住就刷新重试——实测确实不够稳定，易报错，且界面输出并不友好易用。

### 7.3 搜索 —— 自己扒关键字或概念

切到"搜索"tab，面板长这样：

| UI 元素 | 作用 |
|---|---|
| **搜索框 + 搜索按钮** | 输入 + 回车 / 点击触发 |
| **按 Enter 键搜索** | 快捷键 |
| **搜索类型**（radio） | ● 文本搜索 / ○ 向量搜索（二选一） |
| **搜索范围**（checkbox） | ☑ 搜索来源 / ☑ 搜索笔记（可同时勾，默认两个都勾） |

**文本搜索 vs 向量搜索怎么选**：

| 情况 | 选 | 例子 |
|---|---|---|
| 记得原话 | 文本搜索 | `量子纠缠` / `Shor 算法` / `Bell 不等式` |
| 忘了原话只记意思 | 向量搜索 | `粒子之间的神秘关联` → 能搜到量子纠缠 |
| 两者都搜不到 | 先文本再向量切着试 | — |

**向量搜索需要 embedding 模型配好**——我们 Olares 部署之前卡的那个坑：如果 Models 页没配 embedding（或配错了把 chat 模型当 embedding 用），向量搜索永远 0 结果，不会报错只是空白。

### 7.4 两种模式实战对照

**场景 A：我记得某句话，想找原文**

```
用：搜索 tab → 文本搜索
输入：量子纠缠
→ 命中含这四个字的所有 source/note 片段
```

**场景 B：我想探索一个概念，不确定术语**

```
用：搜索 tab → 向量搜索
输入：粒子之间的神秘关联
→ 命中 quantum entanglement / Bell 不等式 / EPR 佯谬等相关内容
```

**场景 C：我要一份对比报告，不是片段**

```
用：提问 (beta) tab
输入：对比我笔记里 Shor 算法、Grover 算法、量子退火三类量子算法
     的适用场景和当前硬件可行性
→ 10-30 秒后得到带引用的综合分析，一键存成笔记
```

### 7.5 常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| 向量搜索永远空 | Embedding 模型没配 / 配错 | Models 页补一个真正的 embedding 模型（推荐 Ollama nomic-embed-text） |
| 提问报错或空 | 策略/回答/最终里某一项模型没配 | 点**高级**看是不是某个槽位显示"未配置"，Models 页补上 |
| 提问跑得太慢 | 策略/回答模型太重 | 点**高级**把这两个换成小模型（如 9B），最终模型才用大模型 |
| 搜索结果不对劲 | 勾错了范围 | 看搜索范围的两个 checkbox 是不是按需要勾 |

## 八、播客（实操）

### 8.1 先认路

左侧边栏 → **创作** → **播客**。进去顶部有 "选择视图" toggle：

- **单集** — 已生成/在跑/失败的所有播客任务列表（管理产出）
- **配置** — "简介工作区"，管理**发言人简介**和**单集简介**两种可复用模板

**操作闭环：先在"配置"里建好两种简介 → 回"单集"点生成 → 等跑完下载**。

> 页面顶部的黄色警告 **需要配置 - 部分配置尚未设置模型** 意思是某个简介还没指定模型（大纲模型/脚本模型/TTS），要先去"配置"把那个红色 ⚠️ 的卡片补全才能生成。

### 8.2 配置视图 —— 先建两种"简介"

切到"配置"tab，页面中部进入"简介工作区"，左右两栏分别管理**发言人简介**和**单集简介**。顶部有一个可折叠的 **"💡 简介如何驱动播客生成"** 帮助框，展开后能看到官方给的关系说明。

两种简介的关系可以一句话说清楚：

> **单集简介**（菜谱）引用一个**发言人简介**（配音阵容 + TTS），再配合大纲模型 / 脚本模型 / 分段数量 / 默认简报，组合成一个可复用的生成配方。

它们是**一对多**关系：一个发言人简介可以被多个单集简介引用；一个单集简介只引用一个发言人简介。

#### 8.2.1 发言人简介（Speaker Profiles）

**干啥**：定义一组**配音阵容**——一个发言人简介里装了**一个或多个** speaker，节目形式由 speaker 数量决定：

| Speaker 数 | 节目形式 | 系统自带示例 |
|---|---|---|
| 1 | 独白 / 科普 | `solo_expert`（Professor Sarah Kim 一位） |

#### 8.2.2 单集简介（Episode Profiles）

**干啥**：定义一期播客的**生成配方**，由若干模型槽 + 引用的发言人简介 + 默认简报 prompt 组成。

**卡片结构**：

```
┌────────────────────────────────────────────────────┐
│ 单集简介名字  [⚠️ 需要配置]          🖊 编辑    ⋮ │
│ 描述                                                │
├────────────────────────────────────────────────────┤
│  大纲模型                  脚本模型                  │
│  openai / gpt-5-mini       openai / gpt-5-mini      │
│                                                     │
│  分段数量                  主持人简介                │
│  6                         business_panel  [TTS]    │
│                                                     │
│  默认简报                                            │
│  Analyze the provided content from a business       │
│  perspective. Discuss market implications...        │
└────────────────────────────────────────────────────┘
```

**字段清单**：

| 字段 | 作用 | 例子 |
|---|---|---|
| 名字 | 简介标识 | `business_analysis` / `solo_expert` / `tech_discussion` |
| 描述 | 副标题 | `Business-focused analysis and discussion` |
| **大纲模型** | 写节目大纲的 LLM（主题拆分、流程设计） | `openai / gpt-5-mini` |
| **脚本模型** | 把大纲改写成多角色对白的 LLM（脚本质量更关键，可以上更重的） | `openai / gpt-5-mini` |
| **分段数量** | 一期分多少段 / 主题块 | `4 / 5 / 6` |
| **主持人简介** | **引用一个发言人简介**（下拉选）；TTS 模型从该简介继承显示 | `business_panel` `openai / gpt-4o-mini-tts` |
| **默认简报** | **一段 prompt 文本**，告诉 LLM 这期节目应该怎么分析内容、从什么视角切入、强调什么 | 见下方示例 |

> 单集简介里**没有独立的 TTS 字段**——TTS 模型完全从"主持人简介"里继承。想换 TTS 就去改被引用的发言人简介（或者建一个新的发言人简介，再回来把主持人简介换过去）。

**默认简报示例**（系统自带 episode profile 里的内容，可以直接拿来改）：

```
# business_analysis 的默认简报
Analyze the provided content from a business perspective.
Discuss market implications, strategic insights, competitive
advantages, and actionable business intelligence.
```

```
# solo_expert 的默认简报
Create an educational explanation of the provided content.
Break down complex concepts into digestible segments, use
analogies and examples, and maintain an engaging teaching style.
```

```
# tech_discussion 的默认简报
Create an engaging technical discussion about the provided
content. Focus on practical insights, real-world applications,
and detailed explanations that would interest developers and
technical professionals.
```

**写"默认简报"的经验**：

- 写清**分析视角**（商业 / 技术 / 教育 / 学术 / 科普……）
- 写清**语气和受众**（面向开发者 / 面向完全外行 / 面向投资人……）
- 可以列出希望覆盖的维度（如"市场影响、技术细节、实际应用案例"）
- 保持在 2-5 句话，过长容易让 LLM 抓不住重点

**选模型和分段的经验**：

- **大纲模型和脚本模型不用同一个最强的**——大纲可以用便宜快模型，脚本再上重的
- 分段数量 4-8 比较自然。2-3 段短平快，10+ 段容易啰嗦
- **主持人简介里的 speaker 数量决定节目形式**：1 人独白、2 人对谈、3-4 人圆桌
- **TTS 继承自主持人简介**——Olares 部署里基本就是 Speaches/Kokoro（本地、免费）；配了 OpenAI Key 的也可用 `gpt-4o-mini-tts`

**系统自带的三个单集简介**：

| Episode Profile | 分段数 | 引用的发言人简介 | 用途 |
|---|---|---|---|
| `business_analysis` | 6 | `business_panel`（3 人） | 商业圆桌深度分析 |
| `solo_expert` | 4 | `solo_expert`（1 人） | 单人科普教学 |
| `tech_discussion` | 5 | `tech_experts`（2 人） | 技术对谈 |

都标着 ⚠️ 需要配置——**点编辑把模型换成你实际能用的**（Olares 部署要改成 Ollama 直连模型 / TensorZero / Bifrost 代理后的模型，或正确配好的 OpenAI Key）就能直接用，不用从零建。

### 8.3 单集视图 —— 跑起来 + 看状态

切回"单集"tab，顶部有 **生成播客** 和 **刷新** 两个按钮，下面是单集概览统计（总计 / 处理中 / 已完成 / 失败 / 排队中）。

#### 8.3.1 生成一期

切回"单集"tab，点右上角 **生成播客** 按钮 → 弹框里选：

- **来源**：勾选要纳入本期播客的 source / note（建议 3-5 个，例如"量子计算入门研究"笔记本里的 3 篇关键论文）
- **单集简介**：选一个你在 8.2.2 建好的（如 `quantum_intro`）
- 确认 → 开跑

**跑之前先确认两件事**：

- 单集简介里所有模型槽位都填了（不然卡片标着红色 ⚠️，会直接失败）
- 要用的来源都已处理完成（source 卡片状态绿色 Ready）

#### 8.3.2 生成中的状态

开跑后任务会出现在"单集概览"列表里，状态依次是：

```
排队中 → 处理中（大纲 → 脚本 → 语音合成 → 混音） → 已完成 / 失败
```

**不阻塞**：可以关页面去干别的，回来点"刷新"看状态。

**典型耗时**（3-5 source + 2 人 20 分钟目标）：

- 大纲 + 脚本：2-5 分钟
- TTS 语音合成：5-15 分钟（主要耗时，取决于 TTS 提供商和 speaker 数量）
- 混音输出：1-2 分钟

#### 8.3.3 产物

跑完后单集卡片能做这几件事：

- 浏览器直接播放
- 下载 MP3
- 查看/导出完整对话文字稿
- 如果不满意 → 重新生成（可以换简介再跑一次，原素材不用重选）

#### 8.3.4 失败了怎么办

看失败单集的报错：

| 报错关键词 | 问题 | 处理 |
|---|---|---|
| model not configured / 404 on /v1/... | 大纲/脚本模型配错 | Models 页测试，再回单集简介补 |
| TTS error / timeout | TTS 提供商挂了或 Voice ID 不存在 | 改发言人简介里的 Voice ID，或切到另一家 TTS |
| Speaches 端中途 502 / "peer closed connection" / "All connection attempts failed" / 单集跑一半失败 / 部分语音段 0 字节 | TTS 并发批量过高，本地单卡 Speaches 顶不住，pod OOM 或连接中断 | 检查 deployment 的环境变量 `TTS_BATCH_SIZE` 是否为 `1`（podcast-creator 上游默认 5，本仓库 Olares chart 已默认强制改为 1）；如果被覆盖成更大值，请改回 `1` 让 TTS 串行生成，代价仅是每个 clip 多 ~1s 墙钟时间 |
| Embedding / retrieval | 罕见，可能和 vector 检索有关 | 查 Models 页 embedding 配置 |
| 超时 / 卡住 | 素材太多或 TTS 拖太久 | 减 source 数量，或分段数量调小 |

## 九、转换 Transformations（实操）

### 9.1 先认路

左侧边栏 → **管理** → **转换**。页面标题"**内容转换规则**"，顶部 toggle：

- **内容转换规则** — 管理所有转换模板
- **实验室**（Playground）— 对着任意文本试跑一条转换，专门用来调 prompt

**关键理解**：这个页面本身只是**管理和调试转换模板**，不会对任何 source 产生影响。真正让一条转换跑在 source 上的入口在第 9.4 节。

### 9.2 内容转换规则视图

进入后从上到下：

#### 9.2.1 默认全局提示词（可折叠块）

"该提示词将被添加到您所有的转换提示词中"。

干啥：一段**全局前置指令**，会自动拼到每一条转换 prompt 的前面，适合写：

- 统一输出语气/风格（"用专业但不晦涩的中文输出"）
- 通用格式要求（"每一节用 markdown ## 标题"）
- 防拒答的兜底指令

新手可以不动，保留默认即可。

#### 9.2.2 自定义转换列表

右上角 **+ 新建转换** 按钮。下面是系统自带的 6 条转换模板：

| 自带转换名 | 描述 | 用途 / 备注 |
|---|---|---|
| **Analyze Paper** | Analyses a technical/scientific paper | 学术/技术论文深度解析 |
| **Dense Summary** | Creates a rich, deep summary of the content | 深度摘要，**系统默认转换**（标"默认"） |
| **Key Insights** | Extracts important insights and actionable items | 提取要点和可执行项 |
| **Reflections** | Generates reflection questions from the document to help explore it further | 从内容中生成启发性问题，帮你往深处想 |
| **Simple Summary** | Generates a small summary of the content | 简短摘要，比 Dense Summary 精炼 |
| **Table of Contents** | Describes the different topics of the document | 生成文档主题目录 / 章节清单 |

每张卡片**左侧的 ›** 可以展开看该转换的完整 prompt 内容；**右侧三个按钮**：

- **实验室** — 直接把这条转换送进实验室试跑（见 9.3）
- **编辑** — 改这条转换的配置（见 9.2.3）
- **🗑 删除** — 删

**"默认"标签**的含义：被标为默认的转换（Dense Summary）在**添加新 source 时会被系统自动勾选**，可以通过"编辑"打开或关闭这个开关；每次只能有一个转换是默认。

**怎么选用**：

| 场景 | 首选转换 |
|---|---|
| 想快速了解一篇文章主要讲什么 | Simple Summary |
| 想拿到完整、可引用的深度摘要 | Dense Summary |
| 要把一篇文章当知识资产来吸收 | Key Insights |
| 读学术 / 技术论文 | Analyze Paper |
| 想用它激发自己思考 | Reflections |
| 长文档想先快速看结构 | Table of Contents |

**推荐做法**：新 source 进来时先跑 Dense Summary 打底（系统默认已勾），后续有需要再进 source 的"见解"标签页用"生成新见解"补跑其它几条——见 9.4 入口 B。

#### 9.2.3 创建/编辑转换的表单

点 **+ 新建转换** 或某条卡片的 **编辑**，打开右侧抽屉。从上到下字段如下：

| 字段 | 必填 | 作用 |
|---|---|---|
| **名称** | ✔ | 转换的**唯一标识符**（建议用下划线小写，例如 `key_topics`、`paper_critique`）——系统内部和列表定位都靠它 |
| **标题** | ✖ | 列表卡片上显示的中/英文名，留空默认等于"名称" |
| **新来源默认建议**（标题右侧的 checkbox） | ✖ | 勾上后这条转换会**在添加新 source 时自动被勾选**（等同于列表卡片上的"默认"标签）；每次只能有一条转换是默认 |
| **添加描述** | ✖ | 卡片副标题那行小字，说明这条转换做什么用，例如 `Analyses a technical/scientific paper` |
| **系统提示词** | ✔ | 真正发给 LLM 的 prompt 模板——是转换的核心 |

**系统提示词编辑器**支持 Markdown 富文本，工具栏常用按钮：

| 按钮 | 作用 |
|---|---|
| **B / I / S** | 粗体 / 斜体 / 删除线 |
| 🔗 | 插链接 |
| ❝ | 插引用块 |
| `<>` / `{ }` | 插行内代码 / 代码块 |
| 🖼 | 插图片 |
| 🗒 | 插表格 |
| ☰ / 🔢 / ☑ | 无序列表 / 有序列表 / 任务列表 |
| ❓ | 内置帮助 |
| 右上三个视图按钮 | 仅编辑 / **分栏预览（默认）** / 仅预览 |
| ⛶ | 全屏 |

编辑区默认是**左边写、右边实时渲染**的分栏视图，写起来很顺手。

**"名称"和"标题"的区别**：

- **名称**：像变量名，用于程序识别（`key_topics`）。建成后**一般不要改**，改了可能影响已经引用它的地方。
- **标题**：对人类友好的展示名（`关键主题提取`），可以随时换，不影响识别。

**系统提示词写作经验**：

- 开头明确**这段 prompt 要做什么**（一句话目标），例如 `对以下文档提取 5-10 个核心主题，按重要性排序`
- 用 markdown 列表/小标题**写死输出格式**，别让模型自由发挥
- 要求引用页码 / 原文段落 → 后续检索可追溯
- 限定字数（"每项不超过 1 句话"）避免输出过长
- 加"**若某项信息缺失请写 '未提及'**" → 避免模型编造
- 写完**先去实验室**（9.3）贴一段真实样本试跑，看输出满意再保存

**系统提示词示例**（学术论文深度分析）：

```
针对这篇学术论文，请提取以下信息（用 markdown 输出）：

## 1. 研究问题
这篇论文要解决什么问题？

## 2. 假设
作者的核心假设是什么？

## 3. 方法论
使用了什么研究方法？请用 1-2 段简述。

## 4. 关键发现
列表形式，每项尽可能引用页码：
- 发现 1：...（p.X）
- 发现 2：...（p.X）

## 5. 局限性
作者承认了哪些不足？

## 6. 未来方向
建议了哪些后续研究？

要求：每节保持 2-3 句话。若原文未覆盖某节，请写"未提及"。
```

### 9.3 实验室（Playground）

切到"实验室"tab，面板三个输入：

| 字段 | 作用 |
|---|---|
| **转换**（下拉） | 选一条已有的转换规则 |
| **模型**（下拉） | 选一个 Language Model 跑 |
| **输入文本**（textarea） | 贴一段要处理的文本 |
| **▷ 运行转换** 按钮 | 开跑 |

**正确玩法**：

1. 拿一段你真实 source 的代表性片段（500-2000 字即可），贴进"输入文本"
2. 选刚建好的转换 + 打算批量用的那个模型
3. 点"运行转换"看输出
4. 输出不对劲就回"内容转换规则"改 prompt，再回实验室重试
5. 这样调 3-5 轮稳定后再去真实 source 上批量应用

好处很直接：**别等批量跑 20 个 source 才发现格式不对，实验室里一段一段试，便宜又快**。

### 9.4 怎么让一条转换真正跑在 source 上

"管理 → 转换"页本身不会对任何 source 产生影响。真正让转换跑起来，有两个入口（在 4.1 节的"步骤三"也有过描述）：

#### 入口 A：添加来源时一次性应用（最常用）

就是第四节 4.1 步骤三里那个"**转换（可选）**"勾选：

```
+ 添加来源 → 选文件/URL/文本 → 下一步 → 下一步
→ 处理设置页面
  → 转换（可选）：勾选 Dense Summary / Key Insights / Analyze Paper 等
  → 启用搜索向量嵌入（建议勾）
→ 完成
```

**优点**：一次搞定，不用回来补。

**注意**：本地单卡场景下，**一次只勾一个转换**最稳定；多勾容易资源争抢、超时、重复生成——这点你自己在 4.1 特别说明里已经强调过。

[图片]

#### 入口 B：事后在 source 的"见解"标签页补跑（最灵活）

```
打开某个 source（从笔记本里点进去，或从"采集 → 来源"进去）
→ 切到"见解"标签页
→ 点"生成新见解"
→ 选一条转换 + 选模型
→ 等待生成
→ 新见解追加到见解列表里
```

**什么时候用入口 B**：

- 添加来源时只勾了 Dense Summary，现在想再跑 Key Insights
- 以前没这条转换，后来自己建了一条，想追加到老 source 上
- 同一条转换想换个模型重跑一份做对比
- 之前跑失败了想重试

### 9.5 转换的产物：见解 Insights

转换跑完后产出的东西叫**见解 (Insights)**，**不是 Notes**。位置：

```
打开 source 详情 → "见解"标签页 → 按生成顺序列出所有见解
```

每条见解可以：

- 阅读 / 复制其内容
- 作为 Chat 的上下文被 AI 使用（source 在 Chat 里设为 Insights Only 时，AI 就只看到见解汇总，不看原文，省 token）

### 9.6 务必分清三个概念

这是最容易混的地方，单独列出来：

| 概念 | 是什么 | 在哪管理 | 谁产出 |
|---|---|---|---|
| **转换 Transformations** | 模板（一段 prompt 模板） | 管理 → 转换 | 用户自己建/改 |
| **见解 Insights** | 转换跑在 source 上产出的分析成果 | source 详情 → 见解 tab | 转换自动生成 |
| **笔记 Notes** | notebook 里的笔记条目 | notebook → Notes 面板 | 手写 / Chat 保存 |

**一句话总结**：**转换是菜谱，见解是做好的菜（挂在 source 上），笔记是你存进菜谱本的菜（挂在 notebook 上）**。

### 9.7 写 prompt 的经验

- 写死格式（"用 markdown 有序列表"）而不是让模型自由发挥
- 要求引用页码 / 来源段落 → 后续检索可追溯
- 限定字数（"每节 2-3 句话"）避免输出过长
- 加"若某项信息缺失请写'未提及'" → 避免模型编造
- 写完先去实验室试一次，满意再保存

### 9.8 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 实验室运行报 model not found | 选的模型没在 Models 页配好 / TensorZero 名字没前缀 | Models 页补配 / 换 model 名加 `tensorzero::model_name::xxx` |
| 添加来源勾了转换但一直没见解 | 多勾导致超时 / 模型挂了 | 一次只勾一个；进见解页用"生成新见解"补跑 |
| 出来的见解格式乱七八糟 | prompt 没限定格式 | 回转换里加"用 markdown、每节 2-3 句" |
| 批量出来每篇格式不一样 | 大段 source 里内容差异大 | prompt 明确列出必须有哪些 section；加"若信息缺失请写'未提及'" |
| 自带"默认"的转换不想自动跑 | 关掉那个"设为默认"开关 | 编辑对应转换 → 关开关 |
| 找不到见解 | 跑错了地方（去 notebook Notes 面板找） | 见解挂在 **source 详情 → 见解 tab**，不是 notebook Notes |

### A.3 推荐文本：什么是量子计算？

**量子计算（Quantum Computing）** 是一种利用量子力学（物理学的一个分支，主要研究微观粒子的行为）原理来处理信息的新型计算技术。

为了让你直观地理解，我们可以通过对比传统计算机（你现在用的手机或电脑）和量子计算机来解释。

#### 1. 核心区别：比特 vs. 量子比特

**传统计算机：开关（0 或 1）**

传统计算机的基本单位是**比特（Bit）**。就像一个电灯开关，它只有两种状态：

- 要么是 **0（关）**
- 要么是 **1（开）**

所有的电影、游戏、文档，在电脑底层都是由长串的 0 和 1 组成的。

**量子计算机：旋转的硬币（0 和 1 同时存在）**

量子计算机的基本单位是**量子比特（Qubit）**。

想象一枚硬币：

- 传统比特就像平放在桌上的硬币，要么是正面（0），要么是反面（1）。
- 量子比特就像**正在旋转中的硬币**。在它停止之前，你无法确定它是正面还是反面，它**同时处于"正面"和"反面"的叠加状态**。

这种特性叫做**量子叠加（Superposition）**。

#### 2. 量子计算的两大"超能力"

量子计算机之所以强大，主要依赖两个量子力学现象：

**A. 量子叠加（并行计算）**

因为量子比特可以同时代表 0 和 1，所以它的计算能力是**指数级增长**的。

- **比喻**：假设你要在一个巨大的迷宫里找出口。
  - 传统计算机像是一个人，每次只能走一条路，试错了再退回来走下一条。
  - 量子计算机像是一团水，可以**同时涌入所有的路**，瞬间就能找到出口。

**B. 量子纠缠（Entanglement）**

这是一种神奇的现象，两个量子比特可以建立一种"心灵感应"般的联系。哪怕它们相隔很远，只要改变其中一个的状态，另一个也会瞬间发生相应的变化。

这使得量子计算机能够将所有量子比特连接成一个巨大的协作体，处理极其复杂的数据关系。

#### 3. 量子计算能做什么？（应用场景）

量子计算机并不是为了让你刷抖音更流畅或玩游戏不卡顿（在这些日常任务上，它甚至不如现在的电脑）。它的强项在于解决**极度复杂的数学和模拟问题**：

1. **新药研发与材料科学**：
   - 模拟分子和原子的相互作用非常困难。量子计算机可以精确模拟自然界的微观过程，帮助科学家快速发现治疗癌症的新药，或者发明更高效的电池材料。
2. **破解密码与网络安全**：
   - 目前的银行加密（如 RSA 算法）基于大数分解的困难性。传统电脑算出来需要几万年，量子计算机可能几秒钟就能破解。这也是为什么国家现在都在研究"后量子密码学"。
3. **金融与物流优化**：
   - 比如送货员如何在几千个目的地中找到最短路径，或者如何在瞬间计算出全球金融市场的最优投资组合。
4. **人工智能**：
   - 加速机器学习的训练速度。

#### 4. 为什么我们还没用上量子计算机？（挑战）

既然这么强，为什么还没取代家里的电脑？因为量子计算机**极其脆弱**：

- **环境要求苛刻**：量子比特非常不稳定。微小的温度变化、噪音或震动都会破坏"叠加态"（这叫**退相干**），导致计算出错。
- **极低温**：目前大多数量子计算机需要放置在接近绝对零度（比宇宙深空还冷）的大冰箱里运行。
- **纠错难**：现在的量子计算机还处于"噪音中等规模量子（NISQ）"时代，容易出错，需要大量的辅助比特来纠错。

#### 总结

量子计算不是"更快的传统计算机"，而是一种"本质不同"的计算机。

- **传统计算机**：一步步逻辑推理（像算盘）。
- **量子计算机**：利用物理法则直接计算概率和模拟自然（像魔法水晶球）。

目前，谷歌、IBM、本源量子（中国）等公司都在激烈竞争，试图造出实用的量子计算机。虽然还处于早期阶段，但它被认为是**第四次工业革命的关键引擎**之一。

### A.4 转换规则

6 个预制转换规则，它们各自的用途如下：

| 转换名 | 用途 |
|---|---|
| **Simple Summary** | 简短摘要，快速判断材料值不值得深读 |
| **Dense Summary** | 信息密度最高的深度摘要，**系统默认转换**，新 source 进来时优先跑 |
| **Key Insights** | 提取要点和可执行项，多份材料对比时用 |
| **Analyze Paper**（Paper Analysis） | 学术/技术论文深度拆解，研究问题 / 方法论 / 关键发现 / 局限性全面覆盖 |
| **Reflections** | 从内容中生成启发性问题，帮你在学习消化阶段往深处想 |
| **Table of Contents** | 长文档生成主题目录 / 章节清单，先看结构再决定细读哪段 |

**使用建议**：

- 拿到一份新材料时，先跑 **Simple Summary** 快速判断值不值得深读
- 值得深读的论文，跑 **Paper Analysis** 做全面拆解
- 多份材料对比时，跑 **Key Insights** 提取每份的核心亮点
- 学习消化阶段，跑 **Reflection Questions** 帮自己提问
- 长文档不知道看哪里，先跑 **Table of Contents** 看结构
- 需要给别人转述时，跑 **Dense Summary** 生成信息密度最高的摘要

这些都可以**批量应用**——选中多个来源一起跑，每个来源各生成一条对应的笔记。

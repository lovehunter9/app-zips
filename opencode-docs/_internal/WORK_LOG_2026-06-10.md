## 〇、用户硬指标（本次最高验收线，原话归纳）
> **安装/启动（新装 / 重装 / 重启 / 升级）阶段，严禁任何联网——包括我们的预装包，也包括用户已装包的"恢复"。只有用户在使用过程中"新装包"可以联网，不在此限。**

> 授权：未提交部分可随意重写甚至推翻；已提交部分也可改。能打进镜像的就打进镜像。镜像号尾缀先用 `-test3`。

## 一、根因复盘：06-08 的设计为何仍会联网
06-08 把 overlay 重置触发从"应用指纹"改成"BASE 指纹"，缓解了**版本升级**重装，但**没有根除**：只要 `BASE_HASH` 变化（我们改基础包 / 升 Alpine / 升 glibc），就 `rm -rf upper` → `restore_user_packages` 走 `apk add` **联网重拉**。这违背"任何升级都不联网"的硬指标。

> 关键洞察：用户装的包（如 ffmpeg + 其 94 个依赖）**本来就完整躺在 OverlayFS 的 upper 里**。只要**永不重置 upper**，就**根本不存在"恢复"这一步**，也就没有任何理由联网。重置+恢复是多余的、且是唯一的联网来源。

## 二、本次重写（全盘推翻 06-08 §6.4 的"重置+恢复+指纹"思路）

### 2.1 overlay upper 永不重置（`init-overlay.sh` 重写）
- 删除全部 `BASE_HASH` / marker / `rm -rf upper work` 逻辑。
- 只做：清理上一个 Pod 残留的 overlay 挂载（umount）→ 按本镜像的 lower 重新挂载。
- upper 跨"新装/重启/升级"**永久保留**；新镜像的二进制（opencode/OMO/cli/基础包）通过 **lower** 自动生效，用户包在 upper 原地不动 → **零联网、零重装**。
- 安全性靠 Dockerfile 钉死 **Alpine 小版本**（base 库 ABI 稳定，upper 链接的 .so 不断）；Alpine 小版本只在我们主动、谨慎时升。

### 2.2 init 严格离线（`init-packages.sh` 重写）
彻底删除所有联网/恢复相关：`restore_user_packages`、`ensure_apk_mirror`、`ensure_apk_cache`、`verify_overlay`、marker、以及 init 里的 `apk add bash` 自愈。
保留且全部为**本地离线**操作：
- `$HOME` 环境文件（`.profile`/`.bashrc`）+ 属主修正；
- 持久 Python venv（用镜像自带 python3）；
- `seed_etc`（拷镜像 `/etc/apk|ssl|passwd|group` 的 KB 级内容到持久态，供 pkg-manager 用）；
- `seed_omo_cache` / `seed_skills`（从 `/opt/olares-bake/` 离线 `cp` 到 appData，幂等；skills 用 `APP_HASH` 打戳，换镜像才刷新）。
- 结果：**init 阶段零 apk、零 wget/curl、零网络**，无论新装/重启/升级。

### 2.3 CHART 简化：3 个 init 容器 → 2 个（`templates/opencode.yaml`）
- init 不再写 overlay upper，故 `init-packages` **不再需要** `pkg-bin/sbin/usr/lib/lib64` 这 5 个 overlay 挂载。
- 把 `init-setup` + `init-packages` 合并为单容器 **`init-home`**（root，仅挂 `opencode-home`/`workspace`，env 合并三项，命令 `init-setup.sh && exec init-packages.sh`）。两者都是"root + 仅 appData + 离线"，合并安全。
- 保留 `init-overlay`（privileged，挂 `pkg-overlay`），且现在它是**最后一个** init 容器，挂好 overlay 紧接主容器启动。
- 渲染行数 474 → 453；init 容器 3 → 2。

### 2.4 Dockerfile
- 删除已无用的 `BASE_HASH` 生成（runtime 不再读取）。
- 保留 `FROM alpine:3.23`（钉小版本，保 upper 长期 ABI 安全）+ `ARG BASE_PKGS`（基础包列表唯一来源，顺带让长 RUN 行干净）。
- 注释更新为"永不重置 overlay"的新语义。

### 2.5 pkg-manager（use-time sidecar，未改语义）
- 仍保留 use-time 的 `apk add`（去 `--no-cache` + 持久 `.apk-cache` 符号链接，命中同版本则离线）、惰性镜像源探测、bash 自愈。
- 这些只在**用户使用中新装包**时触发（允许联网）；sidecar 启动本身惰性、不联网（bash 已 bake → 自愈不触发）。

## 三、各场景结论（对照硬指标）
| 场景 | init 是否联网 | 用户包 |
|---|---|---|
| 全新安装 | **否** | 无 |
| 重启 | **否** | upper 保留 |
| 升级 opencode / OMO / cli | **否** | upper 保留，零重装 |
| 我们改 BASE_PKGS（同 Alpine 小版本） | **否** | upper 保留（base 库 ABI 稳定） |
| 升 Alpine 小版本 / glibc（罕见、主动） | **否**（init 仍不联网，upper 照样保留） | upper 保留；极端情况下个别用户包若依赖变更 SONAME 的 base 库，使用中重装即可（联网属 use-time，允许） |
| 用户使用中新装包 | — | pkg-manager 联网（允许，不在限制内） |

→ **init/启动阶段在所有场景下零联网**，满足硬指标。06-08 §6.5 的缺口已关闭：不再"重置+联网恢复"，连 Alpine 升级也不在 init 联网。

## 七、下午续：从生产版 `.pkg-root` 离线迁移用户包 + 升级到 1.17.0/4.8.1（test4）

### 7.1 暴露的真问题：生产版升级会丢用户包
用户实测：在**之前的版本**用户行为装了 ffmpeg → 保留数据卸载 → 装 test3 → **ffmpeg 没了**。
排查 `opencode-backup-2026-06-08`（= 生产版 chart `1.0.12` / appVersion `1.14.19`）确认根因：
- **生产版持久化机制**：用户包列表存 `~/.user-packages`，**文件**存在一份完整快照 `appData/.pkg-root/{usr,lib,bin,sbin,lib64,etc}`（主容器把 `.pkg-root/usr` 等 bind 到 `/usr`），开机 `restore_user_packages` 用 `apk add` 联网重装。
- **新版（test3）** 用 `appData/.pkg-overlay`（OverlayFS upper），且我已删掉所有 restore 逻辑 → 既不读 `.user-packages` 也不读 `.pkg-root` → **真实用户从生产版升上来，ffmpeg 必丢**。这不是测试机脏，是会砸到每个存量用户的硬伤。

### 7.2 修复：一次性、全程离线的 `.pkg-root → overlay upper` 迁移
在 `init-packages.sh` 新增 `migrate_from_pkgroot()`（在 `init-home` 里、**早于 init-overlay 挂载**执行，直接写 upper 目录）：
- 触发条件：存在 `.pkg-root/lib/apk/db/installed` 且无 `$PKG/.migrated-pkgroot` 标记。
- 用 `apk --root .pkg-root info` 读旧快照已装包，`apk info` 读本镜像 base 包，`grep -vxF` 取差集（= 用户装的包 + 其独有依赖）。
- 对每个差集包 `apk --root .pkg-root info -L` 拿文件清单，把 `usr/ lib/ lib64/ bin/ sbin/` 下的文件 `cp -a` 进 `.pkg-overlay/upper/<f>`。init-overlay 随后挂载 → 文件出现在 merged `/usr` 等。
- **全程零网络**（只读本地旧 DB + 本地拷文件）；`|| true` 包裹、打标记跑一次、永不 brick init。
- 副作用/取舍：只搬文件不并 apk DB → ffmpeg 能跑，但 `apk info`/`pkg-install --list` 暂不列出迁移来的包、`--remove` 对其 no-op（重新 `pkg-install` 即可重新登记）。优先保证"能用"，低风险。后续如需 apk 感知再加 DB 合并。
- **意外利好**：用户当前这台 prod→test3 的脏机器，`.pkg-root` 还在、test3 没打迁移标记 → 升到 **test4 会自动把 ffmpeg 从遗留 `.pkg-root` 迁回**，自愈。

## 一、智能摘要（Summary）— 代码已完成，本地 8090 已起，端到端待验证

结构化 JSON，前端渲染成面板，**所有时间戳可点击跳转音/视频**。目标 app：`audiominutesxdemo`
（代码 `audiominutesxdemo-app/`：`server.js` + `web/`）。本地口径 `PORT=8090 node server.js`。

- Schema 六块全上：`oneLine` 一句话总结 / `overview` 全文概要 / `chapters` 章节速览(带起止+小结) /

## 三、音频 app「安装中一直卡、然后变暂停」根因 + 修复（chart 已改，重建待确认）

### 现象
llamacpp 系（llm-init）在模型没下完时就能打开页面看下载进度；音频系（audiolabx2v3）却卡「安装中」，
一段时间后变「暂停」，看不到进度页。

### 根因（对比 llamacppllmbasev3 vs audiolabx2v3 模板）
- Olares app 进入「running」要求**所有 workload 的 Pod 就绪**；entrance（下载进度页）只有 app running 才可达。
- llamacpp 的引擎容器**没有 initContainer、没有 readinessProbe**，等模型的动作在**主容器内**（llamacpp.sh 等
  sentinel 再 exec）→ Pod 一起就 Ready → app 秒级 running → llm-init entrance 立刻能看进度。
- audiolabx2v3 的引擎有**阻塞式 `wait-models` initContainer**（轮询 sentinel）+ **readinessProbe** →
  下载整个过程 Pod 卡 `Init:0/1`、永不 Ready → app 永远「安装中」→ 安装 watcher 超时 → 「暂停」。
  （llm-init 侧本就正确：readiness 走 `/livez`，秒 Ready，会 serve 进度页；entrance 也确实指向 download-svc。）

### 修复（`audiolabx2v3/templates/engine.yaml`，镜像 llamacpp 做法）
1. **删除** `wait-models` initContainer。
2. 新增 `$waitSentinel`（等 `/run/llm-init/model_download_finish` 的 shell 片段，inline-JSON 安全、无双引号），
   **前置进引擎容器 command**（`command:["/bin/sh","-c","$waitSentinel $pydepsPrelude $engineCmd"]`）。
3. 主容器新增 `run-state`（/run/llm-init, readOnly）挂载，供 $waitSentinel 读 sentinel。
4. **删除引擎 `readinessProbe`**（llamacpp 无探针）；引擎未就绪由 llm-init 的 NotReadyGuard（/v1 返 503）兜底。
- 效果：引擎 Pod 一起就 Ready → app 秒级 running → 下载期间就能在 llm-init 面板看进度，和 llamacpp 一致。
- `helm template`（stt/diar）渲染通过：无 initContainers、无 readinessProbe、command 首段是 wait、run-state 已挂。

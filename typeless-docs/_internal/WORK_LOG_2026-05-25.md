## 二、搜索过程的关键节点

### 2.1 先撞同名歧义陷阱

第一轮 `typeless app 2026` 搜出来时，YC S22 的那家 TypeLess 直接跳出，差点拿那家的资料去写 Huang Song 的事。**第二轮加 `typeless.ai voice transcription` 才把主角和撞名公司分开**。

→ 教训：以「单一英文单词命名」的 startup，**第一动作就该用 site:linkedin / site:producthunt + 创始人姓名做交叉锚定**，不能直接信第一条搜索结果。

### 2.2 创始人锁人靠 LinkedIn + arrfounder + Grokipedia 三方互证

```
LinkedIn  : Founder & CEO at Typeless, Jul 2025 – Present
            前职 Google SWE / LinkedIn SWE / Apple HW
            Stanford EE 硕士 2011-2013
arrfounder: @huang_song_，X 上 5K followers
Grokipedia: "Founded 2024 by Huang Song, Stanford alumnus"
```

三个源的"职业身份 + 学校 + 公司创立年份"完全一致 → 可以信。

LinkedIn 里有个细节："Stealth startup, Apr 2021 – Jul 2025"，等于 Typeless 这家公司之前是用 stealth 状态做了 3+ 年才打出旗号。**这意味着 Typeless 的代码/产品成熟度可能比"2025-11 Product Hunt 首发"看上去要老得多**。

### 2.3 投资人摸到了真格基金

直接搜 `Typeless ZhenFund` 撞中真格基金中英文站的团队页：

> 戴雨森 / Anna Fang 的被投名单里列了 **Manus、Typeless、Momenta、Castbox、ARX-X、Menusifu、Macaron**

→ **Typeless 是真格基金 + Stanford StartX 双 backing**。这条比 Crunchbase 上"未披露融资"要靠谱（Crunchbase 经常对早期种子不收录）。

### 2.4 最有价值的一手发现：隐私政策 vs 营销话术的认知裂缝

`@medmuspg` 那份逆向分析（2025-11，X）在日本 Mac 圈火了一阵，被竞品 Voibe 整理成 audit 报告留下。**关键证据是 Typeless 自家隐私政策 + Voibe 整理的逆向报告互相印证**：

| 营销 | 自家隐私政策 | 逆向报告 |
|---|---|---|
| "On-device history" | "audio inputs and contextual information are processed in real time on our cloud servers" | 路由到 AWS us-east-2 |
| "Never trained on your data" | 同时提到 "third-party LLM providers (such as OpenAI)" | OpenAI 出现在调用链 |
| 没说 | 没说 | 还顺手抓了浏览器 URL / 窗口标题 / 剪贴板 |

**这条"on-device history ≠ on-device processing"** 是整次调研里最有信息量的发现，专门在报告里用 callout 标了出来。

### 2.5 反向印证：OpenTypeless 出现

GitHub 上 `tover0314-w/opentypeless` 这个 2026-02 才开仓的开源项目，等于把 Typeless 的工作机理整套复刻出来了。**它选用的架构（Tauri + Rust 录音 → STT 适配层 → LLM polish 层 → 键盘模拟输出）几乎可以被认为是 Typeless 自身的逆向猜测**：

- 默认 STT 包含 Whisper / Deepgram / Groq Whisper / GLM-ASR / SiliconFlow / AssemblyAI
- 默认 LLM polish 包含 OpenAI / DeepSeek / Claude / Gemini / Ollama / LM Studio 等
- 还配套发了 `typeless-sdk` npm 包

**OpenTypeless 仅用 3 个月就做到了 Typeless 一年多的产品力**——这条数据被显式写进了报告的「核心壁垒不在模型而在产品」结论里。

## 五、assistant 的复盘（给自己）

今天这次调研有两条值得记的：

### 5.1 撞同名陷阱的代价被压到了第二轮就发现

YC S22 的 TypeLess 出现在第一轮结果里，**第一次回答用户前没下结论，先做了第二轮带 "voice transcription" 关键词的搜索锚定**——这次没翻车。但下次可以更早一步：**看到 startup 名是「单一英文单词 + 没后缀」的，应该默认它撞名，第一动作就是 site:linkedin.com/company + 创始人名锁定**，不要先搜大类关键词。

### 5.2 用户的"暂时不要与某项目产生关联"是个非常具体的边界要求

第一版回答里我写了一整章「与你最近工作的关联」——把 OpenTypeless 用 SiliconFlow 调 SenseVoice → 与某个并行项目选模相同的反向印证铺得很满。**第二版（即写进 .md 的版本）按用户要求整章删掉，并把那一节替换成「调研中尚未确认 / 可能需要进一步验证」**——把"延伸建议"换成"诚实的空白清单"。

这是个**调研型文档的健康模式**：写一份当时就有用的"建议下一步"是好心，但**把这种建议焊死在原始调研记录里会污染未来重新读这份文档的眼睛**。下次写调研报告时，**建议性内容默认放进随聊回复里，不进 .md**；进 .md 的只放事实和"我还不知道什么"。

### 5.3 一个不算复盘但值得记的小亮点

Voibe 那份《Typeless Privacy Issues》虽然是竞品出品（有动机抹黑），但**因为它把所有指控都标了出处（X 原帖 + Typeless 自家隐私政策原句）**，可以剥离作者动机只取证据。对这种"竞品撰写但证据透明"的资料，**剥离动机后的事实可信度反而比中立媒体高**——值得纳入"反推/调研"工具箱。

# WORK LOG — 2026-07-03(周五)

## 背景
重 clone 全部 audiolabxv3 实例后,DEMO 出现"完全不工作":
- M1 工作流离线转写报 `audio_mode_mismatch: model Qwen/Qwen3-ASR-1.7B has mode=stt_stream`。
- M2 两个流式(stt_stream / diar_stream)界面上都不出结果(勾一个/两个都一样)。

## 根因(P0)
**模型名冲突。** 离线 Qwen STT 与流式 STT 两个 provider 在网关里注册用的是**同一个模型名** `Qwen/Qwen3-ASR-1.7B`。网关按"模型名 → 唯一 provider"解析,于是:
- 离线 `/v1/audio/transcriptions` 请求命中了 `mode=stt_stream` 的 provider → mode 不匹配报错。
- 流式请求可能命中离线 provider(mode=stt)→ 流式不工作。

之所以今天早些时候流式能用,是因为那会儿离线 Qwen 实例处于卸载状态(无冲突);重 clone 把它装回来后冲突复现。

不是模型被改坏,也不是引擎挂了(两个流式 pod 全程 `1/1 Running`)。

## 修复
### 网关侧(手动 + 脚本)
- 手动删除旧的 `stt-stream-audiolabxv3` provider。
- 用 `audiolabxv3-docs/register-stt-stream-provider.js` 重新注册,**模型名改为独立的 `Qwen3-ASR-1.7B-stream`**(mode=stt_stream),与离线的 `Qwen/Qwen3-ASR-1.7B` 彻底分开。
- `BASE_URL` 需确认为当前 stt_stream 实例入口 + `/v1`(重 clone 后域名可能变)。
- 附带产出 `audiolabxv3-docs/rename-stt-stream-model-id.js`(改名脚本,备用)。

### DEMO 侧(`audiostudioxdemo-app/web/src/stream.tsx`,本地改 + 重打镜像)
1. **说话人默认开启**(`enableDiar` 默认 `true`)——之前默认没勾,进流式 tab 根本不会调用 diar_stream,表现为"没有说话人分离的调用"。
2. **模型自愈**:选中的模型必须是网关当前真实在服务的;若网关残留旧默认名(已删/改名的 `Qwen/Qwen3-ASR-1.7B`),自动回退到列表里的有效模型(优先网关默认,否则列表首个),避免再误走离线 provider。
3. **无 diar 模型时静默降级为仅转写**:`enableDiar` 默认开,但若网关没有 diar_stream 模型,`precheck`/`openEngines` 不再抛错、也不连接 diar,`fusion` 关闭,保证 STT 不被拖住。

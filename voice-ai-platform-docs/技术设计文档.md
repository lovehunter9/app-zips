### 1.2 三层职责切分

| 层 | 组件 | 唯一职责 |
|---|---|---|
| 接入层 | `gateway`（FastAPI） | 鉴权 / 路由 / API 兼容 / WebSocket / SSE |
| 编排层 | `worker`（RQ + Redis） | 任务调度 / 重试 / Webhook / 进度推送 |
| 模型层 | 各模型应用 + 远程 provider | 单一能力：STT / TTS / VAD / diarization / 翻译 / 增强 / embed |

接入层不持有模型，编排层不暴露用户接口，模型层不与用户直接通信。三层用 OpenAI 兼容协议或 gRPC 串联。

### 1.3 数据流

**同步短任务（OpenAI 兼容）**：

```
Client ─HTTP─▶ gateway ─HTTP─▶ provider ─stream─▶ gateway ─HTTP─▶ Client
```

**异步长任务（AuralWise 形态）**：

```
Client ─POST /v1/tasks─▶ gateway ─enqueue─▶ Redis ─pick─▶ worker
                                                            │
                                                            ├─ provider 1
                                                            ├─ provider 2 (chained)
                                                            └─ provider N
worker ─update─▶ Postgres ─poll/SSE─▶ Client
worker ─webhook+HMAC─▶ Client (callback_url)
```

**流式（WebSocket）**：

```
Client ◀═WS═▶ gateway ◀═WS/gRPC stream═▶ provider (Voxtral Realtime / Deepgram Flux / 自家 voice-stt-live-* 系列)
```

## 三、API 设计

### 3.1 通用约定

#### 鉴权
所有 `/v1/*` 端点要求 `Authorization: Bearer <token>`，token 由 Olares 注入。Gateway 解析后写入 `request.state.user`：

```python
class CurrentUser(BaseModel):
    bfl_username: str       # 用户唯一标识
    namespace: str          # k8s namespace user-system-<bfl>
    is_admin: bool = False
```

#### 错误码（结构同 OpenAI）

```json
{
  "error": {
    "type":    "invalid_request_error | authentication_error | rate_limit | provider_error | internal_error",
    "code":    "audio_too_long | invalid_format | unsupported_language | provider_unavailable | ...",
    "param":   "audio_url",
    "message": "Audio duration exceeds 5 hours",
    "request_id": "req_2026...",
    "provider":   "openai"
  }
}
```

HTTP 状态：400 / 401 / 402 / 403 / 404 / 409 / 413 / 415 / 429 / 500 / 502 / 503 / 504。

#### 限流
- 每用户每秒 token bucket：默认 60 req/min（同步路径） + 10 task/min（异步路径）
- 限流命中返 429 + `Retry-After` + `X-RateLimit-*` headers

#### Request ID
- 入口生成 `request_id = "req_" + ulid()`
- 写入响应 header `X-Request-ID`
- 异步任务把 request_id 持久化到 `task.metadata`

### 3.3 OpenAI 兼容路径（同步）

`POST /v1/audio/transcriptions` —— 与 OpenAI Python SDK 100% 兼容：

```python
@router.post("/v1/audio/transcriptions")
async def transcriptions(
    file: UploadFile = File(...),
    model: str = Form("whisper-1"),
    language: Optional[str] = Form(None),
    prompt: Optional[str] = Form(None),
    response_format: Literal["json","text","srt","verbose_json","vtt"] = Form("json"),
    temperature: float = Form(0.0),
    timestamp_granularities: list[str] | None = Form(None),
    user: CurrentUser = Depends(get_current_user),
) -> Any:
    provider = await ProviderRouter.pick(user=user, capability="stt", model=model)
    audio = await audio.decode.normalize(file)
    return await provider.transcribe(audio, language=language, prompt=prompt,
                                     response_format=response_format, ...)
```

`response_format` 与 OpenAI 一致：默认 `json` 仅返 `{"text": "..."}`，`verbose_json` 含 segments + words + timestamps，`srt` / `vtt` 直接返字幕文本。

### 3.4 任务总线（异步 + Webhook）

`POST /v1/tasks` 请求体：

```json
{
  "type": "transcribe-url | translate | podcast | subtitle | summary | meeting | clone | enhance | embed",
  "input": {
    "audio_url":    "https://...",
    "audio_base64": "...",          // 二选一；base64 ≤ 20 MB
    "filename":     "interview.m4a"
  },
  "options": {
    "language": "zh",
    "diarize": true,
    "translate_to": "en",
    "providers": {
      "stt":  "voice-stt-whisperx-large-v3-v2",
      "diar": "voice-diar-pyannote-community-1-v2",
      "llm":  "ollamav2:qwen2.5-14b-instruct"
    },
    "audio_events": false,
    "vad": {"min_speech_ms": 250, "min_silence_ms": 300}
  },
  "callback_url":    "https://my-app.example.com/hook",
  "callback_secret": "...",
  "batch_mode":      false,
  "metadata":        {"user_tag": "..."}
}
```

响应（202 Accepted）：

```json
{
  "task_id": "task_2026XYZ...",
  "status":  "queued",
  "created_at": "2026-05-26T13:00:00Z",
  "estimated_duration_ms": 60000
}
```

任务状态机：

```
queued ─▶ running ─▶ done
                  └▶ failed
                  └▶ abandoned (>24h queue 仍未起，或手动 cancel)
```

`GET /v1/tasks/{id}` 返回当前状态 + 进度（0-100）+ 已完成的阶段列表；`GET /v1/tasks/{id}/result` 在 `done` 时返完整结果。

Webhook 投递规则：
- 触发条件：状态变为 `done` / `failed` / `abandoned`
- 头：`X-Webhook-Event`、`X-Webhook-Signature: sha256=HMAC-SHA256(callback_secret, raw_body)`
- 重试：指数退避（1, 4, 16, 64, 256, 1024 秒共 6 次），全部失败标记 `webhook_dead`
- 投递并发：每用户 4 并发；Redis Stream 持久化

### 3.5 流式协议

`WS /v1/realtime` —— OpenAI Realtime 协议对齐，事件类型完整覆盖：

| 客户端 → 服务端 | 服务端 → 客户端 |
|---|---|
| `session.update`           | `session.created` |
| `input_audio_buffer.append`（PCM16 24kHz mono）| `session.updated` |
| `input_audio_buffer.commit`| `input_audio_buffer.committed` / `.speech_started` / `.speech_stopped` |
| `response.create`          | `response.created` |
| `response.cancel`          | `response.audio.delta` / `.audio_transcript.delta` / `.text.delta` / `.done` |
| `conversation.item.create` | `conversation.item.created` |
|                            | `error` |

`session.update` 可配字段：

```json
{
  "type": "session.update",
  "session": {
    "modalities":             ["text", "audio"],
    "model":                  "voice-stt-live-voxtral-realtime-3b-v2 | voice-stt-live-whisperlive-large-v3-turbo-v2 | gpt-realtime-2 | flux-general-en | u3-rt-pro",
    "voice":                  "alloy | shimmer | <voice_id>",
    "input_audio_format":     "pcm16",
    "output_audio_format":    "pcm16",
    "input_audio_transcription": {"model": "whisper-1"},
    "turn_detection": {
      "type": "server_vad | semantic_vad | none",
      "threshold": 0.5,
      "silence_duration_ms": 500
    },
    "tools": [...],
    "temperature": 0.7
  }
}
```

#### 端点 → provider 映射

| `model` 字段 | 路由到 |
|---|---|
| `voice-stt-live-voxtral-realtime-3b-v2`         | 本地自家流式 STT（Voxtral Realtime 3B，默认）|
| `voice-stt-live-whisperlive-large-v3-turbo-v2`  | 本地自家流式 STT（WhisperLiveKit + faster-whisper large-v3-turbo）|
| `voice-stt-live-paraformer-large-zh-streaming-v2` | 本地中文流式 STT |
| `gpt-realtime-2`           | 远程 OpenAI Realtime（BYOK）|
| `gpt-realtime-whisper`     | 远程 OpenAI Realtime（BYOK），STT-only |
| `gpt-realtime-translate`   | 远程 OpenAI Realtime（BYOK），实时翻译 |
| `flux-general-en` / `flux-general-multi` | 远程 Deepgram Flux（BYOK），转 v2/listen 协议 |
| `nova-3`                   | 远程 Deepgram Nova-3（BYOK） |
| `u3-rt-pro`                | 远程 AssemblyAI Universal-3 Pro Streaming（BYOK） |
| `qwen3-asr-flash`          | 远程阿里 DashScope Realtime（BYOK） |

Gateway 内做事件协议转译（输入永远是 OpenAI Realtime 事件流，出端按 provider SDK 重映射）。

### 3.6 SSE 任务进度

`GET /v1/tasks/{id}/events`（`Accept: text/event-stream`）：

```
event: status
data: {"status":"running","progress":0.4,"stage":"diarization"}

event: partial
data: {"segment_index":12,"text":"..."}

event: done
data: {"task_id":"task_...","result_url":"/v1/tasks/.../result"}
```

worker 把进度写 Redis pub-sub channel `task:progress:{id}`，gateway 订阅后转 SSE。

## 四、Provider 适配层

### 4.1 抽象接口

```python
class ProviderBase(ABC):
    name: str
    capabilities: set[Capability]   # {STT, STT_STREAM, TTS, TTS_CLONE, VAD, DIAR,
                                    #  TRANSLATE, LLM, EMBED, ENHANCE, ALIGN}

    @abstractmethod
    async def healthcheck(self) -> ProviderHealth: ...

    @abstractmethod
    async def list_models(self) -> list[ModelInfo]: ...

class STTProvider(ProviderBase):
    @abstractmethod
    async def transcribe(self, audio: AudioRef, **opts) -> TranscriptionResult: ...

class STTStreamProvider(ProviderBase):
    @abstractmethod
    async def open_stream(self, **opts) -> AsyncContextManager[STTStreamSession]: ...

class TTSProvider(ProviderBase):
    @abstractmethod
    async def synthesize(self, text: str, voice: str, **opts) -> AsyncIterator[bytes]: ...

class TTSCloneProvider(TTSProvider):
    @abstractmethod
    async def register_voice(self, samples: list[AudioRef], **opts) -> VoiceID: ...

    @abstractmethod
    async def synthesize_clone(self, text: str, voice_id: VoiceID, **opts) -> AsyncIterator[bytes]: ...
```

### 4.2 路由策略

```python
class ProviderRouter:
    """根据用户配置 + 用例 + 模型别名，选出具体 provider 实例。"""

    @classmethod
    async def pick(cls, *, user: CurrentUser, capability: Capability,
                   model: str | None = None, language: str | None = None,
                   prefer_local: bool | None = None) -> ProviderBase:
        config = await UserConfig.load(user)
        # 1) 用户显式指定 provider:model
        if model and ":" in model:
            return await cls._resolve_explicit(config, model)
        # 2) 走 alias 表（如 model=whisper-1 → speaches/Systran-large-v3-turbo）
        alias = config.resolve_alias(model)
        if alias:
            return await cls._resolve(config, alias)
        # 3) 走 capability 默认（含 prefer_local）
        chain = config.fallback_chain(capability, language=language)
        for entry in chain:
            try:
                p = await cls._resolve(config, entry)
                if await p.healthcheck().is_healthy:
                    return p
            except ProviderUnavailable:
                continue
        raise NoProviderAvailable(capability=capability)
```

```python
def encrypt(payload: dict, *, user: str) -> tuple[bytes, bytes, bytes]:
    cluster_key = read_secret("/run/secrets/olares-cluster-key")  # 32B
    dek = HKDF(algorithm=hashes.SHA256(), length=32,
               salt=user.encode(), info=b"voice-ai-hub:cred").derive(cluster_key)
    nonce = os.urandom(12)
    aead  = AESGCM(dek)
    ct    = aead.encrypt(nonce, json.dumps(payload).encode(), associated_data=user.encode())
    return ct[:-16], nonce, ct[-16:]
```

### 5.2 对象存储

## 六、任务编排

### 6.1 任务管线（DAG）

每个 task type 是一个 DAG。例：`type=meeting`：

```
   ┌─ decode  ──► chunk_vad ──► transcribe ──► diarize ──► align
   │                                                          │
   ▼                                                          ▼
 original audio                                          merge_segments
                                                              │
                                                              ▼
                                                       llm_summary / chapters / actions
                                                              │
                                                              ▼
                                                          persist + webhook
```

DAG 用 Python 直接编：

```python
@task(type="meeting")
async def meeting_task(t: Task) -> TaskResult:
    audio = await decode(t.input.audio)
    chunks = await vad_split(audio, **t.options.vad)
    segments = await transcribe_chunks(chunks, provider=t.providers.stt, language=t.options.language)
    if t.options.diarize:
        diar = await diarize(audio, provider=t.providers.diar)
        segments = align_diar(segments, diar)
    out = MeetingOutput(segments=segments)
    if t.options.llm_summary:
        out.summary  = await llm_summary(segments, provider=t.providers.llm)
        out.chapters = await llm_chapters(segments, provider=t.providers.llm)
        out.actions  = await llm_actions(segments, provider=t.providers.llm)
    return out
```

每个 await 边界都向 `task:progress:{id}` 发心跳。

### 6.3 重试与超时

| 错误 | 重试策略 |
|---|---|
| `provider_timeout` | 同 provider 重试 1 次，再 fallback 链下一个 |
| `provider_5xx` | 退避 2/8/32 s 共 3 次，再 fallback |
| `provider_429` | 等 `Retry-After`，最多 60 s，再 fallback |
| `provider_4xx` 非 429 | 不重试，直接错误返回 |
| `internal_error` | 重试 1 次，仍失败标 `failed` |
| `oom` | 不重试，标 `failed` 并触发告警 |

### 6.4 Webhook 投递

```python
async def deliver_webhook(task: Task, event: str, payload: dict):
    body = json.dumps({
        "event": event,
        "task":  payload,
        "delivered_at": iso_now(),
    }).encode()
    sig = "sha256=" + hmac.new(secret_for(task), body, hashlib.sha256).hexdigest()
    headers = {
        "Content-Type":        "application/json",
        "X-Webhook-Event":     event,
        "X-Webhook-Signature": sig,
        "X-Webhook-Task-Id":   task.id,
        "X-Webhook-Attempt":   str(attempt),
    }
    async with httpx.AsyncClient(timeout=30) as c:
        r = await c.post(task.callback_url, content=body, headers=headers)
    return 200 <= r.status_code < 300
```

死信处理：失败 6 次后写 `webhook:dlq`，admin 在 Web UI 可手动重投。

## 七、自家模型应用矩阵

### 7.0 用户体验契约（与 ollama* 系列 1:1 对齐）

四条硬约束：

1. **1 个 app = 1 个具体模型变体（含量化档位）**——不是"1 个 app + 一堆下拉菜单切模型"。`ollamaqwen3527bq4kmv2` / `ollamaqwen35a3budq4klv2` 这种"两个量化档各占一个 app"是已建立的先例。
2. **App Store 安装条本身覆盖"镜像拉取 + 模型下载"**——pod readiness 阻塞到模型就绪为止。**不允许出现"装完打开还要再等几分钟首次下载"** 这种场景。
3. **装完用户立刻能拿到 (BASE_URL, MODEL_NAME) 两个值**就能粘到任何其它应用里用。Service 命名规则、entrances 端口、env 暴露形态全部对齐 ollama* 范式。
4. **v2 拆分（`subCharts: [server (shared/clusterScoped), client]`）**——管理员装 server 一份，普通用户装 client 引用同一个 server，模型只下一次。

**唯一允许的偏离**：HuggingFace 门禁模型（如 `pyannote-3.1`）需要用户在 App 配置页粘一次 `HF_TOKEN`（OlaresManifest `envs` 标准机制）。**这是仅有的"用户视角"差异**，且仅出现在门禁模型上。

完整应用矩阵共 ~74 个。下面只给"工程实现"侧的内容：统一 API 容器（§7.1）、一非门禁范型完整 chart（§7.2）、一门禁范型差异（§7.3）、其余应用的差异点速查（§7.4）。

### 7.1 `beclab/voice-model-puller` 统一 API 容器（Milestone 0）

> 这是把"完全统一 UX"做成可能的关键件。所有 ~74 个 voice-* app 共用同一个镜像，差异**只通过 ConfigMap 驱动**。对应 ollama* 系列里的 `harveyff-olares-ollama` 角色。

#### 7.1.2 启动逻辑（伪代码）

```python
import os, hashlib, asyncio, time, urllib.request
from pathlib import Path

MODEL_NAME       = os.environ["MODEL_NAME"]
MODEL_CAPABILITY = os.environ["MODEL_CAPABILITY"]
MODEL_SOURCE     = os.environ["MODEL_SOURCE"]      # olares-cdn | hf-public | hf-gated
MODEL_TARGET_DIR = os.environ["MODEL_TARGET_DIR"]
ENGINE_UPSTREAM  = os.environ["ENGINE_UPSTREAM_URL"]

state = {"phase": "downloading", "error": None, "progress": 0.0}

async def pull_model():
    sentinel = Path(MODEL_TARGET_DIR) / ".success"
    if sentinel.exists():
        state["phase"] = "ready"
        return
    if MODEL_SOURCE == "olares-cdn":
        url, md5 = os.environ["MODEL_TARBALL_URL"], os.environ["MODEL_TARBALL_MD5"]
        await aria2_download(url, "/tmp/model.tar.zst", on_progress=update_progress)
        verify_md5("/tmp/model.tar.zst", md5)
        await asyncio.create_subprocess_exec("zstd", "-d", "/tmp/model.tar.zst", "-o", "/tmp/model.tar")
        await asyncio.create_subprocess_exec("tar", "-xf", "/tmp/model.tar", "-C", MODEL_TARGET_DIR)
    elif MODEL_SOURCE == "hf-public":
        from huggingface_hub import snapshot_download
        snapshot_download(os.environ["HF_REPO_ID"], local_dir=MODEL_TARGET_DIR)
    elif MODEL_SOURCE == "hf-gated":
        token = os.environ.get("HF_TOKEN", "").strip()
        if not token:
            state["phase"] = "waiting_for_hf_token"
            state["license_url"] = os.environ.get("GATED_LICENSE_URL", "")
            return                          # /readyz 持续返 503 直到 token 到位
        from huggingface_hub import snapshot_download
        snapshot_download(os.environ["HF_REPO_ID"], local_dir=MODEL_TARGET_DIR, token=token)
    sentinel.touch()
    state["phase"] = "ready"

async def watch_hf_token():
    """门禁模型下，监听 HF_TOKEN 变化（applyOnChange 会重启 pod，但保险起见也轮询）。"""
    while state["phase"] == "waiting_for_hf_token":
        await asyncio.sleep(5)
        if os.environ.get("HF_TOKEN", "").strip():
            await pull_model()
            return
```

#### 7.1.4 配置驱动新增 app 的最小步骤

新增一个 voice-* app 时**不**需要改 puller 镜像或代码，只需：

1. 在应用矩阵中登记一行（含 App ID、模型、上游、license、资源、优先级）；
2. 抄 §7.2（非门禁）或 §7.3（门禁）范型，改三处：`MODEL_NAME` + runtime 容器 image + 资源量；
3. 把 tarball 推到 `cdn.olares.com/models/voice/<engine>/<name>.tar.zst`，把 md5 写进 ConfigMap（仅 `olares-cdn` 路径需要）。

工作量约每个 app **0.05–0.15 人月**（基本就是写 OlaresManifest + 一份 ConfigMap）。

#### 7.4.3 新增一个 voice-* app 的 7 步指引

1. 在应用矩阵中登记一行（含 App ID、模型、上游、license、资源、优先级）。
2. 在 §7.4.2 表格里把它分到一个引擎 image。如该引擎首发，就同时新建 `beclab/voice-engine-<engine>` image（`Dockerfile` 装上游 + 暴露 `:9000` 引擎 server 即可，不实现 OpenAI 兼容路径，后者由 `voice-model-puller` 反代）。
3. 抄 §7.2 整个 chart 文件树到 `<appname>` 目录，全局 search-replace `voice-tts-kokoro-82m-v2` → `<appname>`、`Kokoro 82M` → `<title>`。
4. 改 `server/templates/configmap.yaml` 三个值：`MODEL_NAME` / `MODEL_TARBALL_URL` + MD5 / `ENGINE_UPSTREAM_URL`（端口和镜像不同则改）。门禁的话改 `MODEL_SOURCE: hf-gated` + `HF_REPO_ID` + `GATED_LICENSE_URL`，并在 OlaresManifest envs 加 `HF_TOKEN`（详 §7.3）。
5. 改 `OlaresManifest.yaml` 的 `metadata.icon` / `description` / `versionName` / `fullDescription` / `license` / `developer` / `website` / `sourceCode` / `doc` / 资源声明（CPU/GPU/RAM）。
6. 改 `server/templates/deployment.yaml` 的 runtime 容器镜像 + 资源 limits/requests（按应用矩阵的 GPU/CPU 列）。
7. 上 tarball：`tar --zstd -cf <name>.tar.zst <model_files>` → md5sum → 上传 `cdn.olares.com/models/voice/<engine>/<name>.tar.zst`（仅 `olares-cdn` 路径需要）；门禁路径无需上传。

工作量约每个 app **0.05–0.15 人月**。引擎 image 首发约 0.3–0.5 人月。完整 ~74 个 app 落地约 **7–11 人月**，其中 P0 + P1 的 ~54 个约 **5–6.5 人月**。

### 7.5 声音克隆相关的状态归属（关键设计取舍）

为了让 `voice-tts-cosyvoice-2-v2` 等克隆类 app 也能保持"装完拿 BASE_URL+MODEL_NAME 走人"的无状态形态，**声纹注册表 / voice_id 索引 / 声纹样本音频** 全部归 `voice-ai-hub`（详 §五.1 PostgreSQL `voices` 表 + §五.2 MinIO `voices/` 前缀）。voice-tts app 只接收无状态请求：

- `POST /v1/audio/speech`：标准 OpenAI 兼容 TTS（无 voice_id 概念）
- `POST /v1/audio/clone`：请求体里 **必须** 直接带 `reference_audio_url` 或 `speaker_embedding`（base64 浮点数组），克隆 app **不**保存任何声纹

由 `voice-ai-hub` 在用户调用克隆时：
1. 从 `voices` 表查 `voice_id` → 拿到 MinIO 上的 sample 音频 key 或 embedding
2. 取出后构造请求体调 `voice-tts-cosyvoice-2-v2` 的 `/v1/audio/clone`
3. 把 hub 内部计算好的 AudioSeal 水印 metadata 一起返回

这样 voice-tts 类 app 在用户视角依然是"装、拿 BASE_URL+MODEL_NAME、走人"。

### 9.2 音频解码与重采样

入口流式音频可能是 PCM16 / PCM24 / G.711 / Opus / FLAC：

```python
class AudioPipeline:
    def __init__(self, in_fmt: str, in_sr: int, out_sr: int = 16000):
        self.dec = Decoder(in_fmt)
        self.rs  = Resampler(in_sr, out_sr, channels=1, dtype=np.float32)

    async def feed(self, raw: bytes) -> np.ndarray:
        pcm = self.dec.decode(raw)
        return self.rs.process(pcm)
```

所有 ASR 在内部统一 16 kHz mono float32；entry / exit 处转换。

## 十、安全

### 10.1 鉴权链

```
Client (BFL token / X-API-Key)
    │
    ▼
Olares Gateway (验证 token)
    │
    ▼
voice-ai-hub gateway (再次验证，加 namespace 检查)
    │
    ▼
内部 worker / provider 调用走 ServiceAccount 短期 token
```

### 10.2 凭证

- 全部 BYOK 凭证：AES-GCM-256 + per-user DEK
- DEK 派生：`HKDF(cluster_key, salt=bfl_user, info="voice-ai-hub:cred")`
- 内存中明文凭证不超过 60 s 缓存
- 日志严禁打印 Authorization / key 字段，统一在 logging filter 中遮罩

### 10.3 数据合规

- 默认音频与文本不出集群；唯一例外是用户配置的远程 provider
- 远程 provider 调用前在 Web UI 弹"将把您的音频发送到 {provider}"二次确认
- 数据保留：用户可在设置里设全局 retention（默认 30 d uploads / 180 d artifacts）
- `DELETE /v1/users/me/data` 一键清空所有用户音频 / 任务 / 笔记 / 声纹

### 10.4 声音克隆专属

- 声纹注册必须用户在 Web UI 勾选《声音克隆使用同意书》后才可写入 `voices` 表
- 注册时验证：上传样本 ≥ 30 s 有效语音；与 `voices` 表中已有 embedding 做相似度查重，阈值 > 0.92 拒绝（防止盗用他人声音）
- 克隆产物默认嵌 AudioSeal 水印，水印 token 落库
- API 调用 `/v1/audio/clone` 需 `voice_id`；不接受任意上传音频做"即时克隆"

```python
from app.tasks.progress import progress
from app.audio.decode import fetch_and_decode
from app.audio.chunk import vad_split

@task(type="transcribe-url", queue="long")

        audio = await fetch_and_decode(t.input["audio_url"])
        await p.set("vad", 0.15)
        chunks = await vad_split(audio, **t.options.get("vad", {}))

            language=t.options.get("language"),
        )

        for i, c in enumerate(chunks):
            r = await stt.transcribe(c, **t.options)
            segments.extend(r.segments)
            await p.set("transcribing", 0.20 + 0.70 * (i+1)/len(chunks))

                user=t.user, capability=Capability.DIAR,
                model=t.options.get("providers",{}).get("diar"),
            )

        await p.set("persisting", 0.97)
        return TranscribeResult(segments=segments)
```

### 13.6 voice-* app 自动发现（不再靠 endpoint 环境变量注入）

由于 voice-* app 现在是 ~74 个 1-app-per-model 的形态，把每个 app 的 URL 单列成环境变量已经不现实，且每次新增 app 都要改 voice-ai-hub 的 OlaresManifest 也违反"完全统一 UX"原则。**改用 sharedEntrance 自动发现机制**：

```python
# app/providers/discover.py
import asyncio, httpx
from kubernetes_asyncio import client, config

async def discover_voice_providers(namespace: str) -> list[ProviderConfig]:
    """扫整个 namespace 的所有 sharedEntrance Service，按 (MODEL_NAME, MODEL_CAPABILITY)
    自动注册 provider；无须事先在 voice-ai-hub OlaresManifest 列每个 app 的 URL。"""
    await config.load_incluster_config()
    v1 = client.CoreV1Api()
    services = await v1.list_namespaced_service(namespace=namespace,
        label_selector="bytetrade.io/sharedentrance=true")
    providers = []
    async with httpx.AsyncClient(timeout=5.0) as http:
        for svc in services.items:
            base_url = f"http://{svc.metadata.name}:8080"
            try:
                r = await http.get(f"{base_url}/v1/models")
                models = r.json().get("data", [])
                for m in models:
                    providers.append(ProviderConfig(
                        name=f"local_{svc.metadata.name.replace('-', '_')}",
                        base_url=base_url,
                        model=m["id"],
                        capability=m.get("capability"),
                        local=True,
                    ))
            except (httpx.RequestError, ValueError):
                continue
    return providers
```

发现策略：
- voice-ai-hub 启动时跑一次发现 → 写到 `provider_registry`
- 之后每 60 s 重扫一次（处理装/卸载 voice-* app 的事件）
- 门禁 app 没填 HF_TOKEN 时 `/readyz` 返 503，发现逻辑会自动剔除（直到用户填好 HF_TOKEN 后再扫到）

需要 voice-ai-hub OlaresManifest 显式注入的环境变量只剩：

```bash
SPEACHES_URL=http://speaches.user-system-alice:8000              # 现有借力 app（命名不规范，单独处理）
WHISPERWEBUIV2_URL=http://whisperwebuiv2.user-system-alice:7860  # 同上
OLLAMAV2_URL=http://ollamav2.user-system-alice:11434             # 同上
OLARES_CLUSTER_KEY_FILE=/run/secrets/olares-cluster-key
```

自家 voice-* 矩阵全部走自动发现，不用单独注入。

### 14.2 引擎容器（以 `beclab/voice-engine-whisperx` 为例）

> 引擎容器只跑模型推理；模型下载、读取 hostPath、暴露 OpenAI 兼容路径全部交给 §7.1 的 `voice-model-puller` 容器。引擎容器自身**只**暴露内部 `:9000` 上的 native 推理 API（whisperX-fastapi、cosyvoice-server、pyannote-server、SGLang OpenMOSS-fork、vLLM Qwen3-Omni 等上游 API 即可）。这一切片让"~25 个引擎 image 服务 ~74 个 voice-* app"成为可能。


模型不在镜像里，由 puller 容器在 pod 启动时下载到共享 hostPath（`userData/Voice/<release-name>` → `/models`）。引擎容器启动时读 `MODEL_DIR=/models/<MODEL_NAME>` 加载。

## 十七、运维 SOP

| 场景 | 操作 |
|---|---|
| 升级 gateway | `helm upgrade voice-ai-hub ... --set image.tag=X.Y.Z`；DB migration 自动执行 |
| 升级模型应用 | 各应用独立升级；gateway 启动 healthcheck 自动重新探测能力 |
| Provider 凭证失效 | Web UI "测试连接" 按钮调用 `POST /v1/models/test`；用户更新 |
| GPU OOM | 任务标 `failed`，告警；管理员调小 model 档位或降低 worker concurrency |
| Webhook 死信 | Web UI 管理 `webhook:dlq`，可批量重投 |
| 数据清理 | cron 每天跑 retention job，按 `uploads_ttl_days` / `artifacts_ttl_days` 清理 MinIO |
| 备份 | Postgres `pg_dump` 每日 + WAL 持续；MinIO `mc mirror` 到外部 |
| 灾恢复 | 从 pg_dump + MinIO mirror 恢复；Redis 数据为缓存性质，丢失不致命（运行中任务可从 DB 重建） |

# 独立模型应用清单与配置层

> 本文回答两个问题：**(1) 本平台的可配置模型层里有哪些应用 / 远程 API；(2) 用户怎么配它们**。
> 上游文档 = `00_产品愿景与总体架构.md`。

---

## 一、本地模型应用（Olares Market 上的"独立应用"形态）

> 每一项都是一个独立 Olares 应用（独立 OlaresManifest），与 `ollamav2` 平级；同时被核心应用通过 sharedEntrance 调用。
>
> **核心策略**：本平台的 ASR / 语音 AI 模型层主力是**自家应用矩阵**（§1.2）；现有 Olares 应用（`speaches` / `whisperwebuiv2` / `ollamav2`）**短期借力作为现成 provider**，**长期由自家矩阵成熟后降为可选**；**本平台不在任何现有应用上扩展新功能**。

### 1.1 现有 Olares 应用（短期借力的现成 provider）

> 这些应用本平台**不修改、不扩展、不提 PR**；只通过 sharedEntrance 当作现成 provider 调用。它们继续保留独立 GUI 工具人设，用户可以单独装、单独用。

| 应用 | 当前版本 | 提供能力 | 在本平台中的角色（短期）| 长期处置 |
|---|---|---|---|---|
| **`speaches`** | v1.0.12 | STT（faster-whisper-small）+ TTS（Kokoro-82M）；OpenAI 兼容 | 默认轻量 STT/TTS provider | 与自家 `voice-stt-whisper-*` / `voice-tts-kokoro-*` 等矩阵并存 |
| **`whisperwebuiv2`** | v1.0.19 | STT（faster-whisper / openai-whisper / insanely-fast-whisper）+ pyannote diarization + UVR BGM 分离 + NLLB / DeepL 翻译；**无 TTS 能力** | 默认重型 STT provider（含 diarization / 翻译） | 自家 `voice-stt-whisperx-large-v3-*` / `voice-diar-pyannote-*` / `voice-translate-*` 成熟后**降为可选 provider**；保留独立 GUI 用户场景 |
| **`ollamav2`** | v1.0.18 | OpenAI 兼容 LLM endpoint（任意 GGUF 模型）| LLM 后处理：摘要、章节、Action Items、翻译、跨笔记 RAG | **长期保留**为本平台唯一 LLM 入口 |

> **关键说明**：`whisperwebuiv2` **不具备 TTS 能力**，且本平台**不打算给它扩展 TTS / 流式 STT / 声音克隆等任何新功能**——这些都由**自家应用矩阵**（§1.2）的对应应用补。

### 1.2 自家模型应用矩阵（待新建，本平台主力）

> **核心原则（与 `ollama*` 系列 1:1 对齐，详 `00_产品愿景与总体架构.md` §1.5）**：
>
> 1. **1 个 app = 1 个具体模型变体**——不是"1 个 app + 一堆下拉菜单切模型"。
> 2. **App Store 安装条覆盖"镜像 + 模型下载"**——pod readiness 阻塞到模型就绪。
> 3. **装完用户立刻能拿到 (BASE_URL, MODEL_NAME) 两个值**粘到任何其它应用里用。
> 4. **v2 拆分（`subCharts: [server (shared/clusterScoped), client]`）**——管理员装 server 一份，普通用户装 client 引用同一个 server。
>
> **门禁模型例外**：HuggingFace 门禁模型（`pyannote-3.1` 等）需要用户在 App 配置页粘 `HF_TOKEN`（OlaresManifest `envs` 标准机制）。**这是仅有的"用户视角"差异**。

下表把 v1 catalog 拟铺开的全部 ~74 个独立模型应用按能力域罗列（12 个能力域：STT 离线 / STT 流式 / TTS（含 dialogue 子能力）/ VAD / Diarize / Translate / Enhance / Embed / Align / Audio-LLM / **Audio-S2S** / **Sound-FX**）。每个应用都按统一规范（§1.3）交付，详细 OlaresManifest 模板见 §1.4。

### 1.3 模型应用的统一规范（每个新应用都要遵循）

为了让 §1.2 中所有 ~74 个 voice-* app 在用户视角上**完全一样**（与 ollama* 系列一字不差），所有新建模型应用必须满足：

#### 部署形态

1. **chart 结构**：顶级 chart + 两个 subChart：`<appname>server` 标 `shared: true / clusterScoped: true`（admin 装一次共享）；`<appname>` 是用户级 client（per-user 安装，引用同一个 server）。完整对照见 ollama* v2 范式（如 `ollamabgem3567mv2`）。
2. **runtime 容器**：上游引擎容器（不同 app 不同，例如 `whisperx-fastapi`、`cosyvoice-server`、`pyannote-server`），只起 server 进程，端口在内部（不外暴）。
3. **API 容器**：统一用 `beclab/voice-model-puller:<ver>`（详 §1.5），它做三件事：(a) 装机时下模型并卡 readiness；(b) 反代上游引擎容器到 `:8080` 暴露 OpenAI 兼容路径；(c) 暴露 `/v1/models` / `/healthz` / `/metrics` / `/readyz`。
4. **模型存储路径**：hostPath `userData/Voice/<release-name>` per-app 一份（**不**跨 app dedupe，对齐 `userData/Ollama/<release-name>`）。
5. **暴露端口与 Service 命名**：`http://api.<release>server-shared:8080`（流式 STT 自动识别为 `ws://api.<release>server-shared:8080`）。

#### 必须暴露的 env（用户视角的两个值 + 一个能力域 tag）

每个 app 的 OlaresManifest **顶层** `envs:` 必须暴露下列三个标准 env（用户在 App 详情页就能看到，并能自动被 `voice-ai-hub` 读到）：

| envName | 类型 | 说明 |
|---|---|---|
| `MODEL_NAME` | 只读，display only | 例如 `whisperx-large-v3` / `cosyvoice-2` / `pyannote-3.1`。**这就是 §一.2 表格里 App ID 去掉 `voice-<cap>-` 前缀和 `-v2` 后缀**。 |
| `MODEL_CAPABILITY` | 只读，display only | `stt` / `stt_stream` / `tts` / `tts_clone` / `tts_dialogue` / `vad` / `diar` / `diar_stream` / `translate` / `enhance` / `embed` / `align` / `audio_llm` / `audio_s2s` / `sound_fx` 之一。`voice-ai-hub` 据此自动路由。 |
| `BASE_URL` | 只读，display only | `http://api.<release>server-shared:8080`（runtime injection；用户复制即用）|

非门禁 app 仅这三项。门禁 app 加一项 `HF_TOKEN`（详 §1.4.2）。可选项 `KEEP_ALIVE`（与 ollama* 一致）。

#### 健康与发现

6. **暴露 `/healthz`（liveness）/ `/readyz`（readiness）/ `/metrics`（Prometheus）三个端点**：`/readyz` 一定要把"模型已下完且加载完毕"算进去，readiness 一通过就代表 (BASE_URL, MODEL_NAME) 立刻可用。
7. **`/v1/models`**：返回 `{"data": [{"id": MODEL_NAME, "capability": MODEL_CAPABILITY, ...}]}`，方便 `voice-ai-hub` 自动发现。
8. **sharedEntrance internal**：不暴露公网；用户在 LarePass 控制面板看不到，只在 App 详情里看 envs 与 sharedEntrance 服务名。

#### 独立可用 + 解耦

9. **不依赖 `voice-ai-hub`**：每个 voice-* app 单独装也能用——直接拿 `BASE_URL + MODEL_NAME` 喂给任何 OpenAI 兼容客户端（chatbox / openwebui / 自家代码）。
10. **不读其它 voice-* app 的状态**：不通过 hostPath 共享 blob，不互相调用 ConfigMap，**只**通过 `voice-ai-hub` 协调。

**用户视角差异仅此一处**：装完进 App 详情，环境变量页有一个 `HF_TOKEN` 待填，下面带链接和说明。其它一切（安装入口、安装动画、(BASE_URL, MODEL_NAME) 暴露形式、Service 名）和非门禁完全相同。

### 1.5 `beclab/voice-model-puller` 镜像（统一 API 容器）

> **这是把"完全统一 UX"做成可能的关键件，必须先做（详 `03_落地路线与工作量.md` Milestone 0）**。
>
> 它对应于 ollama* 系列里的 `harveyff-olares-ollama` 角色——所有 ~74 个 voice-* app 共用同一个镜像，差异只通过 ConfigMap 驱动。

#### 职责

1. **启动时下模型 + 卡 readiness**：
   - 读 ConfigMap：`MODEL_SOURCE` ∈ `olares-cdn` / `hf-public` / `hf-gated`
   - 若 `olares-cdn`：`wget $MODEL_TARBALL_URL` → md5 校验 → 解压到 `MODEL_TARGET_DIR`
   - 若 `hf-public`：`hf download $HF_REPO_ID --local-dir $MODEL_TARGET_DIR`
   - 若 `hf-gated`：检查 `$HF_TOKEN` 是否非空；为空则 `/readyz` 持续返 `503 + {"error":"waiting_for_hf_token","license_url":"..."}` 直到用户填上 token；填上后调用 `hf download --token $HF_TOKEN $HF_REPO_ID --local-dir $MODEL_TARGET_DIR`
2. **反代上游引擎**：把 `:8080` 上的 `/v1/audio/transcriptions` / `/v1/audio/speech` / `/v1/diarize` 等按 `MODEL_CAPABILITY` 自动路由到 `$ENGINE_UPSTREAM_URL`（runtime 容器内进程）。
3. **暴露标准元数据端点**：`/v1/models`（返回 `MODEL_NAME` + `MODEL_CAPABILITY`）、`/healthz`、`/readyz`、`/metrics`。
4. **统一日志格式**：JSON stdout，含 `app_id` / `model_name` / `capability` / `request_id` / `latency_ms`。

#### 配置驱动而非代码改动

新增一个 voice-* app 时**不**需要改 `voice-model-puller` 的代码或镜像，只需：
1. 在 §1.2 的对应分类表格新增一行；
2. 抄 §1.4 范型，改三处（`MODEL_NAME` / runtime 容器 image / 资源量）；
3. 把 tarball 推到 `cdn.olares.com/models/voice/<engine>/<name>.tar.zst` 并把 md5 写进 ConfigMap（仅 `olares-cdn` 路径需要）。

#### Olares CDN 流程

- 所有 redistributable 模型（Apache/MIT/CC-BY/FunASR Model License 等）都打成 `.tar.zst` 推到 `cdn.olares.com/models/voice/<engine>/<name>.tar.zst`
- 流程对齐已有的 `whisperwebui_models.tar.zst` / `cosyvoice` 等老应用（已经在用 `cdn.olares.com/models` 这个一级目录）
- 门禁（`hf-gated`）和 CC-BY-NC（research-only）模型**不**进 CDN，运行时 HF 直拉

#### 工作量

- 镜像本身：1 人 × 1.5 周（Python + FastAPI + 模型 puller 逻辑 + reverse-proxy）
- CI / 上 GHCR：0.5 周
- 文档 + cookbook："新增一个 voice-* app 的 7 步指引"：0.5 周
- **小计 ~0.6 人月**，但**节省 ~74 个 app 各自做下载逻辑的重复工作量**（按每个 app 节省 0.1 人月 × 74 ≈ 7.4 人月）

### 3.2 配置 API

| 端点 | 方法 | 用途 |
|---|---|---|
| `/v1/config` | GET | 拉当前用户全配置 |
| `/v1/config/providers` | PUT | 更新 provider 凭证 |

### 3.3 模型选择策略

每次 API 调用按下列顺序决定真实 provider：

```
1. 请求 body 里的 model / provider 参数（优先级最高，per-call override）
2. 用户当前 usecase 的 primary
3. 用户当前 usecase 的 fallback（primary 不可用时）
4. 系统默认（本地优先 → 失败回 OpenAI Whisper 等通用端点）
```

### 3.4 本地与远程的统一发现

- **本地模型应用**全部按 §1.3 规范暴露 `MODEL_NAME` / `MODEL_CAPABILITY` / `BASE_URL` 三个标准 envs + `sharedentrances-api:80` Service；`voice-ai-hub` 启动时**扫整个 namespace 的所有 sharedEntrance**，按这三个 env 自动发现并填到 `providers.local_*`，**用户不必手动配**
- **门禁 app 没填 HF_TOKEN 时不出现在 providers 列表里**（hub 调 `/readyz` 看 `error: waiting_for_hf_token` 自动剔除，直到用户填好后再出现）
- **远程**全部由用户手动添加；核心应用不提供任何默认远程 key

## 四、本地模型应用 vs 远程 API 的"用户该挑哪个"指引

| 场景 | 推荐 | 理由 |
|---|---|---|
| 个人私密笔记 / 日记 / 工作录音 | **本地优先** | 数据完全不出家 |
| 长任务批处理（夜间跑） | **本地优先** | 不计费、不限速 |
| 流式实时对话（实时性 < 300ms）| **远程**（Deepgram / 火山豆包）| 本地 GPU 难追上专用云加速 |
| 高质量声音克隆 TTS | **本地** `voice-tts-cosyvoice-2-v2` 优先 / **远程**（ElevenLabs / 火山豆包）| CosyVoice 2 已经能打多数云端商用产品 |
| 中文方言 / 行业术语 | **远程**（讯飞 / 阿里云 NLS）| 国内训练数据更多 |
| 偶发使用 / 不想配 GPU | **远程**（Groq Whisper $0.00033/min）| 性价比极高 |
| 离线（无网）使用 | **本地**（自家矩阵） | 仅此一选 |
| 国内中文场景（非私密）| **远程 Qwen3-ASR / 阿里云 NLS** | 国内 ASR 第一优先 + 与 Qwen LLM 生态一脉 |
| 国内中文 + 强方言 | **远程讯飞** | 方言历史厚 |
| 国内中文 + 实时通话 | **远程火山豆包 ASR** | 实时性最佳 |

核心应用的 Web UI 在配置时**主动给出此指引**，引导用户做合理选择。

## 五、本章结论

1. **自家模型矩阵 ~74 个独立 app**（每 app = 1 个具体模型变体；含 2026-04 新增 6 个 MOSS-Audio 系列：2 个 STT 离线变体 + 4 个 Audio-LLM 变体；含 2026-05 月度扫描后再补的 23 个：3 个 Qwen3-ASR 系 / 1 个 MOSS-Transcribe-Diarize / 5 个 MOSS-TTS / 1 个 MOSS-TTSD / 1 个 Streaming Sortformer / 5 个 Audio-LLM 扩档 / 2 个 Audio-S2S / 1 个 Sound-FX / 1 个 TEN-VAD / 升级 4 个 TTS 候选 = 23），按 ollama* v2 范式 1:1 对齐，用户视角与 `ollamabgem3567mv2` 等已有模型应用**完全相同**——装→等→拿 (BASE_URL, MODEL_NAME) 走人。声音克隆产品语义由 `voice-ai-hub` 持有（声纹库 + voice_id 表），TTS app 永远无状态。
2. **`beclab/voice-model-puller` 镜像必须先做（Milestone 0）**——所有 voice-* app 共用同一个 API 容器，差异仅靠 ConfigMap 驱动；新增一个 voice-* app 只是写一份 OlaresManifest + 改三个值（`MODEL_NAME` / runtime image / 资源量）。
3. **门禁模型保留**（`pyannote-3.1` / `pyannote-embedding` 等）——走 OlaresManifest `envs.HF_TOKEN` 标准机制；用户视角差异仅"在 App 详情粘一次 token"，安装入口和 (BASE_URL, MODEL_NAME) 暴露形式与非门禁完全一致。

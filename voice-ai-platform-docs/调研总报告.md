# 调研总报告

> 笔记型，结论先行；只摆事实，不掺假设/工期/分工。

## 一、三句话结论

1. **语音输入法**形态高度同构：30+ 个开源/商业项目都是「全局热键 → 16 kHz 单声道 → VAD → ASR → 文本注入」，差异只在 ASR 引擎和注入手段；移动端外，桌面 100% 走 Whisper / Parakeet / SenseVoice 三大模型家族之一。
2. **语音转录**分六个流派（桌面单进程 / 自托管 Web 全栈 / OpenAI 兼容 API / 会议机器人 / 视频字幕创作者 / AI 笔记本），但**模型层全部收敛**到 faster-whisper / WhisperX + pyannote / SenseVoice / Parakeet TDT 这一小撮组件 + 一层 LLM 后处理。
3. **AuralWise 与上述两类在模型层 100% 重合**（faster-whisper / SenseVoice / Silero / fsmn-vad / CAM++ / YAMNet），区别只在产品形态——AuralWise 走「异步 task + Webhook」纯 API 路径，无 LLM 后处理、无流式 dictation 端点。**三类可统一**到「同一套模型层 + 多形态 API 网关」，详 §五。
4. **开源 Speech-LLM 已成熟**：MOSS-Audio（OpenMOSS / MOSI.AI，Apache-2，4B/8B × Instruct/Thinking）一个模型同时做 ASR + 音频问答 + 时间戳 + 推理 + 音乐理解，**Timestamp ASR 比 Qwen3-Omni-30B 与 Gemini-3.1-Pro 强一个数量级**；不替代主路径，单独作为 `audio-llm` 能力域承载"听感型 QA"，详 §3.11。
5. **另有一批 SOTA 开源关键件**：(a) **Qwen3-ASR-1.7B / 0.6B + Qwen3-ForcedAligner-0.6B**（QwenLM，Apache-2，52 语 + 22 中文方言，流式/离线同模型，强于 Whisper-large-v3）；(b) **MOSS Transcribe Diarize**（OpenMOSS，paper 2601.01554）——端到端 ASR + 说话人 + 时间戳一步出，直接对标 WhisperX + pyannote 主路径；(c) **MOSS-TTS 全家族** + **MOSS-TTSD**（多角色对话 TTS）+ **MOSS-Speech**（真正 S2S 无文本中介）+ **MOSS-SoundEffect**（文生音效）+ **NVIDIA Streaming Sortformer**（流式 diarization）。详 §3.10–3.12。

关键观察：

- **MOSS-Audio-8B-Thinking 是开源同尺度（≤10B）综合榜首**，超过同档 Qwen3-Omni-30B（30B）、Step-Audio-R1（33B）。
- **MOSS-Audio Timestamp ASR 碾压 Qwen3-Omni-30B 与 Gemini-3.1-Pro 一个数量级**（35 vs 833 / 708）；原因是它在 pretraining 时显式插入时间标记 token；架构上独有 *DeepStack 跨层特征注入* + *Time-Aware Representation*。
- **MOSS-Audio 不做流式、不做 TTS、不做 diarize**——只是"听音的 LLM"；流式 ASR、TTS、说话人分离仍然要走 Whisper / Parakeet / SenseVoice / Voxtral Realtime + pyannote / Kokoro / CosyVoice 这条主路径。
- 同家族还有 MOSS-TTS（含 v1.5 主力 / Realtime 流式 / Nano-100M CPU+克隆 / TTSD 多角色对话）/ MOSS-Speech（真正 S2S 无文本中介）/ MOSS-Music（音乐 audio-LLM）/ MOSS-SoundEffect（文生音效）/ MOSS Transcribe Diarize（端到端 ASR+Diar）等独立 collection，OpenMOSS 是完整开源语音家族（与 FunAudioLLM、字节 Voxtral-like 一档）。
- 同档其它候选：Audio Flamingo Next 8B（NVIDIA）/ Step-Audio-R1.1（33B）/ Step-Audio 2.5 Realtime / Qwen3-Omni-30B Captioner——前两者在 MMAU 同评测可见数据（60.16 / 66.48），后两者闭源 / cloud 形态；总体均不及 MOSS-Audio-8B-Thinking 同尺度领先优势。

### 4.2 推断架构

```
公网边缘 (阿里云 CDN Tengine + WAF + 验证码 2.0)
   ↓
API Gateway (Go：Chi/Gin/Echo 风格)
   ↓
Job Queue (Redis/asynq 推断) + DB (Postgres/MySQL：tasks/billing/speaker_embeds 推断)
   ↓
GPU Worker Pool (Python)
   ├─ ffmpeg → 16 kHz mono
   ├─ Language Detect
   ├─ Router (optimize_zh + 中文?)
   │    YES → fsmn-vad → SenseVoice-Small → 段级时间戳
   │    NO  → Silero VAD → faster-whisper Whisper-large-v3(-turbo) → 词级时间戳
   ├─ [可选] Diarize：CAM++ / ECAPA-TDNN 192-d → AHC 聚类 → Silhouette 单说话人回退
   └─ [可选] AED：YAMNet 521 类（AudioSet 527 减 6）；0.96 s 帧 / 0.48 s hop
   ↓
对象存储 (原始音频 + 结果 JSON)
   ↓
Webhook 回调客户 (HMAC-SHA256 + 重试)
```

任务状态机：`queued → processing → done / failed / abandoned`。

## 六、核心结论再贴一次

1. **模型层有事实标准**：Whisper 系（含 faster-whisper / WhisperX）+ Parakeet TDT + SenseVoice + Paraformer + pyannote + Silero/fsmn-vad + Kokoro/CosyVoice 这一小撮组件覆盖输入法 / 转录 / AuralWise 三类的 95%+ 用例。
2. **API 形态分三档**：流式 WS（输入法/会议）/ 同步+异步 REST（转录/字幕）/ 任务+Webhook（AuralWise 兼容）。可在同一个网关里**全部承载**。
3. **开源 Speech-LLM 单列一档**：MOSS-Audio 系列把"音频 → LLM 直接回答 + 推理 + 时间感知"做到 SOTA 开源同尺度榜首，**单独作为 `audio-llm` 能力域承载**，与 ollamav2 互补。
4. **本平台路径**：底层把上面这一小撮模型按"1 app = 1 model"全打成 Olares 独立应用（自家矩阵 ~74 个 + 现有 3 个 + 远程 BYOK 一堆），上层做一个 voice-ai-hub 把三档 API 全暴露出去。详 `概要设计.md`。

# 场景化选型推荐

> 按"我手里有这种音频 / 我要做这种事"的视角，直接告诉你选哪个模型。每条都给 1 个首选 + 1~2 个备选 + 选它的原因 + 注意事项。本文一律按"模型名"维度推荐，不带任何 App ID。

## 二、详细推荐（按场景）

### A. 转录类

#### A-1 中长音频文件转录（最常见，中英混合）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **WhisperX (Whisper-large-v3 + wav2vec2 对齐 + pyannote diarize)** | faster-whisper(CTranslate2) 加速；含词级时间戳；99 语；RTX 4090 上 FP16 仅转录 72× 实时，含对齐 60×，含 diarize 30× |
| 备选 1 | **Qwen3-ASR-1.7B** | 52 语 + 22 中文方言，强于 Whisper-large-v3；vLLM 批量推理快 |
| 备选 2 | **MOSS-Transcribe-Diarize** | 端到端 ASR+Diar 一步出，省去 WhisperX → pyannote 双步串联 |

**注意事项**：
- WhisperX 中文标点正常但 ITN（数字 / 日期归一）较弱，需要后处理；Qwen3-ASR / MOSS-TD 这一档 LLM-based，ITN 内置更自然。
- 中英混（code-switching）三者都行，Qwen3-ASR 训练时显式包含 code-switching。

---

#### A-2 纯英文 / 欧洲语种文件转录（速度优先）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **Parakeet-TDT-0.6B-v3** | NVIDIA Parakeet TDT v3，英文 WER 开源榜冠军；25 European languages；RNN-T 解码比 AED 快几倍 |
| 备选 | **Whisper-large-v3-turbo（WhisperX 包装）** | 英文质感同样好，turbo 比 large-v3 快 ~2× |

**注意事项**：
- Parakeet TDT v3 **不含中 / 日 / 韩**；中文请走 SenseVoice / Paraformer / Qwen3-ASR。
- Parakeet TDT v3 是 CC-BY-4.0（需署名），不是 Apache-2，但商用 OK。

---

#### A-3 中文为主文件转录

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **SenseVoice-Small** | 中文 NAR+CTC 端到端，吞吐高；自带 vad + spk + punc 三合一 |
| 备选 1 | **Paraformer-large-zh** | FunASR 主力中文 ASR，长音频稳定 |
| 备选 2 | **Qwen3-ASR-1.7B** | 52 语 + 22 中文方言；中文 CER 比 SenseVoice 略低 |

**注意事项**：
- SenseVoice 非流式；中文流式必须 Paraformer streaming 或 streaming-sensevoice 第三方 fork。

---

#### A-4 长会议带说话人转录（一步出"谁何时说啥"）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **MOSS-Transcribe-Diarize** | 统一多模态 LLM，端到端一步出 (speaker, text, t_start, t_end) 三元组；长音频说话人 ID 不漂移 |
| 备选 | **WhisperX + pyannote-community-1** 串联 | 两步走主路径，稳定，但需要工程串联两个组件 |

**注意事项**：
- MOSS-TD license ⚠ 未明示（GitHub 无 LICENSE 文件），单租户私部署可用，商用 SaaS 形态请重新核 license。
- 两步走主路径里 pyannote-community-1 是 MIT；pyannote-3.1 需要 HF_TOKEN（HF 门禁）。

---

#### A-5 多语种（≥20 语）转录

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **Whisper-large-v3（WhisperX 包装）** | 99 语事实覆盖，几乎所有项目里默认 |
| 备选 1 | **Qwen3-ASR-1.7B** | 52 语 + 22 中文方言；中文 / 唱歌 / 多语强于 Whisper-large-v3 |
| 备选 2 | **Canary-1B-Flash** | 4 语（英 / 德 / 法 / 西）高精专精，含 ASR + ASR→Translate 一体 |

---

#### A-6 唱歌 / 含背景音乐的人声转录

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **Qwen3-ASR-1.7B** | 训练时专门加了唱歌 / 音乐识别，是当前唯一明确标注支持唱歌的 ASR |
| 备选 1 | **MOSS-Audio-8B-Instruct** | Speech-LLM 一档，听感保留好，对含背景音乐音频鲁棒 |
| 备选 2 | **Demucs v4 先分离人声 → 喂任意 ASR** | 用 Demucs 把伴奏剥离后任何 ASR 都能识别更好 |

---

#### A-7 词级时间戳精度极致（字幕 / 配音对齐 / 视频剪辑 / 播客章节）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **WhisperX (large-v3) + wav2vec2 forced alignment** | wav2vec2 forced alignment 词级精度 **±10 ms**，业内字幕主流，物理上限就这么准 |
| 备选 1 | **MOSS-Audio-8B-Instruct** | Speech-LLM 路线时间戳 SOTA：AAS **35.77 ms**（中文 AISHELL-1）/ **131.61 ms**（英文 LibriSpeech），比 Qwen3-Omni-30B 与 Gemini-3.1-Pro 准 **5–23 倍**；适合"既要 LLM 推理能力又要时间戳"|
| 备选 2 | **Qwen3-ForcedAligner-0.6B**（与任意 ASR 配套） | 11 语 Apache-2，与 Qwen3-ASR 配套强对齐；Qwen3-ASR 系列默认对齐器 |

**为什么 MOSS-Audio 时间戳特别准（背景知识）**：
- pretraining 时**显式插入时间标记 token** —— 不是事后对齐，而是模型本身就学会"我说到第几秒"；同档对手（Qwen3-Omni / Gemini）走的是"先出字 → 再外挂对齐器"路线，精度天花板低。
- 架构上独有 **DeepStack 跨层特征注入** + **Time-Aware Representation**（自训 12.5 Hz 音频 encoder），保证 LLM 能感知到 80 ms 级别细粒度。

**注意事项**：
- **想要纯转录 + 时间戳极致准 → WhisperX (wav2vec2 forced alignment) 仍是物理上限**（10 ms 级），别为了"用最新的"就上 MOSS-Audio。
- MOSS-Audio 真正不可替代的是"一个模型既能转录又能 QA 又能保留听感"；如果你要的只是字幕，WhisperX 又快又准又稳。
- 字幕 / 视频对齐场景中 **±200 ms 以内人眼几乎不可察觉**，再准的精度收益有限。

### C. TTS / 合成类

| 选 | 模型 | 理由 |

### D. Audio-LLM / 理解类

#### D-1 听感型 QA（"这段音频里的人开心吗 / 是不是醉了 / 背景几个人"）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选 | **MOSS-Audio-8B-Thinking** | MMAU/MMAU-Pro/MMAR/MMSU 平均 70.80，开源同尺度（≤10B）综合榜首；超越 Qwen3-Omni-30B（30B）/ Step-Audio-R1（33B） |
| 备选 1 | **MOSS-Audio-8B-Instruct** | 同 backbone 不带 thinking 链，响应快、token 省 |
| 备选 2 | **MOSS-Audio-4B-Thinking** | 4B 轻量版，资源受限时用 |

**注意事项**：
- 这一档**不替代 ASR**，输出是"对音频内容的回答 / 分析"，不是逐字 transcript。
- 端点：`POST /v1/audio/qa`（任意 prompt）/ `POST /v1/audio/understand`（场景 / 事件 / 音乐 / 复杂推理）。

---

#### D-2 音乐理解（识别风格 / 乐器 / 情绪 / 段落结构）

| 备选 | **MOSS-Audio-8B-Thinking** 直接喂音频 | 一步出，保留情绪 / 停顿 / 笑声等"听感"线索 |

### E. 辅助识别类

#### E-4 翻译（主路径 / fallback 双轨）

| 选 | 模型 | 理由 |
|---|---|---|
| 首选（主路径）| **通用 LLM 翻译：Qwen3 / DeepSeek / Llama 等** | LLM 翻译质量稳定，可按场景换；可远程 BYOK（OpenAI / Anthropic / Mistral / DashScope）|
| 备选 1（开源 fallback，可商用）| **MADLAD-400-3B** | Apache-2.0，419 语，可商用 |
| 备选 2 | **OPUS-MT (multi) / M2M-100** | Helsinki-NLP / Meta 开源传统 NMT |

## 三、通用避坑准则

### 3.1 license 字段的"开源 ≠ 可商用"

| 梯度 | 含义 | 典型 |
|---|---|---|
| ✅ **完全自由** | 无任何附加条款，放心商用 | Apache-2.0 / MIT / BSD |
| ✅ **有 attribution 要求但商用 OK** | 需要署名 | CC-BY-4.0（Parakeet TDT v3） |
| ⚠ **名为开源、实有附加条款** | 商用 / 竞品 / SaaS 受限 | TEN-VAD（Apache-2 + non-compete）/ HashiCorp BSL / Elastic ELv2 |
| ⚠ **License 未明示** | GitHub 无 LICENSE 文件 + HF model card 未写 | MOSS-Music / MOSS-SoundEffect / MOSS-Transcribe-Diarize |
| ❌ **明确禁止商用** | 仅研究 / fallback | NLLB CC-BY-NC / fishspeech ⚠ / xtts-v2 ⚠ / mms ⚠ |

### 3.2 资源量预估的快速心智

| 模型档位 | 显存 | 部署形态 |
|---|---|---|
| ≤ 200M（Kokoro-82M / MOSS-TTS Nano-100M / Silero VAD） | < 1 GB / CPU 可推 | 端侧 / 边缘 |
| 200M – 1B（CosyVoice 2 / SenseVoice-Small / pyannote-community-1） | 2–4 GB | 单卡 ≥ T4 |
| 1B – 5B（Whisper-large-v3 / Parakeet-TDT-0.6B-v3 / Voxtral-Realtime-3B / MOSS-TTS Realtime） | 6–12 GB | 单卡 ≥ A10 / 4090 |
| 5B – 10B（MOSS-Audio-8B / MOSS-TTS v1.5 / MOSS-Music-8B / MOSS-Speech 9B / MOSS-TTSD v1.0） | 16–24 GB | 单卡 ≥ A100 40G / 4090 24G |
| ≥ 10B（Qwen3-Omni-30B / Step-Audio-R1-33B） | ≥ 60 GB | 多卡 / 大显存 |

### 3.3 流式 vs 非流式的选型口径

| 场景 | 必须流式 | 可以非流式 |
|---|---|---|
| 语音输入法（按住说话） | ✅ | ❌ |
| 实时会议直转大屏 | ✅ | ❌ |
| 会议机器人交互 | ✅ | ❌ |
| voice agent / 智能助手 | ✅ | ❌ |
| 文件转录 / 录音整理 | ❌ | ✅ 推荐（更准、更便宜） |
| AI 笔记本事后处理 | ❌ | ✅ |
| 字幕生成（视频） | ❌ | ✅ |
| 摘要 / 章节 / Action Items | ❌ | ✅ |

**口诀**：**用户体感"等不及"就走流式；可以等几秒到几分钟就走非流式**。流式模型通常精度比非流式低 1–3 个百分点 WER / CER，所以**能不流式就不要流式**。

### 3.4 中文 / 英文 / 多语场景的快速分流

| 你的音频是什么 | 默认走哪个模型 |
|---|---|
| 纯英文 | Parakeet-TDT-0.6B-v3（快）or Whisper-large-v3-turbo（稳） |
| 中文为主 | SenseVoice-Small / Paraformer-large-zh / Qwen3-ASR-1.7B |
| 中文方言（粤川沪闽…） | Qwen3-ASR-1.7B（首选，22 方言） |
| 中英混（code-switching） | WhisperX (large-v3) / Qwen3-ASR-1.7B |
| 20+ 语种混杂（欧亚多语） | Whisper-large-v3（WhisperX 包装，99 语） |
| 含唱歌 / 音乐 | Qwen3-ASR-1.7B + 先用 Demucs v4 分离 |
| 含强情绪 / 想保留听感 | MOSS-Audio Speech-LLM 一档（不走 ASR） |

### 3.5 门禁模型（需要 HF_TOKEN）使用准则

矩阵里带 ⚠ HF_TOKEN 的模型（如 pyannote-3.1）：

1. 用户必须先去 HuggingFace 对应 model card 点同意；
2. 然后申请 token，粘进 App 配置页的 `HF_TOKEN` 字段；
3. App 才会从 HF 下模型，否则 readiness 一直阻塞，App 启动不了。

非门禁模型走 `cdn.olares.com` 镜像源，无需任何配置，装即用。

### 3.6 同一能力域的"主路径 + 备选"设计意图

矩阵里几乎每个能力域都有 P0 主路径 + P1/P2 备选。**不是冗余，是不同场景的最优解**：

- 主路径 = 通用场景最稳的选择（如 Diarize 的 pyannote-community-1）；
- 备选 = 特定场景才更优（如流式 Diarize 必须用 NVIDIA Streaming Sortformer，pyannote 系做不到）。

挑模型时先按"场景"对，再按"性能 / 资源 / license"在备选之间二选；不要直接按"哪个最新就装哪个"。

### 3.7 时间戳精度的快速对照（毫秒级）

ASR 输出"哪个词从第几秒到第几秒"——这个精度直接决定字幕、剪辑、配音对齐、播客章节切分的体验。**数字越小误差越小**：

| 路径 / 模型 | 词级时间戳精度 | 备注 |
|---|---|---|
| **wav2vec2 forced alignment**（WhisperX 默认）| **±10 ms** | 物理上限，业内字幕主流；和 ASR 本身解耦，先出字再对齐 |
| **MOSS-Audio-8B-Instruct**（Speech-LLM 端到端）| **~36 ms 中文 / ~132 ms 英文** | Speech-LLM 一档 SOTA；pretraining 时显式插入时间标记 token |
| **Qwen3-ForcedAligner-0.6B**（与任意 ASR 配套）| 数十 ms | Apache-2，11 语，Qwen3-ASR 系列配套 |
| **whisper-timestamped / stable-ts** | ±100–500 ms | Whisper 自身时间戳后处理，无外挂对齐器 |
| **Qwen3-Omni-30B / Gemini-3.1-Pro 时间戳** | ~700–830 ms | Speech-LLM 一档其它对手；落后 MOSS-Audio 5–23 倍 |
| **GPT-4o-Transcribe 时间戳** | 数百 ms | 远程闭源 |

**口诀**：
- **要字幕 / 剪辑 / 配音对齐 → WhisperX (wav2vec2 forced alignment)**，物理上限 ±10 ms，最稳。
- **要"既转录又能 QA / 推理 / 保留听感、同时时间戳还要准" → MOSS-Audio**，是 Speech-LLM 一档里时间戳唯一能打的。
- **±200 ms 以内人眼几乎察觉不到字幕错位**——别为了再准几十毫秒就上更贵的模型；按场景需求够用即可。

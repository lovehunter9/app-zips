## 一、市面应用现状（一句话格局判断）

> 整个"语音 AI"赛道当下被两条平行的产品线主导：**(A) 以美 / 国内大厂 SaaS 为主的中心化云服务**（功能强、模型黑盒、按 min 计费、数据出域）；**(B) 以社区开源的 Whisper / Kokoro / pyannote 等为核心的自托管小工具**（隐私好、能力散、需要技术力）。中间缺一个层次：**自托管 + 模型可换 + 多用例 API 化**——这正是本平台填的空。

### 1.1 三种产品形态归类

#### 形态一：语音输入法（dictate / 实时听写）

- **海外标杆**：Typeless（macOS 闭源 SaaS）、Wispr Flow、Aqua Voice、Superwhisper、MacWhisper、VoiceInk、Whisper Memos
- **海外开源桌面**：Handy（**22.2k★** MIT，Tauri 2 + Rust，**同时支持 Whisper 和 Parakeet V3**，最干净基线）、Type4Me、CapsWriter、FluidVoice、Voquill
- **海外 Android 范本**：FUTO Voice Input（独立 RecognitionService APK）、Sayboard、WhisperIME、HeliBoard
- **国内**：搜狗 / 讯飞 / 百度 / 微信 / 腾讯输入法（均闭源、含 ASR 模块）
- **共性架构**：客户端（全局热键 + 麦克风 → VAD → STT → 文本注入）+ 后端（云 ASR 或本地 whisper.cpp）；商业模式以 SaaS 订阅为主
- **核心痛点**：(a) iOS 因 Apple 政策限制自定义键盘无麦克风权限、(b) 国产 Android ROM 阻挡第三方 RecognitionService、(c) SaaS 把音频上云、(d) 自托管工具无统一后端

#### 形态二：语音转录（文件 / 会议 / 字幕 / 笔记）

- **海外 SaaS**：Otter / Fireflies / Rev / Sonix / Notta / TurboScribe / Trint / Happy Scribe
- **会议机器人**：Read.ai / Granola / Fathom / tl;dv / Jamie / Spinach / Gong / Chorus（均 SaaS）
- **视频创作者**：OpusClip / Submagic / CapCut / Captions / Riverside / Descript
- **AI 笔记本**：NotebookLM / AudioPen / Voicenotes / AudioNotes / Cleft / Plaud Note（**最与本平台对位**）
- **国内大厂**：通义听悟 / 飞书妙记 / 腾讯会议 AI / 讯飞听见
- **垂直**：Nuance DAX / Suki / Nabla / Abridge / Verbit（医疗 / 法律）
- **自托管开源**：Vibe / Buzz / Whisper-WebUI / Whishper / Anysub / speaches / whisperX / WhisperLiveKit
- **共性架构**：上传 / 流式录入 → STT → diarization → 翻译 → LLM 摘要 → 字幕 / 文档导出；商业模式按 min / 月度订阅
- **核心痛点**：(a) GPU 重型负载多数家用集群跑不动、(b) 长任务 HTTP 超时、(c) 翻译 / 摘要 / 章节多模型协同复杂、(d) 跨平台同步与权限管理碎片

#### 形态三：语音 AI 综合服务平台（多用例 API）

- **闭源标杆**：Auralwise（auralwise.cn，多用例统一 API）、OpenAI Realtime / Audio API、Deepgram Voice Intelligence
- **开源 / 半开源 gateway**：LibreChat 音频模块、Bifrost、TensorZero、litellm
- **共性架构**：一套 OpenAI 兼容 + 扩展端点 → 内部调度多模型 / 多供应商
- **核心痛点**：海外好的均为闭源 SaaS；国内 Auralwise 是托管服务；没有自托管 + 可换模型 + 全用例的平台

### 1.2 模型层的全景

#### ASR 主流
- **通用 + 多语种**：OpenAI Whisper（large-v3 / large-v3-turbo）、faster-whisper、WhisperX、SenseVoice-Small、Parakeet TDT v3、Voxtral、**Qwen3-ASR-Flash**（阿里 2025 多模态 ASR，52 语种 + 方言）、Moonshine、Granite
- **流式专精 / voice agent**：**Deepgram Flux**（model-integrated EOT ~260 ms，端点 `/v2/listen`）、Deepgram Nova-3（sub-300 ms）、**AssemblyAI Universal-3 Pro Streaming**（real-time diarization + 99+ 语种）、**ElevenLabs Scribe v2 Realtime**（sub-150 ms）、**OpenAI GPT-Realtime-Whisper**（**$0.017/min** 流式 ASR；与 GPT-Realtime-2 speech-to-speech + GPT-Realtime-Translate 实时翻译同套 Realtime API）、Speechmatics、Soniox、Groq Whisper（**$0.04/hr** 228× 实时；非流式但极便宜）、火山豆包 ASR、阿里云 NLS、讯飞 / 腾讯云
- **本地推理**：whisper.cpp、WhisperKit（Apple Silicon）、sherpa-onnx、Vosk、FluidAudio、CTranslate2、`whisper-rs`（Tauri 生态）+ `transcribe-rs`（Parakeet 推理）

#### TTS 主流
- **海外闭源**：OpenAI TTS、ElevenLabs（声音克隆领先）、Azure / Google / AWS Polly
- **开源**：Kokoro-82M（轻量默认）、XTTS v2、Bark、ChatTTS（中文）、Fish-Speech、CosyVoice 2（中文克隆）、OpenVoice v2、F5-TTS
- **国内闭源**：火山豆包 TTS、阿里 / 腾讯 / 讯飞 TTS

#### Diarization / VAD / Translation
- **Diarization**：pyannote 3.1（SOTA）、WeSpeaker、3D-Speaker、NeMo Diarization、diart
- **VAD**：Silero VAD（事实标准）、WebRTC VAD
- **Translation**：DeepL、Google Translate、百度 / 腾讯 / 阿里翻译、NLLB-200（CC-BY-NC 商用受限）、LibreTranslate；近年趋势：直接用 LLM（GPT-4o / Claude / Qwen）做翻译质量更稳

### 1.3 三句话总结市面

1. **闭源 SaaS 功能完整但数据出域 + 按 min 计费**，私域用户无法接受
2. **开源工具多但散** —— 每个工具只覆盖一两个用例，多用例联动需要用户自己拼，缺统一抽象
3. **"自托管 + 模型可换 + 多用例 API"的产品空白** —— Olares 上的本平台正好填这个空

## 二、我们的方案设计

### 2.1 一句话定位

> **在 Olares 上新建一个独立应用 `voice-ai-hub`（暂名）**，对外暴露一套 API（OpenAI 兼容 + 扩展端点），让用户通过它跑 26 个语音 AI 用例；底层模型全部可配置——既可以用本地"独立模型应用"（自家规划的 ASR/TTS/VAD 应用矩阵 + 现有 `ollamav2`），也可以用远程 BYOK（Qwen 系列优先 + OpenAI / Deepgram / ElevenLabs 等）。

### 2.2 四条核心原则

1. **模型可配置、双形态供给**：本地"独立模型应用" or 远程 BYOK，用户在配置中心挑
2. **核心 = API；界面是可选**：自带轻量 Web UI 作演示器，但 API 是产品本体
3. **质量优先级**：英文最优 → 中文不影响英文前提下越高越好 → 实时性越高越好
4. **独立存在、不依赖其它现成应用扩展**：现有应用（`whisperwebuiv2` / `speaches` / `ollamav2`）保留独立人设；本平台**不在它们上面扩展任何新功能**；**自家 ASR 应用体系**独立规划

### 2.4 26 个用例（6 大类）

| 大类 | 用例 |
|---|---|

| **E 音频处理** | 降噪 / 增强、BGM 分离、音频嵌入 |

**统一规范**（每个应用都必须满足）：
1. 暴露 OpenAI 兼容路径 + 标准 envs（`MODEL_NAME` / `MODEL_CAPABILITY` / `BASE_URL`，门禁 app 加 `HF_TOKEN`）
2. 暴露 `/healthz` / `/readyz`（含模型加载完成判断）/ `/metrics` / `/v1/models`
3. sharedEntrance internal（不暴露公网）；hub 自动发现
4. v2 拆分：`subCharts: [server (shared/clusterScoped), client]`
5. hostPath 存模型在 `userData/Voice/<release-name>`
6. 共用 `beclab/voice-model-puller` 镜像作为 API 容器
7. 独立可用：每个 app 单独装也能通过 `BASE_URL+MODEL_NAME` 直接喂 OpenAI 兼容客户端，不需要先装 `voice-ai-hub`

### 2.8 配置层

每个用户 `bfl.username` 独立配置树，分三层：
- **providers**：远程 API key + URL（加密存储）
- **models**：按用例分类的 primary + fallback 选择
- **preferences**：默认语种、质量档位、实时性偏好

每次 API 调用支持 **per-call override**（`provider`、`model` 参数）。

提供"档位预设"（个人 / 中文优化 / 高质量 / 极速）一键应用全部用例，避免选择困难症。

## 三、工作内容（不含工期）

> 调研阶段不进入项目管理；以下是"要做什么"的盘点，不写"何时做、做多久"。

### 3.1 核心应用 voice-ai-hub（必做）

| 模块 | 内容 | 关键技术栈选型 |
|---|---|---|
| **API 网关** | OpenAI 兼容（transcriptions / translations / speech / realtime）+ 扩展端点（meeting / podcast / subtitles / diarize / vad / detect-language / align / keywords / denoise / separate / embeddings / dictate / clone / notes / voices / dictionaries）| FastAPI + Pydantic |
| **配置中心** | provider 凭证 + 模型选择 + 偏好；多用户隔离；加密存储 | SQLite + Olares 集群密钥加密 |
| **任务编排** | 同步短任务 / 同步流式 / 异步长任务 / 流式+持久化 四种模式 | RQ + Redis；WebSocket 直转发 |

## 六、关键事实（核查锚定）

> 按"远程 STT/TTS / 本地 TTS+ASR / 法律政策 / 关键模型 / 关键参数"五大类列出落地决策依赖的全部硬事实。

### 6.1 远程 STT/TTS 关键事实（影响 BYOK 推荐）

1. **OpenAI Realtime 三模型（GA）**
   - `gpt-realtime-2`：speech-to-speech 旗舰；GPT-5 reasoning，128K context；$32/$64 per 1M tokens
   - **`gpt-realtime-whisper`：流式 ASR，$0.017/min**（替代 whisper-1 流式场景）
   - **`gpt-realtime-translate`：实时翻译 70→13 语种，$0.034/min**（直接对接 F-2 实时翻译用例）
   - 全部经 `wss://api.openai.com/v1/realtime?model=...` 入口
2. **Deepgram Flux**：端点 `/v2/listen`（注意是 v2），model-integrated end-of-turn 检测 ~260 ms，专为 voice agent，可比 Nova-3 + VAD 流水线减 200–600 ms 总延迟
3. **AssemblyAI Universal-3 Pro Streaming + ElevenLabs Scribe v2 Realtime（sub-150 ms）**：实时流式 ASR 同时支持 real-time diarization + 99+ 语种，业界最低延迟之一

### 6.2 本地 TTS / ASR 关键事实

4. **CosyVoice 2 进 `voice-tts` 一级候选**：Alibaba FunAudioLLM 开源（Apache 2.0），150 ms 首包 + 双向流式 + zero-shot 声音克隆 + 中文方言（粤语/川话/沪语/津话/武汉话等）+ code-switching——同时打中"中文 + 实时 + 克隆"三个目标
5. **Qwen3-ASR Cloud（DashScope BYOK）**：模型名 `qwen3-asr-flash`（短音频，10 MB 上限）/ `qwen3-asr-flash-filetrans`（长音频异步）；52 语种 + 方言；DashScope OpenAI 兼容路径 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`

### 6.3 法律 / 政策硬约束

6. **Kokoro 默认 G2P 后端 `espeak-ng` 是 GPLv3**——Kokoro 模型本身 Apache 2.0，但打包 `espeak-ng` 静态进容器可能引发 GPL 传染；推荐做法：(a) 动态 link（运行时安装，遵循系统库例外），或 (b) 换用 Kokoro 官方的 `misaki`（MIT）做 G2P
7. **iOS 自定义键盘麦克风权限**：iOS 8 起的限制至今有效，但 host-app 模式可绕过（键盘 → 主 App 录音 → App Group 共享 → `textDocumentProxy.insertText()` 注入），Wave / Spokenly / Wispr Flow / Willow 都已落地。iOS 端可选客户端外壳路径 = 系统 Dictation 兜底 + 自家 App + 键盘扩展 + host-app 模式
8. **AuralWise 实际形态 = 纯异步任务模式**（`POST /tasks` + `audio_url` / `audio_base64` + `callback_url` + `callback_secret` HMAC-SHA256）—— 本平台 API 设计采用"OpenAI 兼容（同步 / 流式短任务）+ AuralWise 风格（异步长任务 + Webhook）"双协议并存
9. **Parakeet TDT v3（NVIDIA）= CC-BY-4.0，但仅支持 25 European languages（不含中/日/韩）**—— 落地为 `voice-stt-parakeet-tdt-06b-v3-v2`，定位"英文 / 欧洲语种性价比首选"；中文路径必须靠 SenseVoice / Paraformer / Qwen3-ASR，两路并存
10. **Voxtral 系列 license 一分为二**：
    - Apache 2.0 / 可本地商用：Voxtral Mini / Small（音频理解）+ Voxtral Realtime（流式 ASR 480 ms 延迟，13 语种，端到端训练，落地为 `voice-stt-live-voxtral-realtime-3b-v2` / `voice-stt-live-voxtral-realtime-v2`）+ Voxtral Transcribe 2（batch + real-time）
    - CC-BY-NC 4.0 / 本地商用受限：Voxtral TTS（4B）——9 语种 + zero-shot 克隆 + 3 秒参考音；**不**新建 `voice-tts-voxtral-tts-*` 本地应用，如需走 Mistral API BYOK（$0.016/1k chars）
11. **SenseVoice 流式真相**：官方架构 non-autoregressive 端到端，**不支持原生流式**；如需中文流式必须走第三方 `streaming-sensevoice` fork（chunk + 截断 attention 的 pseudo-streaming，略损精度）或 Paraformer streaming；SenseVoice 同时支持 speaker diarization（vad + spk + punc 组合调用）
12. **NLLB-200 = CC-BY-NC 4.0**，仅用于 fallback；长期主翻译走 LLM 或商用 API
13. **OpenMOSS 多家族 license**（经 GitHub LICENSE 文件 + HF model card 核验）：
    - **已确认 Apache-2.0**：MOSS-Audio（4B/8B × Instruct/Thinking）/ MOSS-Audio-Tokenizer / MOSS-TTS 全家族（含 v1.5 / Realtime / Nano-100M / Base / Local-Transformer）/ MOSS-TTSD-v1.0 / MOSS-Speech（含 Codec 859M）
    - ⚠ **仍未明示**：MOSS-Music-8B（GitHub repo 存在但无 LICENSE 文件；HF model card 未写）/ MOSS-SoundEffect-v2.0（GitHub 无对应 repo；HF model card 未写）/ MOSS-Transcribe-Diarize（GitHub 无对应 repo；HF 仅 paper + Space）—— 这 3 项本平台暂标"License: 待确认"提示用户，可视为弱档候选。
14. **TEN-VAD（TEN-framework / Agora）= Apache-2 带 non-compete with Agora 非标准条款**——比 Silero VAD 更准更快（RTF 0.015，库 ~306 KB），但商用 SaaS 形态需重新评估；落地为 `voice-vad-ten-vad-v2` 入 P2，license 字段红字标注。

### 6.4 关键模型事实（与落地直接挂钩）

15. **MOSS-Audio（OpenMOSS 复旦 / MOSI.AI，Apache-2）** —— 4B/8B × Instruct/Thinking 共 4 个变体，Qwen3 backbone + 自训 12.5 Hz audio encoder + DeepStack 跨层注入 + Time-Aware Token；同时提供 ASR + 音频问答 + 时间戳 + 摘要 + 推理 + 音乐理解。  
    - MMAU/MMAU-Pro/MMAR/MMSU 平均 70.80（开源同尺度榜首），超越 Qwen3-Omni-30B / Step-Audio-R1-33B
    - ASR 总体 CER 11.30（12 维评测）优于 SenseVoice-Small 14.50 / Kimi-Audio-7B 14.12 / Qwen2.5-Omni-7B 15.05
    - Timestamp ASR AAS：AISHELL-1 = 35.77 / LibriSpeech = 131.61，**碾压 Qwen3-Omni-30B（833.66 / 646.95）和 Gemini-3.1-Pro（708.24 / 871.19）一个数量级**
    - 不流式、不 TTS、不 diarize
    - 落地：(a) STT 离线档 `voice-stt-moss-audio-{8b,4b}-instruct-v2`（P0/P1）；(b) Audio-LLM 能力域承载听感型 QA / 摘要 / 推理，`voice-audio-llm-moss-audio-8b-thinking-v2` P0 + 其余 P1/P2
    - 部署需 SGLang OpenMOSS fork + cu128 + FlashAttn-2，由 `beclab/voice-engine-mossaudio` 镜像封装

16. **Qwen3-ASR（QwenLM，Apache-2）** —— 含 Qwen3-ASR-1.7B / 0.6B + Qwen3-ForcedAligner-0.6B。52 语言 + 22 中文方言；流式 + 离线**同模型**；语音 / 音乐 / 唱歌识别；0.6B 在 batch=128 下 2000× 实时；强于 Whisper-large-v3 与 GPT-4o-Transcribe（中文 / 多语 / 唱歌维度）；context biasing 100k tokens 自定义术语；vLLM 批量推理。
    - 落地：`voice-stt-qwen3-asr-1-7b-v2` 入 P0（与 WhisperX 并列默认）；0.6B 入 P1；ForcedAligner 入 Align 域 P1
    - 引擎：`beclab/voice-engine-qwenasr`

17. **MOSS Transcribe Diarize（OpenMOSS，paper 2601.01554）** —— 统一多模态 LLM 做"end-to-end 说话人归属 + 时间戳转录"，一步出 (speaker, text, start, end) 三元组。
    - 直接对标 WhisperX + pyannote 双步走主路径，且合一；体感更连贯，长音频说话人 ID 漂移问题减轻
    - 落地：`voice-stt-moss-transcribe-diarize-v2` 入 P0（与 WhisperX + pyannote 并列）

18. **MOSS-TTS 全家族（OpenMOSS）** —— 5 个 TTS 模型：
    - MOSS-TTS 8.5B 主基础 / MOSS-TTS-v1.5 8.5B（含 voice cloning）/ MOSS-TTS-Realtime 2.3B 流式 / MOSS-TTS-Nano-100M（CPU 可用 + zero-shot 克隆）/ MOSS-TTS-Local-Transformer 3.06B
    - MOSS-TTSD-v1.0 8.36B —— TTS for Dialogue 一步直出多角色音频，对标 NotebookLM podcast
    - MOSS-Speech 9B + MOSS-Speech-Codec 859M —— 真正 S2S 无文本中介，与 OpenAI gpt-realtime-2 同档开源对手
    - MOSS-Music-8B（Instruct/Thinking）—— 音乐特化 audio-LLM
    - MOSS-SoundEffect-v2.0 —— 文生音效，弱档候选
    - 引擎：`voice-engine-mosstts` / `voice-engine-mossttsd` / `voice-engine-mossspeech` / `voice-engine-mossmusic` / `voice-engine-mosssoundfx`

19. **NVIDIA Streaming Sortformer** —— 生产级流式 diarization 模型；frame-level 实时；2–4 说话人（社区 fork Ultra-Sortformer 扩 N=8）；与 NeMo / Riva 集成；对标 pyannote 但 pyannote 不能流式。
    - 落地：`voice-diar-streaming-sortformer-v2` 入 P1；`MODEL_CAPABILITY=diar_stream`，走 WS 路径，承载 C-1 会议用例的实时说话人显示
    - 引擎：`beclab/voice-engine-sortformer`

# 概要设计

> 设计速览，只说架构 + 选型；无代码、无愿景、无工期。

## 一、设计目标（一句话）

把「输入法流式 dictation / 文件转录 / 会议记录 / 字幕 / 笔记本 / TTS-克隆 / 音频问答 / 真正 S2S 对话 / 多角色对话 TTS / 文生音效 / 流式 diarization / AuralWise 兼容任务」全部合到一个 `voice-ai-hub` 核心应用 + 一套统一模型层（自家 ~74 个 voice-* model app + 现有 3 个 Olares 借力 app + 远程 BYOK），用户视角与 `ollama*` 系列对齐。

## 四、自家模型应用统一范式

### 4.1 四条硬约束（与 `ollama*` 系列 1:1 对齐）

1. **1 app = 1 个具体模型变体**（含量化档位）。
2. **App Store 安装条覆盖"镜像 + 模型下载"**，pod readiness 阻塞到模型就绪；不允许"装完打开还要再等"。
3. **装完用户立刻能拿到 (BASE_URL, MODEL_NAME) 两个值** 粘到任何其它应用里用。
4. **v2 拆分**：`subCharts: [server (shared/clusterScoped), client]`——admin 装 server 一份，普通用户装 client 引用同一个 server。

唯一允许偏离：HuggingFace 门禁模型用 `OlaresManifest envs.HF_TOKEN`，其它一律相同。

### 4.2 实现方式：一个统一 API 容器服务全部 ~74 个 app

```
voice-* app pod
┌────────────────────────────────────────────────────┐
│  runtime container (按上游不同换 image)             │
│   beclab/voice-engine-{whisperx,faster-whisper,    │
│   whisperlive,voxtral,funasr,nemo,kokoro,          │
│   cosyvoice,pyannote,3dspeaker,tts-misc,vad,       │
│   translate,enhance,embed,align,mossaudio,         │
│   qwenasr,mosstts,mossttsd,mossspeech,             │
│   mossmusic,mosssoundfx,sortformer,tenvad}         │
│   只跑模型推理，暴露 :9000 native API               │
└────────────────────────┬───────────────────────────┘
                         │ localhost
┌────────────────────────▼───────────────────────────┐
│  api container = beclab/voice-model-puller        │
│   • 启动时按 ConfigMap 拉模型 (CDN/HF-public/      │
│     HF-gated)，readiness 阻塞到模型就绪             │
│   • 反代 :9000 上游引擎到 :8080 OpenAI 兼容路径    │
│   • 暴露 /v1/models /healthz /readyz /metrics      │
└────────────────────────────────────────────────────┘
        ↓ hostPath 挂载
   userData/Voice/<release-name>  (per-app 模型缓存)
```

新增一个 voice-* app 只需：
1. 抄 `voice-tts-kokoro-82m-v2`（非门禁范型）或 `voice-diar-pyannote-3-1-v2`（门禁范型）的 chart；
2. 改三个值（`MODEL_NAME` + runtime image + 资源量）；
3. 把 tarball 推到 `cdn.olares.com/models/voice/<engine>/<name>.tar.zst` 写 md5（仅 olares-cdn 路径）。

### 4.3 OlaresManifest envs（用户视角的两个值 + 一个能力 tag）

| envName | 类型 | 取值示例 | 说明 |
|---|---|---|---|
| `MODEL_NAME` | 只读 | `whisperx-large-v3` / `cosyvoice-2` / `pyannote-3.1` | 用户复制即用 |
| `MODEL_CAPABILITY` | 只读 | `stt` / `stt_stream` / `tts` / `tts_clone` / `tts_dialogue` / `vad` / `diar` / `diar_stream` / `translate` / `enhance` / `embed` / `align` / `audio_llm` / `audio_s2s` / `sound_fx` | hub 据此自动路由 |
| `BASE_URL` | 只读 | `http://api.<release>server-shared:8080` | 用户复制即用 |
| `HF_TOKEN` | **门禁 app 唯一加项** | 用户填 | 缺失时 readyz 返 503 + license_url |
| `KEEP_ALIVE` | 可选 | bool | 与 ollama* 一致 |

## 五、`voice-ai-hub` 核心应用

### 5.1 内部模块

| 模块 | 职责 | 关键技术 |
|---|---|---|
| **API 网关** | OpenAI 兼容 + 扩展 + AuralWise 兼容 task | FastAPI；OpenAPI 自动生成；流式走 SSE/WebSocket |
| **provider 抽象 + 自动发现** | 把所有自家 voice-* / 现有 3 app / 远程 BYOK 包装成统一 provider；启动 + 60 s 周期扫 sharedEntrance 上的 `MODEL_NAME / MODEL_CAPABILITY / BASE_URL` 三 env | provider interface + Service watcher（k8s API） |
| **配置中心** | 用户级 (provider 凭证 + 用例模型选择 + 偏好) | SQLite + REST API + 集群密钥字段加密 |
| **任务编排** | 同步/异步/流式/流式+持久化 四档 | RQ + Redis；WebSocket 直转发；长任务 polling/webhook |
| **多用户隔离** | 全部任务/历史/配置按 `bfl.username` 分区 | PostgreSQL + MinIO + Redis 命名空间 |
| **数据存储** | 用户配置 + 任务历史 + TTS/转录产物 + 声纹库 | PostgreSQL (含 pgvector) + MinIO + Redis |
| **Web UI** | 配置中心 + 26 用例演示 + 任务历史 | SvelteKit / Vue 3 |

### 5.2 数据存储分工

| 存储 | 内容 | 备注 |
|---|---|---|
| PostgreSQL | users / tasks / providers / configs / voices(声纹元) / notes(RAG)；含 pgvector | 与 `ollamav2` 等其它应用解耦 |
| MinIO | 原始音频 / TTS 输出 / 转录 SRT/VTT/JSON / 声纹样本 | bucket per-user |
| Redis | 任务队列 / WS session / 短期缓存 | RQ 自带 |
| SQLite | 单用户级偏好（轻量） | 可选 |

### 5.3 多用户与声纹

- 所有 `voice-*` model app 一律**无状态**：TTS app 不存声纹，diarize app 不存说话人库。
- 声纹（voice cloning）状态全部归 hub：PostgreSQL `voices` 表 + MinIO `voices/<user>/` 前缀；调用克隆 TTS 时由 hub 把 `reference_audio` 或 `speaker_embedding` 直接喂给 voice-tts-cosyvoice-2 等 app。
- AudioSeal 水印由 hub 在合成结果上打。

## 七、部署 & 集成（OlaresManifest）

### 7.1 voice-* model app（按 §四 范式）

```
voice-<cap>-<name>-v2/
├── OlaresManifest.yaml          # 顶层；envs 暴露 MODEL_NAME / MODEL_CAPABILITY / BASE_URL [+ HF_TOKEN]
├── voice-<cap>-<name>-v2server/ # subChart：shared / clusterScoped
│   └── templates/{configmap,deployment,service}.yaml  # 双容器 runtime + voice-model-puller
└── voice-<cap>-<name>-v2/       # subChart：per-user client，nginx 反代到 server
    └── templates/clientproxy.yaml
```

模型存储：hostPath `userData/Voice/<release-name>` per-app。

### 7.2 voice-ai-hub

```
voice-ai-hub/
├── OlaresManifest.yaml
│   ├── entrances: web (8080) + api (8080)
│   ├── sharedEntrance: enabled         (供第三方应用发现)
│   ├── middleware: postgres + redis + minio
│   ├── permission.userData: voice-recordings
│   └── options.appScope.appRef: speaches / whisperwebuiv2 / ollamav2 +
│                                voice-* P0 优先批 (其余按上架增补)
└── chart/templates/{deployment,service,ingress,…}.yaml
```

### 7.3 自动发现机制

`voice-ai-hub` 启动时 + 60 s 周期：
1. 列 namespace 下所有 sharedEntrance Service（标 `bytetrade.io/sharedentrance=true`）；
2. 对每个 Service 调 `/v1/models`，按 `MODEL_NAME` + `MODEL_CAPABILITY` 注册到 `provider_registry`；
3. 门禁 app 没填 `HF_TOKEN` 时 `/readyz` 返 503，自动从列表剔除；填好后下一轮扫到。

无需在 voice-ai-hub 的 OlaresManifest 里逐个写 voice-* app 的 URL（仅现有 3 个借力 app 显式写）。

## 八、关键流程（三张图）

### 8.1 长音频转录（异步任务）

```
client → POST /v1/audio/transcriptions (file=…)
         → 网关：拒绝 ≤25 MB 同步 → 创建 task → 入 Redis 队列 → 返 task_id
         → 异步 worker：拉任务
            → ffmpeg 16 kHz mono
            → 路由 (provider 配置 + capability=stt)
            → voice-stt-whisperx-large-v3-v2 / 远程 Qwen3-ASR-Filetrans
            → [可选] voice-diar-* / voice-translate-* / ollamav2 摘要
            → 写 PostgreSQL (tasks/segments) + MinIO (产物)
            → 进度 SSE 推 / Webhook
client ← GET /v1/tasks/:id (polling)  或  Webhook 回调
```

### 8.2 流式听写（输入法 / 实时翻译）

```
client (桌面热键 / Android) ──WS──> /v1/audio/realtime
                                  │
                          ┌───────┴────────┐
                          │ 网关：协议转译 │
                          └───────┬────────┘
                                  │
   ┌────────────────────┬─────────┴──────────────┐
   ▼                    ▼                          ▼
voice-stt-live-*    远程 OpenAI gpt-       远程 Deepgram Flux
(自家本地兜底)      realtime-whisper          (低延迟首选)
   │                    │                          │
   └─── partials + finals ──→ 网关合流 ──→ client (注入文本)
```

### 8.3 声音克隆 TTS

```
client → POST /v1/voices  (上传参考音频 + 用户协议)
         → hub：保存到 MinIO + 写 voices 表 (voice_id, sample_url, embedding)

client → POST /v1/audio/clone {voice_id, text}
         → hub：读 voices 表 → 取 sample_url 或 embedding
         → 调 voice-tts-cosyvoice-2-v2 /v1/audio/clone (reference_audio 直接传入)
         → 拿到合成 wav → 打 AudioSeal 水印 → 返 client (X-Audio-Watermark-Id)
```

## 九、本地化、合规与运维要点

| 项 | 设计 |
|---|---|
| **本地优先** | 默认走集群内 sharedEntrance；远程 BYOK 仅在用户启用 + 配 key 时调用 |
| **门禁模型** | OlaresManifest `envs.HF_TOKEN`；puller readyz 状态机；hub 自动剔除/恢复 |
| **CC-BY-NC / 非商用模型** | `fullDescription` 红字 License Notice + `metadata.categories` 加 `Non-commercial` 标签；技术安装路径与免费模型完全一致 |
| **远程 key 安全** | Olares 集群密钥 + 字段级加密；log 脱敏；UI 仅显示后 4 位 |
| **多用户 GPU 并发** | 任务队列限流 + 用户级配额 + 自动 fallback 远程 |
| **流式协议碎片** | 对外只暴露 OpenAI Realtime 兼容 WS；对内转译到各 provider 私有协议 |
| **配置选择困难症** | 档位预设（极速/平衡/高质量） + 按用例配置 + 高级模式 三层入口 |
| **AudioSeal 水印** | 默认开启（克隆 + 非克隆都打）；用户可关闭；token 写在响应 header `X-Audio-Watermark-Id` |

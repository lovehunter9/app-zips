## 四、收尾 6 个 API 真 bug 修复（05-18 下半）

> 严格遵循 "API 层 only、WebUI 路径零侵入"——`_patched_transcribe`（API/WebUI 共享引擎层）**完全不动**，所有变更分布在 `_do_transcribe`（API 入口）、`_normalise_*` / `_normalize_*`（API 工具函数）、`_transcribe_form_params`（FastAPI Form 字段定义）这些 API 专属层。

### 4.1 `VadOptions` 多余 kwarg 引发 500

**症状**：API 调用带较新 VAD 参数 → `VadOptions.__init__() got an unexpected keyword argument 'min_silence_at_max_speech'`。

**根因**：老版 `faster-whisper` 的 `VadOptions` 不认 `min_silence_at_max_speech` / `use_max_poss_sil_at_max_speech` 两个 1.1.x 字段，但本服务 Form 默认值带它们。

**修复**：导入期 introspect `VadOptions` 的 `_VAD_OPTIONS_FIELDS` 字段集合，调用前过滤白名单外字段，记录到 `_meta.vad_dropped_fields`。Script 1b / 4 中所有 Batched/Buffered 调用 `_meta.vad_dropped_fields` ≤ 2 项，无 500。

### 4.2 `language=English` 引发 500

**症状**：`'English' is not a valid language code`。

**根因**：faster-whisper 只接受 ISO 639-1 code（`en` / `zh`），但 OpenAI Whisper 文档约定接受英文全名。

**修复**：API 层 `_normalize_language` 接受 ISO code、英文全名（来自 `_ISO_TO_LANGUAGE_NAME` 反查表）以及若干别名（`Mandarin → zh` / `Castilian → es` / `Burmese → my` 等），未知值 raise 400 并列出可接受形式。Script 2 P1/P2 正向、Script 3 N10 `Klingon` 反向均验证。

### 4.3 API 路径下 Batched 永远 fallback 到 Buffered

**症状**：`_meta.path == "batched_fallback_to_buffered"`，`TypeError: string indices must be integers, not 'str'`。

**根因**：Form 字段 `clip_timestamps` 默认值是字符串 `"0"`；老版 `WhisperModel.transcribe` 自己 parse 字符串，新版 `BatchedInferencePipeline` 直接 iterate 整数下标 → 炸。**这意味着自 Batched 集成以来 API 路径的 Batched 一直是假的，只在 WebUI 走通过。**

**修复**：`_do_transcribe` 把 `"0"` / `"5,12.5,20"` 这种字符串 normalize 到 `list[float]` 再传给 faster-whisper（空 / `"0"` 时干脆不传）。WebUI 路径完全不动。Script 1b C2/C6/C7 + Script 4 中 Batched 调用 `_meta.path == "batched"`。

### 4.4 DeepL `src_lang=EN`（code 形式）触发 502

**症状**：HTTP 502 `DeepL request failed: Source language EN is not supported`。

**根因**：上游 `request_deepl_translate` 严格按 friendly name（如 `English`）查表，但本服务 `/v1/translations/deepl/languages` 同时 advertise `code` 字段，导致用户复制 `code` 调用会失败。

**修复**：API 层 `_normalise_deepl_lang` 双向接受 name/code（不分大小写、含 `EN-US` / `PT-BR` 等带连字符 target code），未知值 raise 400；空字符串 / whitespace 同样 raise 400。Script 3 N6（`src_lang=EN` + 假 key）→ 502 上游拒假 key，反向证明 normalize 层映射成功；N11（`src_lang=Klingon`）→ 400 拒未知值。

### 4.5 `timestamp_granularities[]=word` 不被识别

**症状**：OpenAI SDK 调 `client.audio.transcriptions.create(timestamp_granularities=["word"], ...)` 响应里没 `words`。

**根因**：服务端只识别历史字段 `word_timestamps=true`，没识别 OpenAI 官方字段 `timestamp_granularities[]`。

**修复**：API 层 Form 字段加 `alias="timestamp_granularities[]"`，`_do_transcribe` 收到 `"word"` 时 flip `word_timestamps=True`。Script 2 P1b 的 verbose_json 响应里 `segments[*].words` 存在。

### 4.6 NLLB `src_lang=eng_Latn`（code 形式）引发 500

**症状**：HTTP 500 `Failed to load NLLB model: 'eng_Latn'`。

**根因**：上游 `NLLBInference.update_model` 直接做 `NLLB_AVAILABLE_LANGS[src_lang]` dict 索引，**只接受 friendly name**（如 `English` / `Chinese (Simplified)`）。但 `/v1/translations/nllb/languages` 同时 advertise `name` 与 `code`，用户从 `code` 字段复制 `eng_Latn` 调用直接 `KeyError` → 500。

**特别注意**：NLLB 与 DeepL **不对称**——**NLLB 不接受 ISO 639-1 两字母代码（`EN`/`ZH`）**，DeepL 接受。

**修复**：API 层 `_normalise_nllb_lang` 双向接受 name/code（不分大小写），未知值 raise 400（与 `_normalise_deepl_lang` 对齐）。Script 2 P4c/d/e 用 `eng_Latn` + `zho_Hans` 全部 PASS（修复前同一调用 → 500）；Script 3 N12 `Klingon` → 400。

## 十、教训

1. **扫描-修改循环要有退出条件**：不是"扫到没问题为止"——而是"扫到边际收益归零时停"。本期 U 轮已经踩到这个边界还在继续，应在用户指出之前自己识别。
2. **校对过的内容要标记**：被前几轮明确确认过的写法（如 `Mandarin/Chinese` 别名示例），不应在后续轮次被当作新问题改掉。这是状态遗失。
3. **API 与 WebUI 必须严格分层**：本期 6 个 bug 全部能在 API 专属层修复，是因为前期 `_patched_transcribe` 的位置选得正确。后续任何引擎层改动都应优先考虑能否下沉到 API 层。
4. **`_diag` 是收敛器**：把"调试需要可观测性"与"对外承诺零侵入"这两个本来矛盾的需求用一个 opt-in 开关分开——既能拿到铁证调试，又不污染默认响应。

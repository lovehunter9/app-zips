这座发动机的高度是一万一千米比珠峰还要高两千多米人们管这些发动机叫上帝的喷灯我们站在它巨大的阴影中感受着它通过大地传来的震动地球发动机分为两大类大一些的叫山小一些的叫风我们登上了

**典型 Whisper buffered 崩坏特征**：
- 大段大段无任何标点，多个句子粘连为单段
- 模型"丢失" punctuation token 的输出概率
- buffered windower 无法从中恢复

### 3.2 同段 Test 3（Batched + 后处理）的输出

```
这时地球已经完全停转，地球发动机除了维持这个行星的这种静止状态外，只进行一些姿态调整。所以，在从我三岁到六岁这三年中，光柱的光度大为减弱，这使得我们可以在这次旅行中更好地认识我们的世界。
我们首先在近距离见到了地球发动机，是在石家庄附近的太行山出口处看到它的，那是一座金属的高山，在我们面前赫然耸立，占据了半个天空。
```

**标点完整、段落清晰**。

### 3.3 Test 1 中其他后处理也救不回的 bug

后处理开了双开（Cleaning + Merging）但依然漏过的错误：

| 类型 | Test 1 输出 | 正确（Test 3 参照） |
|---|---|---|
| 内部短语重复 | `发动机加速造成的潮汐吞没了北半球三分之二的大城市发动机加速造成的潮汐` | 单次出现 |
| 凭空插入 | `整个天空仿佛被暴露了。\n。在这一天，我们的世界被白热的火山岩浆所覆盖。` | `整个天空仿佛被白热的火山岩浆所覆盖。` |
| 听写错误 | `光度和温度都在聚在一起` | `光度和温度都在剧增` |
| 字符替代 | `V型压缩机` | `微型压缩机` |

→ **关键结论**：这些都是 Whisper 引擎层面的崩坏，**后处理只能"擦拭表面"，无法修复根因**。Cleaning + Merging 全开也救不回 Buffered 的崩坏。

## 四、Test 2 vs Test 3 的差异

### 4.1 内容质量几乎一致

- 同一段音频，两次的字面输出极度接近
- 残留错误几乎相同（见 §5）
- 不存在"Batched 加后处理后内容字面变化"的情况

### 4.2 主要差异在视觉排版

| 维度 | Test 2（纯 Batched） | Test 3（+ 后处理） |
|---|---|---|
| 段落长度 | 偶有 1-2 句一段，碎片化 | 普遍 3-5 句一段 |
| 句末标点 | faster-whisper 默认（已经不错）| + CJK 标点归一化 |
| 段间换行 | 多 | 少（聚合更密）|

### 4.3 Cleaning + Merging 在 Batched 之上的边际价值

主要是**视觉排版**而非字面准确性。但视觉排版也是用户体验的一部分，所以"全开"是合理默认。

## 六、阶段性结论

### 6.1 已验证的命题

1. ✓ **Batched 模式确实根治了长音频后半崩坏问题**（Test 1 复现 → Test 2/3 消失）
2. ✓ **旧的后处理（Cleaning + Merging）无法替代 Batched**——两者工作在不同层级，后处理无法救回 Buffered 引擎层面的崩坏
3. ✓ **`_batched_cache` 缓存逻辑生效**（22s → 16s）
4. ✓ **Cleaning + Merging 在 Batched 之上仍有视觉排版的边际价值**
5. ✓ **`Batched=True / Cleaning=True / Merging=True` 是中文场景的最优默认**

### 6.2 待英文测试确认/反驳的命题

1. ? 英文长音频是否同样表现出"Buffered 后半崩坏 → Batched 修复"模式？
2. ? Cleaning + Merging 在英文的边际价值是否仍主要是排版？（中文标点归一化对英文意义有限）
3. ? Batched 模式下 condition_on_previous_text 被强制 False，英文是否会损失某些跨句一致性？（之前测试显示英文 `condition_on_previous_text=True` 会导致全大写，`False` 会导致循环——Batched 给的是 `False` + chunk independence，效果待验）

### 6.3 待补的优化

- **`initial_prompt` 全局化**：把领域词汇/人名作为 WebUI 全局配置写入 yaml，每次转录自动注入
- **`hotwords` 暴露**：作为 UI 输入框或全局配置项

## 七、英文测试

样本：福尔摩斯：波希米亚丑闻 ~64 分钟 LibriVox 有声书（与 05-13/05-14 LLM 评估时同一文件，可直接横向对比）。

测试矩阵（同样三组）：
- Test 4: Batched=False, Cleaning=True, Merging=True（✅ 完成）
- Test 5: Batched=True, Cleaning=False, Merging=False（✅ 完成）
- Test 6: Batched=True, Cleaning=True, Merging=True（✅ 完成）

### 7.1 Test 5 结果（Batched 裸跑）

| 项 | 值 |
|---|---|
| 耗时 | **1 分钟 5 秒** |
| 音频时长 | 64 分钟 31 秒 |
| RTFx | **~59×** |
| 后程崩坏 | ❌ 未出现 |
| 招牌 YouTube 幻觉 | ⚠️ 1 处（"Thank you for watching."）|
| 整体结构 | ✅ 完整，正确收尾于 "End of the Scandal in Bohemia." |

**关键证据**：收尾干净——

> "...always under the honorable title of **the woman.** End of the Scandal in Bohemia."

vs 此前预期的 Buffered 长英文表现（参考 05-12 TEST_LOG 中各种英文中后段崩坏样本）：
- 后半段大段重复
- 整段全大写
- "Thank you for watching" / "Please subscribe" 反复刷屏
- 多次完全循环导致丢失剧情

→ **Batched 路径对英文长音频同样根治后半崩坏**。

### 7.2 唯一幻觉点

Section 2 中段在演播员长气声/段落转换处插入 1 句："Thank you for watching."

机理：
1. 该处原文是 Watson 内心独白接外部描写，中间约数秒呼吸/停顿
2. VAD 把这段切到一个内容近静音的 chunk
3. Whisper 在该 chunk 上无法听到有效语音，**回退到训练集偏置输出**
4. LibriVox/YouTube 训练语料里 "Thank you for watching" / "Please subscribe" 极其高频
5. Batched 路径下 `condition_on_previous_text=False`，无法被上文压制

**修复路径（轻量）**：在 `_post_clean_segments` 里加 YouTube boilerplate 黑名单——`Thank you for watching|Please subscribe|Don't forget to like|Like and subscribe` 等高频幻觉短语，整段丢弃。零成本即可干掉这一整类已知幻觉。

### 7.3 残留错误（与 Batched/Buffered 路径无关，属 Whisper 本身盲点）

| 类型 | Test 5 输出 | 应是 |
|---|---|---|
| 专有名词漂移 | `Armstein` / `Armstrong`（同一角色前后写法不一）| von Ormstein |
| 角色全名 | `William Gottfried Sigmund` | Wilhelm Gottsreich Sigismond |
| 罕见历史名 | `Wallstein` | Wallenstein |
| 法语借词 | `Cote Blanche` | Carte Blanche |
| 古旧词 | `Wetlock` / `a guess-a-jean` / `chamos leather` | Wedlock / a gasogene / chamois leather |
| 误听 | `going into Hannes` | going into harness |
| 书名 | `the Stoughton scarlet` | "A Study in Scarlet" |
| 旅店名 | `at the Logram` | at the Langham |
| 平凡词错 | `Pregoo` / `Cochlea` | Prague / coach-house |

观察：跨 chunk 专有名词不一致（`Armstein` vs `Armstrong`）正是 `condition_on_previous_text=False` 造成的副作用——同一专有名词在两个独立 chunk 各自被模型猜了一遍。但相比 Buffered 模式下的全大写/重复循环，这种代价**小得多**。

→ **下一根有效杠杆**：`initial_prompt` 注入专有名词列表（"Sherlock Holmes, Watson, Irene Adler, Ormstein, Bohemia, Langham, ..."）。当前 API 已支持，UI 尚未暴露全局配置。

### 7.4 Test 4 结果（Buffered + 全后处理）

| 项 | 值 |
|---|---|
| 耗时 | **4 分钟 11 秒** |
| RTFx | ~15.3× |
| 速度对比 Test 5 | Test 5 快 **3.86×** |
| 跨语言污染 | ⚠️ 多处（韩/中/日/西/脏话/俚语字符混入） |

**速度比 3.86× 与 WhisperX 论文宣称 3-5× 完全吻合**。中文同测试（12 min 音频）只有 2.9×，因为短音频中 Silero VAD 启动开销占比偏高；64 min 才是 Batched 加速效应的真实剂量。

### 7.5 Test 4 崩坏样本——逐条点名

#### 7.5.1 跨语言污染（最经典 Whisper 长音频副作用）

**样本 A**（Section 1，国王诉案前）：

> if your majesty would condescend to stay away from the man we have **오** but he was **勤才** of the city of bali that the mosher would not come from this manor i would rather have been a man of the land of the elsaa that dropt out of the al alegree of elsa a gi'ew

- 韩文字符 `오`、中文字符 `勤才` 直接混入英文输出
- 整段是"幻觉空间"随机游走

**样本 B**（Section 2 中段 silence 区域）：

> but the coachman had counseled our lady and i continued on and **hijo** vit routinely to cajol my mother and being sniffed dearly for every**ったly** i looked up from the window of her flat... when in fact she swore it was just as **fucking** podeous to keep the clip wicked... and she was undtailed **lol** ... but the coachman had **conseguir**

- 西班牙语 `hijo`、`conseguir`
- 日文字符 `ったly`
- 现代俚语 `lol`
- 现代脏话 `fucking` 出现在 1891 年维多利亚小说里
- → **后处理（Cleaning+Merging 都开了）救不回，因为崩坏在引擎层、后处理在文本层**

#### 7.5.2 整段编造对话

**样本 D**（"But it has twice been burgled" 之后 8 行）：

> But it has twice been **burned**.（误听）
> Oh, she is old and fragile. She can not look.（编造）
> Oh, dear. Oh, dear. You know, I know.（编造）
> I have been invited to the commonwealth, and theazer on my way there will be a very good guest.（编造）
> She can be a great beauty, and I find her to be striking.（编造）
> I dare you not to fuss over a woman's duty, with such an **30%** of men.（编造，含数字"30%"）
> No, sir, do not worry. I will not.（编造）
> No, sir. I am aware of the facts, and whet your self-esteem.（编造）
> carriage came round the curve of the avenue（才接回原文）

整 8 行完全是 Whisper 自己生造，跟原文完全无关。

#### 7.5.3 段内重复

> In this case I found her **in the middle of the street, and I found her in the middle of the street.** I found sandwiched in between that of Hebrew rabbi

原文应是 "I found her biography sandwiched in between..."。

#### 7.5.4 单词丢失

> His dress was rich with a richness which would, in England, be looked upon as akin to **a man**.

原文 "akin to **bad taste**" → `bad taste` 被吞了。

#### 7.9.1 Test 6 vs Test 5 几乎逐字相同

所有 Test 5 的错误，Test 6 全部保留：

| 位置 | Test 5 = Test 6 |
|---|---|
| Whisper 标志性幻觉 | "Thank you for watching."（Sec2 中段，完全同位置同字面）|
| Wedlock | `Wetlock` |
| harness | `going into Hannes` |
| A Study in Scarlet | `stoughton scarlet` |

3. 排版上看不到中文 Test 3 那种"碎段聚成 3-5 句"的明显改进

#### 7.9.2 关键发现：英文与中文 Cleaning+Merging 边际价值差异

| 维度 | 中文（Test 2 vs Test 3）| 英文（Test 5 vs Test 6）|
|---|---|---|
| 标点 | CJK 标点归一化收益大 | faster-whisper 英文标点本来就完整 |
| 段落 | Batched 输出 1-2 句一段，碎片化 | Batched 输出已 3-5 句一段 |
| 字面错误纠正 | `26 segments punct-fix` | 0 字面变化（未触发清洗规则）|
| 视觉收益 | **可见** | **几乎不可见** |

**结论修订**：英文场景下 Cleaning + Merging 几乎是 no-op，但仍建议保持双开默认：
1. 跨语言统一默认值比"按语言切换默认"简洁
2. 英文里"无害"，中文里"明显有益"——单向风险
3. 用户可随时手动关闭

## 九、英文测试 OOM 故障与修复（1.0.16 内部 hotfix，版本号不递增）

### 9.1 故障现象

切到英文 64 分钟样本（福尔摩斯：波希米亚丑闻）跑 Test 5（Batched=True / Cleaning=False / Merging=False）时，CTranslate2 在 `generate_segment_batched` 报：

```
[HAMI-core ERROR (pid:18 ... allocator.c:274)]: cuMemoryAllocate failed res=2
RuntimeError: CUDA failed with error out of memory
```

### 9.2 根因——`_batched_cache` 累积式泄漏

观察日志中的 `cache size` 计数：

```
BatchedInferencePipeline created (model id=138058316332304, cache size=1)
BatchedInferencePipeline created (model id=138058302421392, cache size=2)
BatchedInferencePipeline created (model id=138058302915088, cache size=3)
BatchedInferencePipeline created (model id=138058314797904, cache size=4)
BatchedInferencePipeline created (model id=138058313692560, cache size=5)
↑ OOM 触发
```

**关键观察**：每次转录的 `id(model)` 都不同——意味着缓存从未命中过，每次只是新增条目。

**根本原因链**（与 1.0.16 设计假设的偏差）：

1. Whisper-WebUI 的 `WhisperParams.enable_offload` 默认 `True`，每次转录结束后会执行 `self.offload()`：
   ```python
   def offload(self):
       if self.model is not None:
           del self.model
           self.model = None
       if self.device == "cuda":
           torch.cuda.empty_cache()
   ```
2. 下次转录走 `update_model`，由于 `self.model is None`，**重建全新 `WhisperModel`**——新对象、新 `id()`。
3. 我们 1.0.16 的 `_batched_cache = {}` 是个普通 dict，按 `id(model)` 做 key，**永久强引用**所有历史 `BatchedInferencePipeline`。
4. 每个 pipeline 内部 `self.model = <WhisperModel>` 又强引用它包裹的那份 ~3GB large-v2。
5. 链条：`_batched_cache → pipeline_old → model_old`，导致 `del self.model` 只释放一份引用，模型**实际仍存活在 GPU**。
6. `torch.cuda.empty_cache()` 因为模型还活着等于 no-op。
7. 第 N 次转录时 GPU 里同时有 N 份 large-v2。本配置 GPU 16GiB / 3GB ≈ 5 → **第 5 次必 OOM**，与日志完全吻合。

> 这个 bug 1.0.16 中文测试时没暴露，是因为中文样本只有 12 分钟，三组测试期间累计 ~3-4 个模型刚好没爆。一旦换到 64 分钟英文 + 多次重试，立刻击穿。

### 9.3 修复策略（单槽缓存 + 显式 GC）

把"无界累积 dict"改成"单槽缓存 + 失配时立即 evict + 强制 GC"：

```python
def _get_or_create_batched(model):
    key = id(model)
    if key in _batched_cache:
        return _batched_cache[key]               # 缓存命中走快路径
    if _batched_cache:                            # id 不同 → 旧条目 evict
        _batched_cache.clear()                    # 断开 pipeline → model 的强引用
        gc.collect()                              # 主动回收
        torch.cuda.empty_cache()                  # 同步归还 GPU 显存
        logger.info(...)
    pipeline = BatchedInferencePipeline(model=model)
    _batched_cache[key] = pipeline
    return pipeline
```

### 9.4 修复后的两种工作场景

| 场景 | 行为 | 显存峰值 |
|---|---|---|
| **API 流**（连续调用，无 offload）| 同 `id(model)` → 缓存命中，每次省 ~6s Silero VAD 启动 | 1 个 model + 1 个 pipeline |
| **WebUI 流**（每次 offload + update_model）| `id(model)` 不同 → evict + gc + empty_cache → 同步释放旧 GPU 显存 → 再建新 pipeline | 短暂 2 份（新建瞬间），稳态 1 份 |
